# 50 + 50 配对受控场景 (lanefix 网, 18 个 RL 路口)

实现计划: `experiments/analysis/PLAN_PAIRS50_LANEFIX_2026-10-28.md` (第三版)。工具: `experiments/tools/dublin/scenario/pairs50lf/`; 测试: `experiments/tests/test_pairs50_lanefix.py`。
路网 `dublin_8std_splitslot18_southclosed_corridor_nocg_lanefix.net.xml` 与动作表 `dublin_8std_splitslot18_southclosed_corridor_nocg_lanefix_meta.json` (与 18h 定稿相同, sha256 核验)。

## 用途与核心设计

受控测试: 比较不同优先级规格 (如 111 / 531 / 351) 下公交与救护车的待遇, 尽可能隔离路线、出发时机、沿途竞争等外部因素。**公交与救护车可互换**: 共用同一套路线 (逐段同车道), 数量相同 (各 50), 每条路线对数为偶数且路线内交替先后, 出发时刻分布相同; 两类唯一的区别是车型标签。观测按优先级档位分桶、奖励用同一张表加权, 控制器看不到车型, 所以 531 与 351 在本场景里是同一个问题, 只是哪些车是 5 档换了。

## 评估建议 (计划 §8)

- 主证据: 同一份时刻表、车型不变, 只换 531 / 351 —— 同一批救护车在 531 下是否比 351 下少等, 同一批公交反过来; 原份与镜像都做再合并; 111 作空白对照。
- 所有规格用同一批评估时刻表 (第 8–13 份及镜像) 与同一批评估种子; 排空到 4500 s, 截尾不补零、不只比完成的车。
- 用同一检查点切换规格时, 每次都新建环境、观测与奖励函数; 分别训练时要多次独立训练才能把规格效果与训练差异分开。
- 固定配时等确定性周期的基准, 单份时刻表上两类会有 ±1–2 s 的偶然差 (相位对齐由时刻表决定), 必须按原份 + 镜像合并报告。

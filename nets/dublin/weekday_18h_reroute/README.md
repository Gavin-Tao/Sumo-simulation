建立 2026-09-30 (用户令: 可以接受更改分布, 让那个转向不要死锁; 重建一个新的 sumo 文件夹, 原始的和更正后的都保留; 只改 18h)。
原始场景 `../weekday_18h/` 逐字节保留, 未改动。取证与方案比较见 `experiments/analysis/DUBLIN_18H_REROUTE_2026-09-30.txt`。

## 改了什么 (只改小汽车路由文件; 路网、公交、救护车、探针公交、四个 sumocfg 与原文件夹逐字节相同)

- 177 辆小汽车 (18h 全部 5829 辆小汽车的 3.0%) 原路线以 `-532427444#2 369977731` 结尾:
  Aungier Street 南行, 在非信号让行口 cluster_2384200130_2384200132_389663 右转进入 Peter's Row 出口边, 从边界出口 247416072 离网。
- 改为 `-532427444#2 -341583777#1 -5976022 gneE52 -43321722 -43321718#3`:
  直行沿 Redmonds Hill 南行, 经 gneJ47 / gneJ48 进入 Kevin Street Lower 西行, 从边界出口 508057825 离网。
  只有出口改变 (仍向西离网), 行程 207 m → 224 m (+17 m); 出发时刻、车辆 id、车型、起点边和其余 5652 辆小汽车全部不变。
- 核对规则: `grep -c '-532427444#2 369977731"'` 原文件 = 177, 新文件 = 0; 其余四个路由文件与四个 sumocfg 用 cmp 逐字节相同。

## 为什么 (死锁机制)

- 该路口 (Aungier St / Redmonds Hill / Peter's Row / Digges St Upper) 在路网里是 priority 型, 不在 27 个信号、也不在 18 个 RL 信号之内。
- 18h 流量: Redmonds Hill 北行左转进 Peter's Row 796 辆/h (主路, 不让行); Aungier 南行右转进 Peter's Row 177 辆/h
  (左行交通里右转要跨越对向车流, 是让行方向); Aungier 南行直行 57 辆/h (20 小汽车 + 37 公交, 主路), 与右转车共用一条 106 m 单车道。
- 让行右转在连续 796 辆/h 主流下几乎等不到可穿越的间隙: 固定配时 seed 123 下, Aungier 进口道全小时每 5 min 等待 1000-3300 s,
  占有率 50%, 一小时只通过 138 辆 (需求 234), 177 辆目标车平均时间损失 610 s (中位 470 s);
  队列回溢到上游 RL 路口 389281 的东进口 22962979 (每 5 min 等待 2000-3000 s)。RL 路口 389281 及其下游因此"锁死", 但锁点在 RL 动作空间之外, 任何控制器都解不开。
- 改道后该路口所有让行连接 (state m) 的流量都是 0, 只剩两条互不冲突的主路运动 (Redmonds Hill 左转 796; Aungier 直行 57+177+37), 结构上不再可能在这里因让行而等待。

## 被否决的替代方案 (细节见分析文档)

- 改走 Wexford Street 出口: 把 177 辆/h 推到 RL 路口进口道 532427445#0, 该边每 5 min 等待 400-800 → 2000+ s, 更差。
- 改路口规则 (让行方向互换 / 拉链): 需要用 netconvert 从 plain 文件重建路网, 重建后全网另有约 80 条连接的让行状态与原网不同 (plain 导出不能逐位还原), 做不到"只改一处"; 拉链变体插入只有 4292 辆, 大幅更差。

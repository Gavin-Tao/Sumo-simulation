建立 2026-10-27/28 (用户令 "开始做 sumo 文件")。设计: `experiments/analysis/SCENARIO_PRIORITY_PAIRS50_DESIGN_2026-10-27.md` (只含 SUMO 场景文件; 训练/评估安排另定)。

## 2. 背景车流

### 2.1 生成规则 (gen_background_demand.py)

- 需求按 (路口, 转向) 直接设定 (demand_targets.json); 路线按路网连接生成, **车道一致** (从 departLane 起不换道可走完, 生成时核对), 起点边 ≥ 40 m (13 个运动的进口边只有 10–27 m, 从上游一条边起步); 经过的非 RL 节点只走本路线有路权的连接 (net 里 state 'M'), 不经过让行连接 ('m'); 向上游最多再经过 1 个 RL 路口 (无候选时放宽到 2)。
- **路线结尾穿过下游 RL 路口直到边的下游节点不是 RL 路口** (v3 起; 之前路线结束在相邻路口的进口边上, 车辆在边末消失前排在下游队尾, 造成人为回溢, 是 v1/v2 积压的主因)。
- 一条路线经过几个 RL 路口就贡献几个 (路口, 转向); 用非负最小二乘 (NNLS) 在候选路线上分配车数使实现需求最接近目标 (v5 起; 表外转向以 0 为目标、权重 0.3)。
- 候选路线按经过的 RL 路口数: 1 个 76 条, 2 个 35, 3 个 25, 4 个 35。

## 4. 标定 (scenario_check.py; exp461 的环境参数, 8STD 分槽相位, 不传送, 含 50 对实验车)

## 6. 已知局限与待补

- 相邻路口间的短边 (25–58 m) 使回溢事件比 18h 多, 属路网几何, 已把该群需求压低。
- 两条合成路线不来自真实路由; 5 条路线经过非 RL 让行连接 (主判据只在 RL 路口上算)。
- 需求实现与目标在 16 个转向上偏差超过 15 个百分点 (见 §2.2), 是多路口路线折中的结果。
- 同对两车同时出现在同一进口道的占比未统计; 训练后在学习策略下的机会数未量 (需要检查点)。
- 参考控制器 (469 best) 的核对等它训完后补做。

─────────────────────────────────────────────────────────────────────────────────────
§1 枚举器是怎么工作的 (代码事实)
─────────────────────────────────────────────────────────────────────────────────────
  枚举单位是 12 个运动槽 = 进口 (N/E/S/W) × 转向类 (L/T/R); 转向类按几何 (出口车道末段方位 − 进口车道末段方位) 判定, 与观测共用同一张表。
  槽间关系: 同进口 0 / 相容 1 / 合流冲突 2 / 交叉冲突 3; 只要两槽间任一对 link 交叉或汇入同一车道, 整槽即冲突。
  菜单 = 全部 "极大无冲突槽集" (回溯穷举); 相位串把入选槽的全部 link 置 'G', 只保护相位, 无 'g'。
  GS 臂训练时观测的槽位映射取自 enum meta 的 links[*].approach/turn (frap_glue.load_enum_tables); 8STD 臂取自 dublin_8std_meta.json (train.py ts_turnmap), 两者互不牵连。

─────────────────────────────────────────────────────────────────────────────────────

  A1 安全: 相位内任意两条绿灯 link 不交叉、不汇入同一车道, 无 'g', 不给不存在的 link 绿灯      0 违反
  A2 槽级完备: 对存在的槽穷举全部子集, 极大无冲突集 == 菜单                          18/18 相同 (不缺不多)
  A8 槽间关系表重算 == 元数据, 且对称                    18/18
  A4 覆盖: 每条 link 至少在一个相位为绿                   0 条永不绿
  A5 一个信号位含多条连接且归类不同                       0
  A3 link 级最大性: 某相位还能无冲突地再加一条红灯 link      仅 cluster_21620852_… 4 处 (见 §3)
  A7 8std 的相位不被任何 enum 相位包含 (8STD 能放而 GS 放不了的组合)   仅 cluster_21620852_… 2 个
  两臂相位集完全相同的路口 13 个; 另 4 个路口 (135109534, 659802, cluster_135109528_9101656, cluster_5166592137_…) enum 含 8std 全部相位并多出 1/1/3/1 个;

  A6 共用车道部分放行 ("同一车道一部分连接绿、另一部分有流量的连接红", 队首车可能挡住后车): enum 39 个 (相位, 车道) 组合, 8std 32 个。
     这是 "只保护相位 + 多转向共用车道" 的固有现象, 两臂都有 (如 1448442 的 -554991019 单车道 144/78 辆/h, 即此前取证的右转饿死点;
     389281 的 22962979 182/111; 26165126 的 -5826896#0 79/159), 不是枚举错误; enum 多出的 7 个来自它多出的相位。
  A9 几何转向 ≠ netconvert 标注的 link: 135109534 1 条, 1430847303 3 条, cluster_21620852_… 2 条。
     槽内含多个去向的情况全网 3 处: 1430847303 (W,T) [未藏住任何相容组合, 不处理], cluster_21620852_… (E,T) 与 (S,L)。

§3 唯一的问题: cluster_21620852_2383668110_2383668118_4009885977 (Harcourt St / St Stephen's Green / Cuffe St)
─────────────────────────────────────────────────────────────────────────────────────
  link 0,1  St Stephen's Green → 4078079#1  (dir s)  槽 (E,T)   171+171 辆/h
  link 2    St Stephen's Green → 2110697#0  (dir r)  槽 (E,T)   24        ← 几何判为直行, 与 link 0,1 并槽
  link 3    Cuffe → 2110697#0   (dir l)  槽 (W,L)    2
  link 4    Cuffe → 4629169#0   (dir s)  槽 (W,T)   55
  link 5    Harcourt → 4078079#1 (dir l) 槽 (S,L)  206
  link 6    Harcourt → 2110697#0 (dir s) 槽 (S,L)   24        ← 几何判为左转, 与 link 5 并槽
  link 7    Harcourt → 4629169#0 (dir r) 槽 (S,R)   61
  link 5 与 Cuffe 的 link 3/4 不交叉、不同车道 (相容); link 6 与 link 3 交叉且同车道、与 link 4 交叉 → 整个 (S,L) 槽被判与 Cuffe 冲突。
  同理 link 0,1 与 Cuffe 相容, link 2 与之冲突 → 整个 (E,T) 槽被判与 Cuffe 冲突。
  结果: enum 菜单 4 相位 {WL,WT} {SR,WL} {SL,SR} {ET}; 8std 的 {3,4,5} 与 {3,5,7} (Cuffe 相位里加 Harcourt 左转 206 辆/h) GS 放不出来。
  Harcourt 是 98 m 单车道, 71% 左转: 可放行相位 enum 1/4, 8std 3/4。原场景 exp290 best×10 种子该路口均值 114 s (全网最差), exp297 的 ep20-35 评估尖峰全出在此。

§4 修正 (enum_phases.py --split-slots, 默认关闭)
─────────────────────────────────────────────────────────────────────────────────────
  规则 (只在确实藏住相容组合时触发): 槽内 link 去向 ≥ 2 个, 且存在另一进口的槽 B 使 "整槽与 B 冲突但槽内至少一条 link 与 B 完全不冲突"
    → 把槽内 netconvert 标注转向与几何转向不同的 link 改归到该进口的 (进口, 标注转向) 槽, 前提是那个槽原本为空; 不把原槽搬空。
  全网只触发一个路口、两条 link: link 2 (E,T)→(E,R), link 6 (S,L)→(S,T)。原几何转向保留在 meta 的 turn_geometric, 触发记录在 meta["slot_split"]。
  重新枚举后该路口菜单 4 → 6 个相位:
      rrrGGGrr {SL,WL,WT}   = 8std 的 Cuffe 全部 + Harcourt 左转
      rrrGrGrG {SL,SR,WL}   = 8std 的 Cuffe 左 + Harcourt 左 + Harcourt 右
      rrrrrGGG {SL,ST,SR}   = Harcourt 全部
      rrGrrGrr {ER,SL}        St Stephen's Green 右转 + Harcourt 左转 (新)
      GGrGGrrr {ET,WL,WT}     St Stephen's Green 直行 + Cuffe 全部 (新; 对向直行)
      GGGrrrrr {ET,ER}      = St Stephen's Green 全部
  产物 (新文件名, 旧文件不动): nets/dublin/dublin_enum_splitslot.net.xml, dublin_enum_splitslot_meta.json,
        nets/dublin/weekday_18h_reroute_v2/dublin_weekday_18h_probe11h_enum_splitslot.sumocfg。
  验证:
    - 无开关运行枚举器 (输出到临时目录) 与现有 dublin_enum.net.xml / dublin_enum_meta.json 逐字节相同 → 默认路径未变。
    - 新旧对比: meta 与 tlLogic 只有这一个路口不同; 除 tlLogic 外路网文本完全相同; n_actions (K_max) 仍为 11; 观测维度仍为 326。
    - 对新文件重跑 §2 全部审计: A0/A1/A2/A4/A5/A8 全过, A3 = 0, A7 = 0 (GS 现在包含 8std 的全部相位), 多去向槽只剩 1430847303 (无影响)。
    - sumo 加载无新增告警; FRAP 相关测试 23 项通过; smoke_enum 对新配置 exp300 与旧配置 exp299 均 SMOKE OK ("net greens == meta menus" 两者都过)。
    - 固定配时 (每相位 30 s, 改道第二版, seed 123) 全网: 旧 enum 5667 辆 / 52.4 s, 新 5682 / 51.6 s, 8std 5793 / 48.2 s。
      该路口在固定配时下 Harcourt 进口等待不降 (13536 → 14532 s): 相位从 4 个变 6 个, 周期变长, 等分配时不能体现菜单的价值; RL 自选相位, 以训练结果为准。

║   Part 1: Reward 设计审计 — avg-waiting 的四个问题(按严重度排)            ║

─────────────────────────────────────────────────────────────────────────────
  1.1 ★★★ 稀释效应 (dilution) — 实测确认, 但方向出乎直觉
─────────────────────────────────────────────────────────────────────────────

实验: t 路口固定 phase 0 不动, 让其它方向 queue 持续增长, 每 5s 记录 car 的
      count / sum_wait / avg_wait (2026-06-10, seed 7, 150s):

  t=90:   49 辆, sum=1422, avg=29.02
  t=95:   57 辆, sum=1611, avg=28.26   ← 新车波到达, avg 反而降 (↓稀释)
  t=100:  53 辆, sum=1808, avg=34.11
  t=105:  62 辆, sum=2020, avg=32.58   ← 又一次 (↓稀释)

量化: 被堵住的 queue 里每辆车每秒老化 1s, avg 理论上应每 step (+5s) 涨 5;
      实测只涨 ~2/step —— **约 60% 的老化信号被新到达稀释掉**。
      sum 的增速 = 当前排队数 (二次增长), avg 增速 ≈ 常数 (线性, 且带抖动)。

后果 (三条, 注意方向):
  (a) 无紧迫度增长: 70 辆的 queue 和 10 辆的 queue, 继续压红灯的 per-second
      penalty 一样大 (甚至更小)。agent 对"长 queue 更急"无感 → 整体效率损失。
  (b) reward 抖动: 到达是随机的, avg 直接被到达扰动 → Q target 噪声
      → 加重 fit-noise (见 Part 3 的 SNR 链条)。
  (c) ⚠ 对 amb-vs-bus margin 的影响是 **amb 有利** 的:
      amb n=1, avg_amb ≡ 该 amb 的 wait, 每秒精确涨 1, 零稀释;
      bus/car 的 penalty 增速被稀释打折。
      → 稀释 **不是** 5-4-1 倒挂的原因 (它反而轻微帮 amb)。

是否要解决?
  - 对 priority 故事 (thesis 主线): 不必须。amb 不受稀释影响。
  - 对整体效率 + target 噪声: 值得一个受控 ablation。
  - ⚠ 不要改成 sum: sum 让 117 辆 bus 的总量碾压 2 辆 amb —— per-class avg
    正是让 amb 的 per-vehicle weight 打满的机制, 这是当前设计 **正确** 的部分。

  候选修正 (保留 per-class 归一, 找回紧迫度):
    A. avg × sqrt(count):  部分计数敏感, 不至于 bus 总量碾压      [推荐先试]
    B. sum / N_expected:   分母用固定期望车数, 消除"到达即稀释"
    C. car/bus 用 Δ累计延误 (PressLight 式), amb 保持 wait        [改动最大]

─────────────────────────────────────────────────────────────────────────────
  1.2 ★★★ State-Reward 错位 (aliasing) — 当前设计最大的硬伤
─────────────────────────────────────────────────────────────────────────────

  Reward = 100% waiting-time 的函数 (per-class avg accumulated waiting)
  State  = PriorityBCA = **纯计数** (phase + min_green + 每 lane 车数 ×3 类)
           → 含 0 个 waiting 信息

  两个 obs 完全相同的状态 (同车数同相位), 因等待年龄不同, 真值可以差数倍
  → Q-net 注定有不可消除的 value 噪声 (state aliasing)。

  这直接对应 checkpoint 诊断里测到的链条 (Part 3):
    5-4-1 时 amb 状态 |TD| = 0.635 (平均的 1.5 倍), Q-margin std 0.617
    → 29% 决策步选错相位。其中一部分噪声是 **结构性的**:
    agent 根本看不见 amb 已经等了多久, margin 必然估不准。

  修复 (代价极小, 收益直接打 SNR 的分母):
    新 obs = PriorityBCA + per-class per-lane accumulated waiting (/100)
    (库里已有 PriorityWaitingBCAObservationFunction, 只含 waiting 不含 count;
     建议新建 hybrid: counts + waiting 都给, 维度 77 → ~113)
    ⚠ 注意: 改 obs 后与 exp145-147 不再 controlled, 作为新 ablation 轴。

─────────────────────────────────────────────────────────────────────────────
  1.3 ★ amb 的 avg ≡ max ≡ 该 amb 的 wait (单 amb 场景)
─────────────────────────────────────────────────────────────────────────────

  本场景每路口每时刻最多 1 辆 amb → avg_amb = max_amb = 这辆 amb 的等待。
  实证: exp167 (ambmax) 与 exp147 (avg) 的 eval 序列 **逐点完全相同**
  (两个不同 reward 训出 byte-identical 的行为) —— ambmax 在单 amb 场景退化。

  推论: 要放大 amb 信号, 瞬时 max 无效, 只有两条路:
    - 时间维非线性: amb 项用 wait² (或 exp(wait/τ)) —— 等越久惩罚超线性
    - 事件 bonus: amb 通过路口时一次性正奖励 (potential-based shaping)

─────────────────────────────────────────────────────────────────────────────
  1.4 ✓ 无问题项 (审计过, 排除)
─────────────────────────────────────────────────────────────────────────────

  - waiting_time_memory = 1000 (默认) = 全 episode 长度, 无饱和 (amb 最长
    观测 125s << 1000)。
  - /100 缩放: 无害, 只是尺度。
  - reward 只算 incoming lanes: 合理 (outgoing 不该罚)。
  - 跨 lane wait 修正逻辑 (env.vehicles 簿记): 行为正确。

四个候选协同方式的实测判决:

─────────────────────────────────────────────────────────────────────────────
  2.1 ✗ 静态可学 β (CoeffDQN, additive sigmoid)  → 死路, 两次复现
─────────────────────────────────────────────────────────────────────────────
  sigmoid(β) 最终值 [up,down,left,right]:
    exp145 (5-2-1): [0.5, 0.5, 0.0, 0.0]   ← left/right 学到 0
    exp147 (5-4-1): [0.5, 0.5, 0.0, 0.0]   ← 完全一样
  邻居 reward 对梯度的影响 = 精确的零。CoeffDQN 优于 vanilla 的部分
  全部来自 concat state。原因: 邻居 reward 与本地 action 的因果延迟 5-50s,
  additive β 下调它是降低 target 方差的最快路径 → β→0 是稳定吸引子。

─────────────────────────────────────────────────────────────────────────────
  2.2 ✗ 常开凸组合 (α=0.5, FixedCoeff/GATCoeff/TPAMI-style) → 实测有害
─────────────────────────────────────────────────────────────────────────────
  exp166 (uniform mean): amb 6.29±4.04 (vs 纯本地 exp147 的 3.13±1.66)
  exp163 (GAT-β):        amb 5.54±4.80
  机制 (实测): 训练后期本地控制好了 own_r 很小, nb/own 量级比 = 14~17×
  → eff_r 被邻居信号主导, 本地 amb 事件信号被进一步稀释 (在 0.5% 梯度占比
  的基础上再砍半)。**常开混合在 99% 无事件的时间里只贡献噪声。**

─────────────────────────────────────────────────────────────────────────────
  2.3 ✗ GAT 动态 β (reward 层 attention) → 本拓扑学不出判别
─────────────────────────────────────────────────────────────────────────────
  exp163 GAT-β entropy 全程 0.689→0.691 ≈ ln2 (两邻居均匀分布的最大熵),
  β_left/right 0.74/0.76 横盘 2000 ep。原因: 1x3 chain 上 e 的左右邻居
  reward 高度相关, 权重给谁 loss 都一样 → 无判别梯度压力。
  GATCoeffDQN 实际退化为 FixedCoeff (数据印证: 5.54 vs 6.29, 同病)。

─────────────────────────────────────────────────────────────────────────────
  2.4 ✓ 选定方案: 事件门控加性协同 (event-gated additive coordination)
─────────────────────────────────────────────────────────────────────────────

  公式:
    eff_r_i = own_r_i + λ · Σ_d 1[amb ∈ nb_d 的 incoming] · nb_amb_r_d

    其中 nb_amb_r_d = 邻居 d 的 reward 中只取 amb 项 (= -γ_w · 邻居amb等待/100)
    门控 1[·] 从 nb_obs 的 amb_inc 计数直接读, **不学习, 无参数**
    λ 唯一超参, 建议从 1.0 起扫 {0.5, 1.0, 2.0}

  为什么这个设计每一条都对着实测证据:

    证据 1: cos(grad_AMB-nb-only, grad_OTHER) = +0.74
      → "邻居有 amb"的状态目前被当普通交通状态学, 完全没有形成
        "amb 要来了, 提前清道"的绿波前导行为。
      → 门控项恰好只给这些状态注入专属 reward 信号。

    证据 2: 99% 的 step 无 amb → 门控关闭, eff_r = own_r
      → 保住 exp147 已被证明的全部本地能力 (它仍是 5-4-1 下最好的),
        不重蹈 α=0.5 常开混合稀释日常信号的覆辙 (2.2 的教训)。

    证据 3: β→0 (2.1) 和 GAT entropy=ln2 (2.3) 证明
      "让网络自己学什么时候听邻居"在这个信号结构下学不出来
      → 门控显式写死 (amb 计数>0), 把可学部分压缩到一个标量 λ。

    证据 4: amb 路线 t→e→J0 固定走廊, 下游路口提前 5-50s 能从
      邻居 obs 看到 amb (saliency 显示网络对邻居块敏感度占 53%,
      信息通路已存在, 缺的只是 reward 信号)。

  配套 (训练层, 与协同正交, 同等重要):
    Stratified Replay — 每 batch 强制 amb-related transition 占 25%
      (单独 amb buffer, 组内 uniform, 不按 TD 优先 → 不会重蹈 exp153
       PER 过拟合 outlier 的覆辙 [amb max 125s, std 26.9 的教训])
      直接把 amb 梯度占比从实测 0.5% 提到 ~25%, 打 SNR 分母。

  不做的事 (数据已否决):
    - PER / PER+Double (exp153/156: 7.96±26.9 / 34.8±127)
    - 任何常开 reward 混合 (α 凸组合)
    - reward 层 attention (GAT-β)
    - 瞬时 ambmax (单 amb 场景 ≡ avg)

║   Part 3: 根因链回顾 (5-4-1 倒挂, 全部实测数字)                             ║
╚══════════════════════════════════════════════════════════════════════════════╝

  决策余量 (margin) 与拟合噪声 (noise) 的赛跑, 两头同时塌:

  margin = 5 − (w_bus + 1):        +2 (521)  →  +1 (531)  →  ≈0 (541)
  amb 状态 |TD| (fit noise):       0.365     →  0.420     →  0.635
  Q-margin/std @ t (决策信噪比):   1.24      →  0.94      →  0.62
  amb 在场选 amb 相位 @ t:         93%       →  86%       →  71%
  amb 结局 (eval per-visit):       1.04      →  1.67      →  3.13 (倒挂)

  深层机制:
  - on-policy amb transition 仅 1.9%, 梯度占比 0.5% (TD² 加权)
  - 平衡点随 w_bus 上升倒向 OTHER: 521 时 amb 拟合优于平均 (0.365<0.432),
    541 时 amb 扛 1.5× 残差 —— 余量最需要精确 Q 的时刻, Q 恰好最不准
  - 倒挂只发生在协同方法 (vanilla 5-4-1 不倒挂): 协同方法把 bus 优化到
    2.3s 的能力, 挤压的正是 amb 独占的无-bus 相位 (t 路口 +4.16 震中)
  - obs 无 waiting 信息 (1.2) 是噪声的结构性下限

║   Part 0: TL;DR                                                              ║
╚══════════════════════════════════════════════════════════════════════════════╝

  1. A/B/T work 吗? — **B 和 T work, A 崩了**:
     B(173) 和 T(174/182) 收敛良好 (reward -38/-40/-37, 与控制 -34.5 同档);
     A(172) 训练性崩溃 (reward -122→-598 持续恶化, 大瘫痪 speed 0.95,
     completion 0.77, 末期救护车根本到不了路口), tuned 版 A(180) 同样不行
     (-233) — A 方案在两种容量下都失败, 是方案级问题不是调参问题 (见 2.3
     的"常绿右转污染"假说, 有修法)。
  2. 核心主张拿到首个数据支持: **优先级桶 state 改善优先级车辆**。
     B-cqm(177) amb 3.65±3.00 vs 控制 PriorityBCA(175) 7.15±6.87 (-49%),
     代价 car +11% (32.0 vs 28.9)。且 **177 保住 541 排序 (amb 3.65 < bus
     6.03), 控制臂反而倒挂 (amb 7.15 > bus 3.90)** — "看见优先级桶"直接
     兑现成优先级结果。(单 seed, std 有重叠, 待多 seed。)
  3. 字段消融结论清晰且有两个反预期:
     reward 排序: cqm(-38.8) ≈ cq(-38.5) > c(-58) > cqmm(-67) >> qm(-481发散)
     amb 排序:    cqm 3.65 < cq 4.65 < c 5.75 << cqmm 12.85 << qm 26.1
     → +mean 兑现 AUDIT 预测 (amb 改善 22% 且效率不付费) ✓;
     → max_awt 有害 (反设计预期! 178 全面劣化 + qmax 峰 1451 不稳);
     → **count 不可去** (179 灾难性发散: loss 2.7万, qmax 峰 2.9M) —
       修正我此前 "lean core = queue+mean" 的假设, 实证 core = count+queue。
  4. tuned 包 (hd256/d256 + eps_decay 20k + cap 100k): **伤 MLP 臂、微帮 T 臂**
     (180/181 全劣于基线, 182 略优于 174)。eps_decay×4 下 2000 集可能欠训
     (181 末段仍在恢复), 但同预算下 MLP-tuned 输了。
  5. R2 裁剪被数据正名: 182 的 grad_norm 峰 20820 (被 clip 在 1.0), qmax
     峰 913 后回落收敛; 对照无裁剪的 179 直接 Q 发散到 2.9M。
  6. Transformer 注意力诊断 (182): attn_on_amb 末均 0.05 < 均匀份额 ~0.08
     — CLS 并未聚焦救护车 token, 与 amb 梯度占比 0.5% 的稀疏问题一致 →
     stratified replay 的必要性再添一证。
  7. 倒挂格局 (Part 5): **B 族 5/5 有效臂全部保序; T 族两臂均倒挂 (ns);
     控制臂倒挂最深 (-3.25)** — 倒挂与否是 state 方案的函数。多路口选型:
     B 主力 + T 第二臂 (必配 stratified) + A 修复后补位 + BCA 对照,
     Dublin 押谁由 1x3 结果决定。

  ── 2.1 总体效率: 控制臂最优, B/T 同档紧随 ─────────────────────────────────
    all: 175(27.6) < 173(29.1) < 177(30.6) ≈ 182(30.2) < 174(31.2)。
    控制赢 ~5-12% — 不意外: PriorityBCA 77 维含 in+out 双侧逐道计数,
    新方案 45-173 维只看 incoming (out 信息差异见 ABT_OUTGOING doc)。
    [推测] 1x3 加 ψ 下游 2 维后此差距应大幅收窄 (E1b 可验)。

  ── 2.2 优先级表现: 新方案的核心主张兑现 ───────────────────────────────────
    amb: 177(3.65) < 173(4.65) < 174(5.30) < 182(5.60) << 175(7.15)。
    所有 B/T 臂的 amb 都优于控制; 最优组合 (B+cqm) 改善 49%。
    更重要的是排序: 控制臂 amb(7.15)>bus(3.90) 倒挂 — 在"看车型计数"的
    state 下, 高频 bus 被顺带优化、稀疏 amb 被牺牲; B 臂保序。
    解释: B 按转向分桶 → amb 所在 NS-直行槽的 p5 位是它的专属信号位;
    控制臂的 amb 计数淹没在 24 维逐道车型计数里。这与 1x3 倒挂因果链
    ("稀疏类信号被高频类淹没") 是同一机制的 1x1 缩影 — 而 state 分桶
    在源头缓解了它。

  ── 2.3 A 方案崩溃 — 诊断与"常绿右转污染"假说 ──────────────────────────────
    事实: A 在 hd128(172) 渐进恶化至大瘫痪, hd256(180) 不收敛 — 两个容量
    都失败, B/T 同 φ 同字段同协议却正常 → 问题在"按相位分组"本身。
    主导假说 (与 B/T 对照吻合): A 的每个相位行 = 2 条专属道 + 4 条常绿
    右转道 (右转在所有相位皆 G → 进所有行)。右转流量 4×350=1400 veh/h,
    专属流量仅 2×350=700 → **每行 φ 质量的 ~2/3 是四行完全相同的右转
    噪声**, 行间判别信号被稀释到 1/3。B 把右转隔离在独立槽、T 给右转
    token service=[1,1,1,1] 由注意力学会忽略 — 两者都不受污染, 唯独 A
    把它聚合进每一行。
    修法 (一行级): A 的 served-lanes 集合排除 always_green_lanes (与
    metrics 的 excluded_lanes 口径一致); T 的 service 同步考虑。
    修复后 A 必须重跑 — 当前 172/180 的数字不能当"相位粒度"的判决。
    备注: 渐进恶化形态 (Q1 还有 -122) 提示是"低判别 state + 自强化拥堵"
    的螺旋, 不是初始化问题; 缺 q 诊断 (批1早于诊断代码), 重跑时会有。

  ── 2.4 T (Transformer) 评估 ────────────────────────────────────────────────
    work: 174/182 都正常收敛, 182 与控制 reward 同档 (-36.8 vs -34.5),
    bus 全场最优档 (3.86), R1 身份修复后没有左转失明迹象。
    tuned 增益小 (174→182: reward +3, bus -0.7) — 1x1 12 token 太小,
    attention 没有发挥空间, 符合预期 (T 的主场在 1x3/异构)。
    稳定性: grad_norm 峰 20820 被 clip 拦下 (无裁剪的 179 同期直接发散)
    — R2 决策被数据正名; qmax 峰 913 后回落。
    注意力负发现: attn_on_amb=0.05 < 均匀份额 — 网络没学会看救护车,
    与 0.5% 梯度占比一致。改进杠杆: stratified replay (训练层) 或
    attn 正则 (架构层, 暂不推荐加复杂度)。
    排序: 174/182 均值上轻微倒挂 (ns) — T 臂在 amb 上不如 B 臂,
    [推测] set-pooling 对单点稀疏信号的聚合不如 B 的专属槽位直接;
    1x3 中 stratified + ψ 后再判。

  ── 2.5 tuned 包判决 ────────────────────────────────────────────────────────
    A: 180 失败 (方案问题, 与 tuned 无关)。
    B: 181 明显差 (-156 vs -38), 轨迹震荡 (-539 谷), 末段仍恢复中 —
       hd256 + lr1e-3 无裁剪在 MLP 上不稳 + eps_decay×4 在 2000 集预算下
       欠训。两个解释都成立, 同预算下结论: B 用 hd128 基线即可。
    T: 182 略优于 174 — d256+裁剪是唯一受益组合。
    教训: "容量轴类比对应"在 MLP/Transformer 上反应不同 — MLP 缺裁剪
    保护; 若重试 MLP-tuned, 先给 grad_clip。

    且没有效率代价。**cqm 应设为 A/B/T 的默认字段集** (原默认 cqmm)。

  ── 3.3 max_awt: 反预期有害 ✗ ──────────────────────────────────────────────
    178 vs 177: amb 3.5×差, bus 2.5×差, 训练后期劣化 + qmax 峰 1451。
    设计时的辩护 ("多车桶抗稀释") 被推翻。机理 [推测]: max 是离群值驱动的
    高方差输入 — 单辆久候车使整桶特征跳变, Q target 随之抖动 (qmax 轨迹
    佐证); 对 n=1 的 amb 桶它本来就冗余。处置: 从默认字段中移除;
    若将来要"长尾感知", 用 robust 替代 (如 P90 分位) 再消融。

  ── 3.4 count: 不可去 — 修正我此前的 lean-core 假设 ─────────────────────────
    179 (qm) 灾难: loss 2.7万, qmax 2.9M, reward -2425 谷。我此前推 "lean
    core = queue+mean" (count 与 queue 相关可省) — **数据否决**。
    机理 [推测]: 拥堵中车流缓行时 queue(速度<0.1) 可为 0 而需求巨大;
    mean_awt 无上界且滞后 — 两者都不提供有界、即时的"需求规模"地板信号。
    count 是 obs 里唯一有界且单调反映占用的量, 去掉它后 value 目标失去
    锚点 → 发散。结论: **core = count+queue, mean 是增益项, max 删除**。
    (顺带: 176 只有 count 也能慢慢学 — 地板信号的基础性反向印证。)

  ── 3.5 与控制 (175) 的字段视角对照 ─────────────────────────────────────────
    175 的 77 维裸计数 (in+out, per-type) 拿到最优 all 但最差 amb + 倒挂;
    177 的 65 维 (优先级桶 + cqm, 仅 in) 用更少维度换 amb -49% 和保序。
    字段质量 > 字段数量; out 侧信息是 175 仅存的优势 (ψ 设计已就位待 1x3)。

    模式: **B 族 5/5 有效臂全部保序; T 族两臂均倒挂; 控制臂倒挂最深。**

    机制解读 (与 1x3 倒挂因果链同源):
      B 保序   — amb 所在 movement 槽的 p5 桶是它的专属信号位, 稀疏信号
                 有自己的"格子", 不被高频类淹没 (优先级写进结构);
      控制倒挂 — amb 计数淹没在 24 维逐道车型计数里, 高频 bus 被顺带优化、
                 稀疏 amb 被牺牲 — 1x3 倒挂机制的 1x1 缩影;
      T 倒挂   — set-pooling 聚合后 amb 单点信号要靠注意力捞出, 而
                 attn_on_amb=0.05 表明网络没在看它 (指望网络学 vs B 的
                 结构保证)。可能是可修的训练问题 (stratified 对其病根),
                 非结构死刑 — 1x3 配齐再判。

    口径: 全部单 seed; T 的两处倒挂不显著 (174: amb 5.30±4.59 vs bus
    4.59±1.21, std 大幅重叠); 控制臂 −3.25 最接近可信, 同样待 3-seed。
    改写一条旧结论: "1x1 不倒挂"只在 100%bus 旧场景成立 — 20-80 场景下
    倒挂与否是 state 方案的函数, 这本身就是"状态组织影响优先级结果"的
    直接证据 (论文可用)。

  ── 5.2 多路口 (1x3 起) 方案选型 ────────────────────────────────────────────
    决策: **B 主力, T 第二臂, A 修复后补位, BCA 对照。**

    B 为主力的四条理由:
      (1) 1x1 数据直接支持 — amb 最优 (-49%) + 唯一全系保序的方案族,
          而排序正是 1x3 的核心战场;
      (2) 多路口适配已验证 — 几何归槽在 1x3 三路口逐跳全对、与边名无关,
          U-route 不触发 G2, 零代码可上;
      (3) ψ 下游信息的最自然载体 — movement→to-lanes 连接级一一映射,
          E1b (±ψ) 做在 B 上最可解释;
      (4) 训练便宜稳定 (MLP hd128; 配 I-5 clip 更保险)。

    T 必须同跑 (而非淘汰) 的理由:
      1x1 无优势是预期内 (12 token 无 attention 空间); 回报点在多路口 —
      CLS 的 h_int 是 CoLight GAT 协同的天然挂接点 (E3), 且是 Dublin/异构
      的唯一长期架构。不拿 1x3 数据无法做 Stage 2/3 投资决策。
      T 的 1x3 必选项 (非可选): stratified replay — 1x1 的倒挂倾向 +
      attn_on_amb=0.05 都指向稀疏训练信号。

    分叉点声明: **Dublin 押谁由 1x3 结果决定** —
      若 T+stratified+ψ 追平 B 且协同增益显现 → Dublin 主力定 T;
      若 B 仍领先 → B 做 G1/G3 改造 (角度排序槽) 后同样 Dublin 可用。

    E1 批次构成 (统一 cqm 字段 / 5-4-1 + 5-3-1 双档 / clip 1.0):
      B-cqm + stratified            — 主力
      T-cqm + stratified            — 协同钩子 / Dublin 判据
      A-cqm (先做 I-1 常绿道排除)   — 修复验证臂
      PriorityBCA                   — 对照 (预期 1x3 倒挂 → 反衬故事)
      后接: E1b (B±ψ), E3 (T±GAT)。

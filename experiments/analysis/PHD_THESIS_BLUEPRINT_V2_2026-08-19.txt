§1 W1 — 优先级状态与奖励设计 (encoding)
   "Priority-Bucketed Observations and Contract-Weighted Rewards:
    Preserving Service Ordering in RL Signal Control"

  GAP:
  g1a 主流做法把优先级【只】放进 reward 权重、状态对优先级失明 →
      权重旋钮失效/倒挂。注意: 本文的 reward 同样加权 — 病根不在
      "加权", 在"只靠加权"。三条独立证据:
      (i) 同一加权 reward 下的状态族对照 (exp172-182 清洁台账):
          type-count/T 族 (优先级不可观测) 倒挂 −49% amb @ +11% car,
          优先桶 B 族 5/5 保序 — 倒挂根源是状态可观测性
      (ii) 权重通胀曲线: 加大权重不单调改善高优类 (C1; 旧扫描含
          seed 污染, 按 scope remark 仅作动机不进对比表)
      (iii) multihead 失真: argmax 名义权重精确, 有效决策影响仅
          0.45× — 权重精确 ≠ 优先级实现
      论文表述: "权重定价,桶感知"——加权 reward 的角色是定价(每级值多少),
      优先桶状态的角色是感知(让优先级可观测),逐类平均的 reward 形式是防稀释(单辆 amb 不被车流量除掉)。
      三件缺一即失效;主流做法的病是只有第一件。你的设计不是"不加权",是"不只靠加权"。
  g1b 训练失稳在优先级设定下有特殊代价 — 失稳最先牺牲高优先级类
      (发散取证实测; exp218 multihead 崩盘时 amb 36.9s 为又一例),
      而现有稳定性技巧从未按优先级视角评估/组包 → 对应 RQ1.3/E1-3
      (稳定包 + 发散解剖 + ep800 判据)

  子 RQ:
  RQ1.1 优先级该进 reward 还是进 state? (答: 都进, 但角色不同 —
        state 桶提供"看得见", reward 权重提供"值多少")
  RQ1.2 状态按什么组织才保序? φ 优先桶特征化 (级×count/queue/awt,
        车按契约级别入桶而非车型) × 三种分组 (相位/movement/lane)
  RQ1.3 倒挂的机制是什么? 容量悖论解剖 + "失稳最先牺牲高优先级"
  RQ1.4 奖励口径: 逐类平均再加权 (单 amb 不被稀释) + Q≤0 域界

  解法与机制 (方法怎么封住对应 gap):
  ▶解 g1a — 优先桶状态 + 逐类平均加权 reward, 三重机制:
    m1 感知机制: 车按契约级别入桶 → "哪个级在等"从 reward 的时间
       信用分配问题 (慢/间接/被稠密类淹没) 变成状态的空间感知问题
       (快/直接/逐槽可见) — 梯度能把 amb 价值归因到 amb 特征维,
       不再需要从类失明的计数里反推
    m2 分工机制: 权重从此只承担"定价" (每级值多少), 不再背负
       "让优先级可见"的任务 — 单旋钮双职是主流做法失效的根源
    m3 防稀释机制: 逐类平均后再加权 → 单辆 amb 以满权重进 reward;
       逐车求和口径下一辆 amb 只是 1/N 信号
    (m1 的桶表可换设计是 W3 zero-shot 重排的伏笔: 桶=可插拔接口)
  ▶解 g1b — 稳定包按发散通道逐一对症 (取证驱动的组包, 非堆砌):
    Q≤0 钳位=全负 reward MDP 的域界, 砍跑飞的乐观值; masked double
    =砍 max 算子高估回授; huber=饱和爆炸 TD 梯度; 慢 target=断
    棘轮; γ.95=缩短视界杠杆。为何失稳先杀高优类: 稀疏类的 Q 值由
    少量样本支撑 → 发散噪声最先淹没它们 → 稳定性在优先级设定下
    是保序需求而非训练锦上添花 — 这就是"从优先级视角组包"的含义。

  已做实验与结果:
  E1-1 状态方案大对决 (1x1, exp172-182 + A/B/T 谱系): B 族 (movement
       分组优先桶) 5/5 保序; T 族/type-count 控制组倒挂 — RQ1.2 答案
  E1-2 加权基线的倒挂台账 + 权重扫描 (multihead 权重扫描系列):
       纯权重旋钮无法修复排序 — g1a 实证
  E1-3 稳定包与发散取证 (R-campaign, exp205-209): clamp+eps05 自愈,
       ep800 判据; 发散解剖 5 个数量级; "失稳最先牺牲高优先级"
  E1-4 1x3 泛化 (a/b/c 臂): coeff −15% car wait 稳健; amb 功效声明
       (1.1/ep, 永不引单评) — 评价纪律的起点
  E1-5 Dublin 承载验证 (exp207/208): B 栈上真网 18 路口存活且保序,
       为 W2 提供状态底座

  Claim-Evidence:
  C1 桶状态保序、加权基线倒挂 | E1-1/E1-2 | supported
  C2 稳定包必要性 | E1-3 | supported
  C3 逐类平均奖励防稀释 | 设计论证 + exp211 amb 行为 | supported
  边界诚实: 单 seed; 1x1/1x3 合成流量 (Dublin 在 W2 接棒)

§2 W2 — FRAP 系异构路网建模: 自家设计 + 别家架构 (modeling)
   "Movement-Duel Control over Enumerated Phases: Inductive Bias
    versus Capacity on Heterogeneous Urban Networks"

  GAP:
  g2a 固定 8 相位模板盖不住真实异构路口 (Dublin 13/18 路口 2-3 相位
      非标准菜单); 逐路口独立训练不可扩展
  g2b 原版 FRAP 的相位对竞争无法跨异构路口共享参数
  g2c "更大容量 (attention/多头/协同) 更好"是领域默认假设, 缺系统
      的单变量消融

  子 RQ:
  RQ2.1 动作空间怎么覆盖任意路口? → enum-FRAP: 离线枚举极大无冲突
        movement 组合作菜单; movement 12 槽 = 跨路口普适接口
  RQ2.2 打分怎么组织? → g (自需求) + s (对决, 规则冲突图×可学调制)
        + 相位可加聚合; 单 agent 控 18 异构路口
  RQ2.3 可学交互能否超过手工先验? → 六臂梯子 (中段×协同 双轴):
        注意力叠加 (233) / 替代 (235) / multihead (218/219) /
        浅协同×两种底座 (232/234)
  RQ2.4 协同值多少? → 232-vs-234 同机制对照 (梯子的协同轴)

  解法与机制 (方法怎么封住对应 gap):
  ▶解 g2a — 动作空间从"模板"变"推导": 相位菜单由路口几何离线算出
    (connection → 冲突图 → 极大无冲突组合), 每口得到恰好属于它的
    合法集 (实测 2-11 相位), mask 管合法性 — 菜单是数据不是架构,
    任意异构口零定制代码
  ▶解 g2b — 竞争单元从相位对下沉到 movement 对: movement 关系
    (同臂/兼容/合流/交叉) 是几何普适的 — "北左 vs 东直=交叉"在任何
    路口同义 → 一套 12×12 关系参数全网共享; 相位分按成员可加合成
    (Q=Σg+Σmax s) 天然吃任意相位数/相位大小 → 单 agent 控 18 异构
    口。对照: 相位对参数无跨口语义 (A 口相位3 ≠ B 口相位3), 原版
    FRAP 因此不可共享 — 下沉是必然而非偏好
  ▶解 g2c — 用实验设计而非新方法封 gap: 六臂梯子每臂与邻臂恰差
    一个组件 (中段×协同两轴, 状态/动作/reward/稳定包全程锁定) →
    差异可归因; "偏置>容量"从领域直觉变成单变量证据链, 且 W4 补上
    机制解释 (s 通道承载/可读性谱系) — 消融本身是方法论贡献

  已做实验与结果:
  E2-1 1x1 动作消融 (217 vs 220): per-visit 双镜头 — 8std 价格赢
       (J 71.9 vs 77.7), enum-FRAP 优先级质量赢 (分离 p=4.6e-11 vs
       0.045) — enum 用 ~5% 效率买优先级分离, 对称口是它的客场
  E2-2 Dublin 主战 (208 vs 211): enum-FRAP 双维全胜 (J 9.0<12.7,
       效率 2.51<4.74, amb 0.66<0.78) — 异构菜单是它的主场 (g2a 闭环)
  E2-3 ★六臂梯子终榜 (各 800集/160 evals, 同 eval 流量):
       手工对决 9.0 < 叠加 11.4 < 替代 12.0 (输在 bus +48%, 与 W4 的
       s 通道定位咬合); multihead Dublin 崩 (J 212, amb 36.9s, 关闭
       1x1 D-4 悬案); MTT+浅协同尾崩 (J 尖峰 213) vs 冠军+同一套协同
       稳定平手 (9.3≈9.0, 效率小胜, 滑3最佳 4.4 全史最优) — 失稳源
       隔离到 MTT 底座, 协同本身无增益也无害
  E2-4 意图审计方法论 (09 审计): 叠加/替代两变体的谱系由 transcript-
       as-ground-truth 审计产生 — 可写成 methodology 反思小节
  中心结论: 归纳偏置 > 容量; 手工竞争通道是承重墙 (行为侧; W4 补
       机制侧)。协同判决: 浅协同 (repo-CoLight 同构) 在稳定底座上
       平手、在高容量底座上放大失稳; 深协同列 open problem。

  Claim-Evidence:
  C4 enum-FRAP 制霸异构网 | E2-2 | supported (E2-1 双镜头如实)
  C5 偏置>容量 (三路挑战者全负) | E2-3 | supported (单 seed, E3 前置)
  C6 失稳源=底座容量非协同 | E2-3 对照 | supported
  与 W1 的边界: W1 固定 8std 动作比状态; W2 固定 B 状态比动作/架构
  — 实验设计上单变量互补, 无证据重叠。

§3 W3 — 优先级契约变更: zero-shot 与 few-shot 适配 (adaptation)
   "Zero-Shot and Few-Shot Priority Re-Contracting for Deployed
    RL Signal Controllers"

  GAP:
  g3a 部署后契约会变 (5-3-1 → 4-2-1 / 3-5-1); 从头重训 (2000ep)
      不可行; 微调何时有效、为何失败, 无人回答
  g3b "两个策略都保序, 谁更好"无统一标准; 单标量掩盖排序违约;
      amb 稀疏使评价本身不可靠 (单集 ±30 J 点)

  子 RQ:
  RQ3.1 zero-shot 能走多远? (a) 改价: 原策略+契约重评分;
        (b) 重排: obs 桶重映射 (不动权重的"提示工程")
  RQ3.2 few-shot 微调怎么做? 冻什么训什么 (v1-v4 谱系), 从哪个
        起点热启动
  RQ3.3 微调失败的机制? M1 尺度 / M2 缓冲 / M3 吸引子 三假说对决
  RQ3.4 合规怎么评? 六层 SLA: 指标角色分类 + 门先于价 + 翻转边界
        + 窗口化坏率

  解法与机制 (方法怎么封住对应 gap):
  ▶解 g3a — 三级适配阶梯, 每级有机制不是配方:
    m1 改价→do-nothing 的机制: 强边际母策略 (5-3-1) 已坐在邻近
       价格向量的近优解上; 而新契约自己的 TD 吸引子质量差 (弱边际
       → 解质量差), 从好起点向它训练 = 主动降级。M3 解释了"为什么
       动手反而坏": 新约 TD 梯度在好起点处就指向劣质吸引子, 离开
       起点不需要破坏任何已学参数 (残差臂 base 冻结完好仍劣化 =
       机制铁证)
    m2 重排→桶价分离的机制: 桶是"训练过的感知槽位" (特征检测器只
       在有车流的桶上学过), 契约数字是"价格" — 二者本体不同。重排
       = 把类塞回训练过的槽位复用已学感知 (zero-shot 过门), 解耦键
       (obs_priority_source) 让定价独立变动; 处女桶臂 (267) 是机制
       的阴性对照 — 这条律直接由 W1 的桶设计 (m1 伏笔) 兑现
    m3 few-shot v4 的机制: pair_fc/rel_emb 编码契约无关的路口物理
       (冲突语义不随优先级重排而变) → 冻结; enc+双头编码契约语义
       → 放开 — 只训契约触碰的部分, 300ep 够且避开 OOD 感知灾难
       (heads-only 564 = 冻错侧的阴性对照)
  ▶解 g3b — 用"指标角色分类"把评价问题结构化: 合同条款 (排序门,
    先判) ≠ 价格 (J, 门内比较) ≠ 估计不确定度 (amb 窗口化坏率/同
    种子配对) — 单标量掩盖违约的病根是三种角色混在一个数里; 翻转
    边界证书把"谁更好"变成"在哪些权重下判决会翻" (可携带的证书,
    非点断言) — 评价协议由本战役的真实评价危机催生, 不是事后包装

  已做实验与结果 (14 臂战役 exp227/228/229/230 + 09 复核):
  E3-1 改价 (4-2-1): ★zero-shot do-nothing J39.7 配对 5/5 全胜一切
       训练臂 (few-shot 家族 58.7-73.0, 金标准从头 67.3) — 65-73 是
       弱边际契约的 TD 吸引子, 从头 2000ep 也落入
  E3-2 重排 (3-5-1): ★桶身份≠契约价格律 — 双入训练桶 zero-shot
       (amb→bus旧桶, bus→amb旧桶) 门 5/5 + J 78.5; "契约值即桶号"
       落处女桶 → 267; few-shot v4 physics-frozen (冻物理 pair_fc/
       rel_emb, 训语义 enc+双头, 300ep) 75.5 胜金标准 94.9 (配对
       4/5); heads-only 564 灾难 (冻 enc 背 OOD 不可恢复)
  E3-3 机制判决: M1 证伪 (rscale 无效) / M2 证伪 (warmup20k 无效) /
       M3 确认 (残差臂: base 全程冻结完好仍劣化 — 离开好起点不需要
       破坏参数, 新约 TD 梯度在起点处即指向劣质吸引子)
  E3-4 六层 SLA 协议 + 活案例: do-nothing 在 3-5-1 裸 J 数值碾压
       (60.9) 但违排序门 → 门先于价; 支配预检 + 翻转边界证书
       (217-vs-220 仅 w_amb>122 翻转); amb 窗口化坏率纪律
  E3-5 J 榜完整复核 (11/11 wandb 重算 Δ=0.0) + 关键判决多种子配对
       稳健化 — 评价的评价 (meta-rigor)

  运营手册 (thesis 的可交付物):
    改价 → 不训练; 重排 → 双入训练桶 + 解耦键 (obs_priority_source)
    [+ v4 few-shot]; 被迫训练 → 残差+锚; 一切先过排序门再比价格。

  Claim-Evidence:
  C7 zero-shot 改价定律 | E3-1 | supported
  C8 桶价分离律 | E3-2 | supported (v4-从双入桶起点 = 待补一臂)
  C9 M3 机制 | E3-3 三重 | supported
  C10 门先于价协议 | E3-4 | supported

§4 W4 — KAN 契约内化审计 (auditing) [由"可选"转正 — 理由见 §5]
   "Auditing Priority Internalization with KAN Distillation:
    Effective Weights, Channels, and the Interpretability Cost of
    Architecture"

  GAP:
  g4a 策略"学会优先级"还是"搭几何便车"不可区分 (黑箱)
  g4b 训练期优先级能力丢失不可见 (灾难遗忘无监测)
  g4c 架构的可解释性代价只有定性讨论, 无量化度量

  子 RQ:
  RQ4.1 内化的有效权重 α 是多少, 与名义契约差多远?
  RQ4.2 优先级住在哪个通道 (g 自需求 vs s 对决)?
  RQ4.3 能否作训练期监测器?
  RQ4.4 架构改动的可解释性代价可测吗?

  解法与机制 (方法怎么封住对应 gap):
  ▶解 g4a — KAN 蒸馏之所以能读出内化契约, 前提是 W1/W2 的架构
    选择: g 是"单 movement 16/27维 → 标量"的小函数且输入按级规则
    排布 → 可蒸馏成 G≈Σα_l·φ_l, α 即内化有效权重, 与名义契约同
    坐标可比 — 偏差=失真被测量, 几何搭便车被暴露 (1x1 双通道皆
    car 主导 → amb 优先是几何副产品; Dublin amb 住 g → 真学的)。
    致盲探针的行为交叉验证给读出以外部效度 (读出≠自说自话)
  ▶解 g4b — vintage α 轨迹: 在 checkpoint 上重放同一蒸馏协议,
    灾难丢失表现为 α 崩塌签名 (amb 2.6→0.2 + bus 双通道接管) —
    价值层签名与行为侧独立吻合; 边界如实: 粗监测成立, 细粒度
    (学反/学对之辨) 在 draw 噪声带内不成立
  ▶解 g4c — 谱系的机制: 同一蒸馏协议跨架构复用, 其成功依赖架构
    的可分解性 (逐槽 g) — 注意力混合破坏分解 → R² 崩塌本身就是
    可解释性损失的测量值 (0.77→0.09→0.03)。协议失败模式被转化为

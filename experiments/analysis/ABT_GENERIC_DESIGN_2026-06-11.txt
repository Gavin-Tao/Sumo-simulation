    全 trainer 一致 / eval-seed 修复在位 / NaN 链安全。

  ── 1.1 本轮新实测 (1x3 syc, 2026-06-11) ────────────────────────────────────
    ✓ 三路口 (t/e/J0) A/B/T 全部构造成功; K=4, N_lanes=12, B 占满 12 槽
    ✓ 维度跨 ts 一致: A=45 / B=125 / T=173 → 共享 agent 可用 (G4 的前提
      在 syc 1x3 成立)
    ✓ 120 步三路口 obs 全有限
    ✓ 全 route 逐跳静态归槽: 贯通走廊 (route_we) 在 J0/e/t 一致 E-T;
      转弯路线逐跳语义正确 (S-R→W-R 等); J0 的 -E4/-E5 边名照常工作
      → 几何法 (atan2 方位 + 夹角转向) 不依赖边名/方向命名, generic 实证

  ── G1 ★★★ (Dublin 必修) B 的罗盘槽位在非正交路口会碰撞 ──────────────────────
    现状: _approach = round(进口方位角/90°) → {N,E,S,W} 四格。
    触发: 两条进口道落在同一 90° 扇区 (Y 形/斜交/五岔, Dublin 常见) →
      两条不同道路的 movement 并进同一槽, 计数混合、动作语义错乱。
      另: 恰好 45° 时 Python banker's rounding 不确定归边 (正交网无此角)。
    当前安全性: syc 1x1/1x3 全正交 → 不触发。
    修法: 槽位改"角度排序索引" — 按方位角排序进口臂, slot = rank×3+turn;
      N_SLOTS 从 net 派生 (= n_arms×3)。不再有罗盘语义但保持稳定身份;
      跨路口共享时 rank 即可对齐 (以"最北臂=rank0"约定旋转归一)。

  ── G2 ★★ (环路 latent) B 的 vid→slot memo 在重访时变陈旧 ────────────────────
    现状: _vid_slot 仅按 vid 键控; 车辆若两次经过同一路口 (环线/掉头路线),
      第二次仍取第一次的 slot → 错。
    当前安全性: 已核 1x3 amb U-route 每路口只过一次; 所有现有 route 无重访。
    修法: memo 键改 (vid, from_edge) — 一行级改动, 上环线场景前必做。

  ── G3 ★★ B 的 N_SLOTS=12 硬编码 ────────────────────────────────────────────
    ≠4 臂路口 (Dublin 三岔/五岔) 槽数错。与 G1 同改: N_SLOTS = n_arms×3
    从 net 推导; obs 维度随之 per-ts 变化 → 牵出 G4。

  ── G4 ★★★ (异构必修) 两个 trainer 都是单共享 agent ─────────────────────────
    实测: train.py:214 / traincoeff.py:255 都只建一个 agent, 用
      env.observation_space 单一维度服务所有 ts → 隐含"全网同构"假设。
    syc 1x3 同构 ✓ (本轮实测); Dublin 异构 (K、N_lanes、臂数各异) 直接崩。
    三条出路 (按推荐序):
      (i)  K 无关头 + padding 表示 (Part 3 Stage 2/3) → 保留参数共享
           (好训练的核心: 跨路口共享 = 数据效率×N_ts);
      (ii) padding-to-max: 全网取 N_lanes_max/K_max, 短的补零+mask —
           最小代码改动, 牺牲一点输入效率;
      (iii) per-ts 独立 agent — 最简单但放弃共享, 数据效率最差, Dublin
           大网不可取。

  ── G5 ★★★ (异构必修) Transformer 无 padding/attention mask ─────────────────
    LaneTokenTransformerQNet 按固定 n_tokens reshape; 变 N_lanes 必须
    pad 到 N_max + key_padding_mask (encoder 原生支持, 接 mask 即可),
    obs 侧补零 token + 输出 mask 向量。改动局部、不动架构。

  ── G6 ★★ T 的 service multi-hot 维度绑 K ───────────────────────────────────
    token_dim 含 K 维 service → K 不同的路口 token 不同宽。
    修法: service pad 到 K_max (短的补零) — 与 G5 的 padding 一并做;
    语义不变 ("我被第 k 相位放绿"), 跨路口对齐靠相位排序约定。

  ── G7 ○ (设计差异, 非 bug) 共享车道的三方案语义 — 写进论文的对比点 ──────────
    同一条"直行+左转共享车道"上 5 辆车 (3 直 2 左):
      A: 整条车道进"直行相位行"和"左转相位行"双份 — 5 辆全部双计,
         意图盲 (intent-blind), 高估两个相位的需求;
      B: 按每车 route 拆分 — 直行槽 3 辆、左转槽 2 辆, 意图精确
         (intent-exact)。共享车道处理最强是 B 的核心卖点;
      T: 一个 token, service multi-hot 两位同时点亮 [直,左] —
         需求不拆但"可由谁放行"显式给出, 意图留给 attention 学
         (intent-latent)。
    → 共享车道场景是天然的 A vs B vs T 判别实验 (Part 4)。

  ── G8 ○ Dublin 左行 (LHT) 检查 — 代码安全, 叙事小心 ────────────────────────
    转向分类纯几何 (夹角) → LHT 下 L/T/R 标签依然正确。代码从不假设
    "右转常绿" (service 直接读相位真值) → LHT 自动正确。只有分析叙事里
    "右转=近侧自由转"要换成"左转" — 文字层注意, 代码零改动。

  ── G9 ○ 配置纪律: obs_phase_service 误配给 A/B 会 TypeError ────────────────
    train.py 盲传该键; 只有 T 类接受。现状靠"只在 T 配置里写"维持 —
    可接受; 上 Dublin 多人协作时可在 train.py 按类过滤 (低优先)。

╔══════════════════════════════════════════════════════════════════════════════╗
║   Part 3: 打磨后的 generic 设计 (分阶段, 每阶段可独立交付)                   ║

  设计不变量 (所有阶段共享, 这是"generic"的根):
    I1  φ 优先级桶特征器 (5 级 × 字段) — 与车型解耦, 换 BNF zero-shot;
    I2  分组粒度 = 唯一方案变量 (相位/转向/车道);
    I3  身份信息 = "谁放行我" (service), 不是静态几何 — 既修 R1 又天然
        适配共享车道/LHT/任意相位方案;
    I4  动作契约 = 选一个绿相位 + min/max-green 掩码 (不动 action);
    I5  归一化口径固定 (count/queue÷jam容量, awt÷100) — 跨车道长度可迁移。

  ── Stage 0 (现在, 零代码): 1x3 syc 同构 ───────────────────────────────────
    内容: exp172-182 的 1x3 版 (A/B/T × 基线/tuned, + PriorityBCA 对照),
      配置只换场景文件与 wandb project。共享 agent 沿用 (实测同构成立)。
    价值: 倒挂只活在 1x3 — 这是"状态组织 × 优先级排序"的真战场;
      可直接复用 5-3-1/5-4-1 双档协议 (AB_TRANSFORMER doc 复审6)。
    配套 (强烈建议, 训练层正交): stratified replay (amb 25%/batch,
      REWARD_STATE_AUDIT 2.4) — 1x3 的 amb 梯度占比实测仅 0.5%,
      不修它, 状态层做得再好也喂不进信号。

  ── Stage 1 (1x3 收尾, 极小代码): 协同 + 健壮性 ─────────────────────────────
    a. B memo 键 (vid,from_edge) (G2, 一行) — 上环线/真实路网前的保险;
    b. CoLight GAT 挂接: T 的 CLS 输出 h_int 即为路口嵌入, 邻居 attention
       直接吃 h_int (spec 预留位); A/B 用倒数第二层激活当 h_int;
    c. 宽 except 加"连续非 SUMO 异常 N 次即 abort" (R4, 防废跑)。

  ── Stage 2 (异构准备, 中等代码): 表示层解绑 ────────────────────────────────
    a. B 槽位改角度排序索引 + N_SLOTS=n_arms×3 派生 (G1/G3);
       旋转归一约定: 最北臂=rank0, 顺时针编号 — 跨路口槽语义可对齐;
    b. T padding: token pad 到 N_max + key_padding_mask (G5);
       service pad 到 K_max (G6); obs 返回 (tokens, mask) 或约定零 token;
    c. G4 选型: 先用 padding-to-max (改动最小, 保参数共享);
       per-ts agent 仅作 baseline 对照。
    交付检验: 人造异构小网 (一个三岔 + 一个四岔) 上 A/B/T 构造 + 维度 +
       slot/token 语义冒烟 — 不必等 Dublin。

  ── Stage 3 (Dublin 真网): K 无关头 + 课程迁移 ──────────────────────────────
    a. 相位池化打分头: phase_k 的分数 = MLP(pool({h_lane: lane∈served(k)}),
       h_int) — 参数量与 K 无关, 任意相位方案直接打分; 动作语义仍
       "选一个绿相位" (I4 不破)。这是 spec 原 FRAP 头的回归, 在异构网
       它从"可选"变"必需";
    b. LHT: 代码已安全 (G8), 叙事换"近侧转=左";
    c. 课程: 1x1 → 1x3 → Dublin 子区 → Dublin 全网; 每级 warm-start
       上一级权重 (T 的 token/φ/service 表示跨级不变 → 迁移合法);
    d. 迁移协议: zero-shot (直接评估) vs fine-tune (短训) 两条曲线 —
       这是 thesis 的"generic"主张的实证形式。

  ── 好训练 (trainability) 设计原则 — 为什么这套能训得动 ─────────────────────
    t1. 参数共享 = 数据效率: N 个路口共享一套权重, 每步 N 份梯度 —
        前提是表示同构, 这正是 Stage 2 padding 的全部意义;
    t2. 身份用 service 而非可学位置嵌入: 零新参数、无需学、跨路口语义
        一致 (位置嵌入绑 token 序号, 换网作废);
    t3. 稀疏 amb 不靠状态层解决: 状态层管"看得见", stratified replay 管
        "学得到" — 两层正交, 都要 (实测 0.5% 梯度占比是硬瓶颈);
    t4. Transformer 稳定性三件套已配: dropout=0 (确定性)、grad_clip 1.0、
        lr 预案 5e-4; token 数 ≤ 几十, 计算量可忽略;
    t5. 维度卫生: 死桶 (truck/p4) 在 φ 里保留为零 — 换 BNF 即激活,
        不为省 8 维破坏 zero-shot 结构;
    t6. 永远先冒烟语义 (槽位/service/维度 vs 真值) 再烧 GPU —
        本项目两轮审查抓住的 R1 这种"结构性失明", 训练曲线根本看不出来。

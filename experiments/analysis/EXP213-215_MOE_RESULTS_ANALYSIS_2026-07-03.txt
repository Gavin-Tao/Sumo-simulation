§1 判决先行

  1. MoE-Gcμ v1 三跑全线失败, 与基线差 ~9-16 倍:
       1x1:    exp113 (plain DQN) eval 收敛 ~-35;  exp213 -323 / exp214 -467
       Dublin: exp208 -19.1 / exp211 -17.0;        exp215 -308 (160/160 全崩盘)
  2. 失败不是接线 bug — 探针显示提案被正确执行 (65% 立即执行, 其余为
     min_green 保持), 相位映射正确。是两个设计级机制:
     M-A 专家零多样性: 96% 的决策步 6 个专家提出同一个相位 → gate 的
         动作对结果几乎无影响 → MoE 退化为单条 depth-1 短视规则,
         gate DQN 无信用可分配 (Q 六值几乎相等), 学习空转。
     M-B 短视规则相位抖动: 96/199 步换相 (≈每 2 步一换), 每换插 2s 黄灯;
         depth-1 Δ 不含换相机会成本 → 永远追逐当前最大队列 → 绿灯
         时间被黄灯和残余启动损失吃掉 → car 层饿死。
  3. 用户三层目标里, "每级一个专家+学习 gate 讲故事"的前提 (专家分歧)
     在真实类别混合下不成立: 大多数步只有 l1(car)+l3(bus) 在场, 各专家
     权重向量对同一队列结构给出同一 argmax。

§4 设计层结论与修复选项 (只提案, 未动代码)

  结论: "按优先级分专家"的 MoE 前提在本任务失败的根源是 专家分歧度
  ≈ 0 (M-A) — gate 再聪明也无从选择; 而共享的 depth-1 短视规则本身
  被换相成本击穿 (M-B)。两者都是设计问题, 不是超参问题: 6 个 W 向量
  对"谁的队列最痛"给出的排序在 l1+l3 常驻的混合下几乎总是同解。

  修复选项 (按我推荐顺序):
  S1 给 Δ 加换相机会成本 + 滞回: Δ_k(切换相位) -= (yellow_time +
     启动损失) × 受影响流率; 或最小承诺步数 (>1 个 delta_time)。
     针对 M-B, 对 M-A 无效, 但可先验证"规则质量"下限。
  S2 专家硬聚焦: expert-k 只看 level-k 的质量 (W 改成 one-hot 或
     focal-only), 无该级车辆时提案 "keep/efficiency 兜底" → 提案
     天然分歧, gate 才有真选择。针对 M-A。S1+S2 是最小修复组合。
  S3 换结构: gate 直接在相位菜单上选 (action=phase), 6 位专家的
     Δ 分数拼成特征喂给 gate — 保留"规则可解释性"叙事, 消掉
     "argmax 一致就退化"的结构性风险。改动量最大。
  否决项候补: 若 S1+S2 修复后仍无竞争力, MoE-Gcμ 进 roadmap E 区
  (否决清单), 保留 §3 探针作为否决证据 — "gate-over-identical-
  experts 不可学习"本身是论文可用的负结果。

§5 v2 修复 (2026-07-03 实施, 用户授权"看着改, 要 generic")

  实现 = S1+S2 合并进一个零旋钮模型 (sumo_rl/agents/moe_experts.py,
  design=2 为默认; v1 原样保留 moe_expert_version: 1 供法证复跑):
  * 聚焦专家 (治 M-A): expert-k 只按 level-k 车辆计分, 场上无该级
    车辆 → 弃权(提保持); expert-0 = 全车效率专家。
  * 清空视界计划成本 (治 M-B): score(p) = 在公共视界
    H = clip(max_p T_clear(p), Δt, max_green) 内, "切到 p 并按饱和
    流率放行"下焦点车辆的预测新增等待 (排队第 j 车 min(t_j,H); 未
    服务 H; 到达车 (H−ETA)+)。迟滞自然涌现: 放行中的队列剩余工作
    量小, 弃坑代价高。
  * per-slot 换相延迟对齐 ts.py 真实语义 (黄灯按 link, G→r 才变黄):
    cur 与 p 共有的绿 slot 换相零延迟, 仅新绿 slot 付 yellow。
  * 全部量为环境常量 (Δt/yellow/max_green) + 物理 (ETA) + 工程标准
    (饱和车头时距 2s) — 任意路口/菜单/场景零调参。
  两次设计迭代被手算单测当场抓住并修正: (i) 每计划各自视界不可比
  → 偏向短/空相位有冻结风险 → 改公共视界 H; (ii) 全 slot 计黄灯
  延迟与 ts.py per-link 黄灯不符 → 改 per-slot。

  验证 (全零训练, 规则裸跑, 同网同 reward 同 seed 夹逼):
    1x1 enum (exp213 场景, eval_seed 42, 200 步):

      随机相位        -219.9

      v2 expert0     -159.2  (一致率 1%, 换相率 0.47)

    1x1 8std (exp214 场景): v2 expert0 -109.7 (菜单无关性 ✓)
    Dublin (exp215 场景, eval_seed 123, 720 步, 18 TLS):

§6 v2 重跑中期分析 (2026-07-03, 213v2/214v2 跑到 ~ep1300; vs exp169)

  数据: wandb oysvhdrb(213v2) rn07ddvk(214v2) 2p27if7j(exp169)。
  可比性警示 (169 不是同口径靶):
    exp169 = 原始 4 相位网 + PriorityBCA obs + reward 5-3-1-ambmax
    (显式 amb 最大等待惩罚项!) + eval_seed 123 (213/214 是 42)。
    它的 amb 好是目标函数直接买来的, 不能证明 MoE 结构差。

  确认的三个观察 (窗口 median, eval_seed 42, n=39-80/窗):
  a) 213v2 全程优于 214v2: mean_reward 末窗 -54.7 vs -75.0;
     amb stops 0.5 vs 1.0, amb speed 7.0 vs 6.6 → enum 菜单继续赢。
  b) amb 劣于 169: 169 amb speed 9.0-11.2 / stops 0-0.5 / stopped 0-2.5;
     213v2 后期 speed ~7.0 / stops 0.5-0.75 / stopped 7.5。
  c) "前好后差"为真且与 211 同构: 213v2 amb stopped 2.5(ep0-600) →
     7.5(ep600+), speed 8.7→7.0, 拐点 ep400-600; 同期 car stopped
     50.6→41.1 单调变好, mean_reward -75.6→-54.7 单调变好。
     排除项: epsilon ep200 已到底 0.01, 晚 400ep 的退化与探索衰减无关。

  机制 (checkpoint 探针 probe_gate_shift.py, 贪心 eval, 直接证据):
    ckpt      ep_return  amb在场步的专家选择        跟随amb专家率
    ep200     -52.3      {5:5, 4:2, 2:1} /8         87.5%
    ep500     -56.7      {5:7} /7                   100%
    ep1300    -56.2      {5:4, 4:4, 2:4} /12        66.7%
  → gate 在 ep500 时"amb 在场必委托 expert-5"; ep1300 时 1/3 的 amb
    时刻改选 2/4 号弃权专家 (=按住当前相位不动) — 部分遗忘了让行规则。
    全程 k 直方图同证: expert-4 (本场景无 level-4 车, 永远弃权=保持键)
    从 30/200 涨到 61/200 — gate 发现弃权专家是免费的"hold"按钮,
    用它保 car 流。reward (5-3-1 均值加权) 允许这笔交易: amb 只在
    ~8-12/200 步在场, car 项统治其余步。amb_steps 8→12 也自证
    (amb 过路口变慢, 在场时间变长)。
  功效注: 每 eval 仅 ~2 辆 amb, 单点不可引; 上表为整 episode 逐步
  统计 + 窗口 median (n≥39) 双口径一致。

  解决方案 (按推荐序, 均不改代码):
  F1 moe_lexicographic: true — L4 GUARANTEE 层, 本来就是为这个失效
     模式设计的: amb 在场 → mask 强制 expert-5, 训练与 eval 同时生效,
     gate 无法再学出"无视 amb"。零代码, 改一行 config。代价: amb 在场
     步让渡 car 优化空间 (~5% 的步), 论文叙事恰好需要这个 GUARANTEE
     vs HELP 对照。
  F2 目标对齐: 若对比靶就是 169, 加一条 reward_fn:
     5-3-1-avg-waiting-time-ambmax 的 MoE arm — 用目标函数而非
     动作约束保 amb 尾部。与 F1 正交, 可做 2×2。
  F3 反事实加密 (需小加法代码): 加速 gate 对稀疏 amb 信号的学习,
     但不改变最优解本身 — 最优解就是要交易 amb, 所以 F3 单用无效,
     只作 F1/F2 的陪跑增强。
  预登记判据: F1 后 amb stopped 应回 ≤2.5s 带且不随 ep 漂移;
  car stopped 允许 ≤10% 回吐。

  网络现实 ✓: dublin_8action.net.xml = 都柏林市中心 St Stephen's Green /
    Grafton St / Dame St 区域 (~1.4km × 0.9km), 129 junction / 212 edge /
    27 个信号路口。27 个里 26 个是 2-3 进口臂 (T 形/一对单行), 仅 1 个
    4 臂 → "8 标准相位"大多数路口只有 2-4 个有效动作, mask 是核心机制
    而非附属品。

  Action 设计 (Part 2): 离线预处理脚本把每个 TLS 重建为 8 标准相位
    (左行交通 FRAP 式: 2×直行对 + 2×保护右转对 + 4×单臂全放)。
    冲突关系直接读 net.xml 的 <request> foes 矩阵 (精确, 非几何启发)。
    每相位做"最大兼容闭包"——核心 movement 置 G, 与核心不冲突的其余
    link 全部补 G, 跨冲突的右转补 g (permissive) → 不浪费绿灯。
    无效/重复动作静态 mask; ε-greedy 与 argmax 只在 valid 集合内取;
    buffer 永远只存实际执行的 canonical action; target max 按掩码取。
    动作维恒 = 8 → 恢复共享单 agent 的同构前提 (解 G4)。

  数据现实 ✓: SCATS 本地文件实际只含 4 天: 1/1(周日+元旦), 1/2(周一银行
    假日), 1/3(周二, 唯一干净全天工作日), 1/31(仅 02-06 时)。27 路口中
    24 个能匹配到 ≤130m 内的 SCATS site (18 个 ≤20m), 但部分 site 数据
    缺失/可疑 (220 无数据, 205 全零, 402 异常低) → 需邻站推算。
    GTFS 完整 (子网内 55 个公交站); DFB 2023 救护车日志完整 (station 级)。

  .rou 管线 (Part 3-4): 边界流入 + 转向比例的马尔可夫路径生成; 转向比例
    初值按下游容量/邻站流量加权, 再用"流量守恒线性最小二乘"校准边界流入,
    使各路口仿真通过量 ≈ SCATS site 总量 (无需迭代仿真, 纯线性代数)。
    car = SCATS 总量 − GTFS bus 穿越量。bus 走 GTFS 真实路线+真实班次+
    停站驻留。ambulance 用 DFB 小时率 × 距离衰减暴露模型生成过境轨迹
    (开往 St James / Mater / St Vincent's 方向)。车辆固定 edge 级路径,
    关闭自由变道 (只留战略变道进转向车道) → 车道级近似确定轨迹。

  时段顺序 (决策 D1): 先做 11:00 工作日 (中等流量, 最好调试) → 18:00
    晚高峰 → 02:00 free-flow (1/31 的 02-06 可做第二样本交叉验证)。

  决策登记: D1 时段顺序(11h→18h→02h) / D2 仅保留战略变道 / D3 跨向右转

  ── 2.1 movement 提取 (与 B 方案 obs 共用同一模块) ──────────────────────────
    对每个 TLS 的每条受控 connection:
      approach = 罗盘扇区(进口臂方位角+180°, 1.1 tie-break)  ∈ {N,E,S,W}
      turn     = connection 的 dir 字段 ∈ {l(近侧左), s(直), r(跨向右)}
                 (左行: 左转近侧不跨对向, 右转跨对向 —— 与美式文献镜像)
      movement = (approach, turn);  link → movement 多对一 (多车道同向)
    该映射写入 JSON sidecar (per-TLS: link↔movement↔lane), obs 的 B 方案
    归槽与 action 重建共用, 保证状态-动作语义对齐。

  ── 2.2 8 标准相位定义 (左行 FRAP 式) ───────────────────────────────────────
    核心 movement 集 (T=直, R=跨向右转; 近侧左转 L 不做核心, 全部闭包补绿):
      a0: N-T + S-T        (南北直行)
      a1: E-T + W-T        (东西直行)
      a2: N-R + S-R        (南北保护右转)
      a3: E-R + W-R        (东西保护右转)
      a4: N-T + N-R        (北臂全放)
      a5: S-T + S-R        (南臂全放)
      a6: E-T + E-R        (东臂全放)
      a7: W-T + W-R        (西臂全放)

  ── 2.3 不浪费绿灯: 最大兼容闭包 ────────────────────────────────────────────
    冲突真值来自 net.xml junction 的 <request> foes 位矩阵 (SUMO 原生,
    含合流/交叉全部冲突对) —— 不用几何启发, 精确且零维护 (D4)。
    构造每个相位的 state 串:
      1) 核心 movement 的所有 link → 'G'
      2) 闭包: 其余 link 若与当前已置绿集合零冲突 → 补 'G'
         (贪心序: 先近侧左转, 再按 link index; T 形路口大量相位靠闭包
          变成"实际可放尽放")
      3) permissive: 跨向右转若与核心冲突但属"可让行通过"(其 foes 全是
         对向直行) → 补 'g' (让行绿, 符合都柏林常见 permissive right) (D3)
      4) 其余 → 'r'
    保证性质 (构造即证): 每条 link 至少在一个 valid 相位中非 r → 修复
    1.1 的 5 个"永不放行"坏路口; 每个相位都是其核心的最大兼容扩张 →
    无浪费绿灯。

  ── 2.4 mask 与去重 (canonical action) ─────────────────────────────────────
    相位有效性 (静态, 每路口一次算好):
      invalid ⟺ 核心 movement 集为空 (该臂/该转向不存在)
      duplicate ⟺ 闭包后的 link-G 集合与更低 index 的 valid 相位完全相同
                  → mask 掉, 并记录 dup→canonical 映射
    典型结果 [推测, 预处理脚本会输出实际值]: 2 臂路口 2 个 valid, 3 臂
    路口 2-4 个, 4 臂路口 4-8 个。
    训练语义 (用户关切点, 必须严格):
      • 选择: ε-greedy 的随机分支只在 valid 集合内均匀采样; 贪心分支
        Q 值上对 invalid 置 -inf 再 argmax → invalid 永远不会被选中
      • buffer: 存的 action 永远是实际执行的 canonical index (因为选择
        阶段已经只产生 canonical, 无需事后重映射; 防御性 assert 兜底)
      • target: max_a' Q(s',a') 同样按该路口的 mask 取 → 不会用幻影动作
        的 Q 值自举
      • mask 是静态 per-ts 常量 → 不必进 buffer, transition 只需带 ts 的
        mask 查表键 (或直接把 8 维 mask 拼进 transition, 实现取其简)
    与现有代码的接合 [推测, 待实现验证]:
      • 预处理脚本产出 dublin_8std.net.xml (替换全部 tlLogic 为 8 相位
        程序, 只含绿相位, duration=占位) + dublin_8std_meta.json (mask/
        movement 映射/dup 映射)
      • TrafficSignal._build_phases 读到的就是 ≤8 个绿相位; 合成黄灯机制
        照常工作; action_space 统一 Discrete(8)
      • DQN agent 加 mask 参数 (select_action 与 compute_target 两处);
        改动面小, 与 PER/普通 buffer 正交

  ── 3.1 总体结构: 边界流入 × 转向比例 ──────────────────────────────────────
    无 OD、无转向观测 → 选"边界流入 + 路口转向比例"的马尔可夫生成模型:
      • 起点 (D7, 实测 ✓): 入口 = "没有任何 <connection> 通向它"的 edge
        (连接图真值, 网络内部不可达 → 流量必然在此发生)。本网恰好
        15 个入口 / 16 个出口 ✓:
          主干入口: Camden St Lower (南大门, Camden/Wexford/Aungier 走廊
            唯一北向入口), Dame St(2车道), College Green(2车道),
            Harcourt St, Kevin St Lower, Merrion Sq West/South,
            Grafton St, Fitzwilliam Sq N/S
          次要入口: Duke St, Harry St, Whitefriar Pl, Stephen St Upper,
            Fownes St Upper (小巷, 校准中加先验防吸收不合理流量, 见 3.3)
        出入口不对称由都柏林单行系统解释 ✓ (如 Nassau St 单行东向只出
        不进; Earlsfort Tce 只出) —— 这是真实路网语义, 不是 bug。
        注意: 几何死端法会大量误判 (双向街中间节点满足互逆对条件),
        必须用 connection 图判据 —— M0 脚本固化该列表。
      • 每个入口 edge 是独立 Poisson 源, 率由 3.3 校准给出; 车辆进入后
        在每个路口按转向比例抽样下一 edge, 直到离开子网
      • 抽样在生成 .rou 时一次完成 → 每辆车是完整确定的 edge 级 route
        (满足"轨迹准确从哪儿到哪儿"; 不依赖 SUMO 在线 routing)
      • 环路禁止: 路径生成时不允许重访同一 junction (同时保护 G2)
      • 不做网络内部起终点 (停车场/装卸) [假设 A8]: v1 全部流量
        边界进出; 若 V3 残差显示中心路口系统性高估, 再加停车场
        源汇 (Mercer St 车场就在 site 663 旁) 作为修正项
    为什么不用 SUMO randomTrips.py (用户问题, 显式记录):
      ① 它只能均匀/fringe-factor 抽 OD + duarouter 最短路 → 无法按
         路口级 SCATS 总量校准 (只能全局缩放), 最短路还会把流量不真实
         地集中到少数走廊; ② 无转向比例控制; ③ 产出的 route 不带
         车道纪律与车型结构 (bus 要走 GTFS 真实路线, amb 要走暴露模型)。
      randomTrips 仅可用作 V2 烟雾测试的对照流, 不进正式管线。

  ── 3.2 转向比例 (初值) [假设 A1] ──────────────────────────────────────────
    每路口每进口臂: P(turn) ∝ 下游出口 edge 车道数 × 下游路口 SCATS 总量^α
    (α=0.5 起步)。直觉: 车流偏向"更宽且更忙"的下游。
    单行约束自动满足 (不存在的 connection 概率 0)。
    不做时段差异化 (数据不支持) —— 转向比例全天同一套, 时段差异全部由
    边界流入率承载。

  ── 3.3 边界流入率: 流量守恒线性最小二乘校准 (本管线的技术核心) ──────────────
    给定转向比例矩阵 P, 每条 edge 的稳态流量是边界流入 x 的线性函数:
      f = M(P) · x   (M 由转向比例沿拓扑传播构造, 一次性算好)
    路口 i 的模型通过量 = Σ(进口 edge 流量) = (A·x)_i
    解:  min_x ‖ A·x − s ‖² + λ‖x − x_prior‖²  s.t. x ≥ 0
    维度良好: x ∈ R^15 (15 个入口, 3.1), 目标 ~22 个可信 site → 超定。
    x_prior ∝ 入口车道数×道路等级 (弱正则 λ, 防止小巷入口吸收不合理
    流量 —— Harry St 不该被解出 800 veh/h); λ 取使主干入口解基本不动
    的最小值。
    其中 s = 该小时各路口 SCATS site 总量 − GTFS bus 穿越量 (见 3.4),
    仅对"可信 site"行加入 (1.2 的 ≤130m 且数据正常的 ~22 个路口);
    缺失/可疑路口 (220/205/402/...) 不进目标函数 —— 它们的流量由守恒
    自动插补 (这正是缺失站估计的原理: 不单独拍脑袋, 由邻居流量+拓扑
    推出, 比 IDW 更物理) (D6)。
    残差诊断: ‖A·x−s‖ 的 per-site 残差大 → 转向比例初值有问题, 调 α 或
    对个别路口手工修比例 (预期只需 0-3 处 [推测])。
    产出: 每小时一组 {边界 edge → veh/h}。

  ── 3.4 car = SCATS − bus [假设 A2] ────────────────────────────────────────
    SCATS 感应线圈计全部机动车 → 校准目标里先扣 GTFS 推出的该路口该小时
    bus 穿越数, 余量当 car (出租车/货车/摩托并入 car, 不另立类)。
    救护车量级 (~每小时 1-3) 相对误差可忽略, 不扣。

  ── 3.5 车道级轨迹 (用户要求: 像 1x3 那样不变道) (D2) ───────────────────────
    • route 是确定的 edge 序列 (3.1); SUMO 内 departLane="best" +
      关闭自由变道: lcSpeedGain=0, lcCooperative=0, lcKeepRight=0,
      仅保留 lcStrategic=1 (不留它车辆进不了转向车道, 会死锁)
    • 效果: 车辆只为"按 route 转向"换道, 不为快换道 → 车道占用由 route
      决定, 与 1x3 的语义一致但不会死锁 [假设 A3: 战略变道保留是必要
      妥协, 论文表述为 "lane-disciplined routing"]
    • bus/ambulance 同参数 (bus 进出站本身是 SUMO 停靠机制, 不算变道)

       与各 station 占比
    2) 暴露模型: 子网作为过境走廊的小时救护车数
         λ_subnet(h) = λ_city(h) × w_exposure
       w_exposure = Σ_station P(station) × P(穿越子网 | station)
       其中 P(穿越|station) 用 exp(−d/800m) 衰减打分 station→子网 与
       子网→{St James, Mater, St Vincent's} 三医院方向组合归一 (沿用旧
       MD 的衰减形式, 参数同 800m; 量级预期 1-3 辆/h [推测, 脚本输出后
       核对 daily 总量与 DFB Tara St/Donnybrook 出警量的比例合理性)
    3) 路径: 入口边界 edge 按 station 方向加权抽样, 出口按医院方向加权
       抽样, 子网内最短路连接; 显式校验不重访 junction (G2)
    4) vType ambulance, vClass="emergency" — 但与 1x3 一致: 不开 SUMO 的
       bluelight 特权干预, 优先通行完全由 RL 策略学出 (这是论文主张)
    产出: ambulance.rou.xml。

  ── 9.1 实现中的设计偏差 (均已验证, 重要度排序) ────────────────────────────────
  ⑴ 校准模型改为"生成器一致的蒙特卡洛 A 矩阵", 弃用线性传播 (I−P^T)^{-1}:
     实测发现闭式传播在 St Stephen's Green 单行环岛上计入车辆绕环穿越
     (纯 P 游走平均 14.1 步 vs 禁重访 8.3 步, 总穿越数差 1.7 倍), 即
     "少车×绕圈"凑流量, 物理错误。改为: A[j,k] = 用实际生成器 (禁重访 +
     车道链可行性) MC 估计的期望穿越数 → 校准与生成构造上同分布。
     后果: 总边界流入从 ~2000 修正到 ~3850 veh/h (平均每车过 3.0 个信号
     路口), 这才是和 SCATS 路口总量自洽的需求水位。
  ⑵ 车道锁定的正确实现 = "edge 级 P 游走 + 车道链 DP 证明":
     初版"逐跳只在当前车道可达集采样"被实测否决 —— 等效转向分布趋向
     车道数比例而非校准 P (专用转向车道强制带偏), V3 误差 53%。
     终版: 先按 P 采样 edge 路径(与校准同分布), 再 DP 证明存在
     lane→lane 连接链并据此定 departLane; 链不存在则重采 (~3% 拒绝率)。
     救护车用同一 DP。bus 保留战略变道 (要靠站)。
     ✓ V2 实测: 3647 辆插入, 0 teleport / 0 死锁 → "完全不变道防卡死"
     成立, 且整类"等变道挤不进去"死锁被消除 (用户问题的最终答案)。
  ⑶ SCATS 可信目标的两条新数据规则 (数据驱动, 非手工黑名单):
     a. 探测器存活: live≥4 或 live/total≥0.5 (剔除 668=1/24, 662=2/24
        等部分覆盖站 —— 它们只测部分进口, "路口总量"系统性偏低);
     b. 站名含 "PED" = 路段中点人行横道信号, 只测单街, 永不作路口目标。
     最终可信目标 17/27 (设计预估 ~22 → 实际更严)。
  ⑷ NNLS → 带箱约束的 lsq_linear: 0 ≤ x_k ≤ 700×车道数, 防止解把不合理
     流量塞进小巷入口 (Duke St 曾被解到 663 veh/h/lane)。
  ⑸ bus shape 匹配加"最长连通段救援": 市中心 shape 常踩到子网外街道/
     公交闸门 (College Green bus gate), 整条丢弃会损失 Aungier/Georges
     走廊主力路线 (15/15A/15B/16/14...); 保留最长可行子段后匹配率
     60/144 → 104/144 (其余 40 条 cov≈0, 确实不走子网, 正确剔除)。
  ⑹ "合并 rou"实现为 sumocfg 引用三个 route-files (car/bus/amb 各自按
     depart 排序), 不做物理合并 —— 各组件可独立重生成。
  ⑺ GTFS 服务日选取: 枚举 feed 窗口内全部周二选活跃 service 最多的一天
     (中点日会落进季节性时刻表的稀疏区, 实测只剩 35 个 service)。
  ⑻ 源 net 的两个继承特性: TL link index 有空洞 (剥离行人后未压缩,
     状态串保持原长, 空洞位恒 r); 135109491 存在单 index 挂双 connection
     汇入同一车道 (无法用字符区分, 保留 G, SUMO 良性警告)。
     另发现跨臂/同臂汇入同一目标车道的 merge 不在 foes 矩阵里 →
     reindex 加 merge 降级 pass (次优方 'g')。

  ── 9.5 无竞争路口降级 (用户决策, 当日第三轮更新) ────────────────────────────
  动机: 行人已剥离 (L1) 后, 部分信号灯失去存在理由 —— 实测 9/27 个路口
  在全部三个时段都不存在"互相冲突且都 ≥10 veh/h"的车流对 (如 135109491
  与其西邻 32235616: Nassau 走廊单向直通 377-476 veh/h, 其余臂为 0;
  133307321/32236047 甚至全臂为 0)。保留它们做 RL agent 的害处:
  共享 buffer 被恒定动作样本稀释 + 探索在直通走廊上点红灯, 给邻居
  agent 制造假拥堵噪声。

  互为 foes、且在任一时段均 ≥10 veh/h 的 link 对; 否则 netconvert
  node-patch 降级为 priority 让行路口 (重算让行权), 并验证全部
  connection 不变 (车道链不受影响, rou 文件无需重生成)。

  pedestrian traffic are converted to priority junctions" —— 是 L1 假设
  的自洽推论, 不是 ad hoc 删减。
  结果: RL 控制 18 路口 (动作分布 {2:×5,3:×7,4:×2,6:×3,8:×1});

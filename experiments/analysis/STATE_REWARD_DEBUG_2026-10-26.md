# 状态与奖励逐步独立重算核对报告（2026-10-26）

实施计划 experiments/analysis/STATE_REWARD_EXACT_PLAN_2026-10-26.md 任务 9。工具：
experiments/tools/dublin/state_reward_debug.py（逐步独立重算）、experiments/tools/dublin/state_audit_full.py（全网静态审计）。
全部为只读分析，策略用 exp457 的最后一个检查点（ckpt_ep00800，ckpt_env 默认），种子 123，一整集 720 个决策步。

## 1. 方法

重算工具自己从 SUMO 的 getControlledLinks 与 meta 标签建槽表（不读观测类内部表），每个决策步在同一快照上独立算出
头部、is_green、进口 count / queue / mean_awt、下游 count / queue、lane_occ、槽内最短绿，以及奖励
（legacy = 跨车道记账原公式的复现；visit = 逐秒统计器公式），与环境输出逐维比对。同时统计：
车辆第一次出现在 RL 进口道时是否已带上游等待、共享车道上的车辆观测、多连接索引第二条车道上的车辆观测、被丢弃（槽 −1）的车辆观测、
（车辆，路口）重访次数、旧缓存与当前路线不一致的次数、统计器缺条目次数。

## 2. 四种组合的结果（exp457，18h 改道第二版，种子 123）

| 组合 | 网 | 口径 | 各组最大绝对差 | 奖励最大差 | 统计器缺条目 |
|---|---|---|---|---|---|
| 旧（现行配置） | 8std | legacy，首连接，缓存 | 全部 ≤ 2.9e-8 | 0 | 不适用 |
| 新口径 | 8std | visit，全连接，无缓存 | 全部 ≤ 2.9e-8 | 0 | 0 |
| 旧口径 | 8std_splitslot | legacy，首连接，缓存 | 全部 ≤ 5.2e-8 | 0 | 不适用 |
| 新口径 | 8std_splitslot | visit，全连接，无缓存 | 全部 ≤ 3.0e-8 | 0 | 0 |

差异量级是 float32 舍入。结论：四种组合下环境输出的每一维都等于按定义独立算出的值；新口径下统计器从未缺条目。

旧口径的重算用同样的"按车辆 ID 缓存"规则复现，复现过程中记到 5 次"缓存与当前路线不一致"，正是前面路由核对找到的
5 辆重访公交（39 路三班、44 路一班、X1 路一班）。换句话说旧实现与旧定义一致，错的是定义。

## 5. 新发现与备注

1. 用 457 的旧策略跑分槽网时，cluster_21620852 的车辆观测从 3193 次升到 11053 次：该路口动作从 4 个变 6 个，旧策略对新掩码下的动作语义没有训练过。
   这证实分槽网必须重训，不能拿旧检查点评估。
2. 重算工具自身的一个错误被当场发现并改正：复现旧缓存时最初用了一个全局字典，而观测类是每路口一个实例；改为按（路口，车辆）记后旧口径差异归零。
   记在这里是为了说明旧口径的 2.9e-8 结果是在修正后的参照上得到的。
3. 本会话早先的 ψ 置零闭环、reward 三口径重算等诊断用的是 457 的 ckpt_ep00800（ckpt_env 默认取最后一个检查点），不是 best.pth（ep505）。
   结论方向不受影响，但引用时须写明检查点。
4. 没有发现第 1 到 6 项之外的新实现错误。

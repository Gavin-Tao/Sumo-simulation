# 优先级是否真的起作用: 三层证据 (2026-10-27)

用户问题: "对于新的配置, 我用什么 metrics 来体现我的优先级真的起作用了, 我的 amb 真的得到了优先?" → 按三层做: 第一层 (同一臂内各类车的待遇, 现有 best × 10 数据), 第二层 (换车型孪生对照, 新评估), 第三层 (策略对车型的反应, 状态扰动测试)。
工具: experiments/tools/dublin/priority_evidence/ (tier1_class_metrics.py, gen_probe_routes.py, run_probe_evals.sh, tier2_typeswap.py, tier3_state_perturbation.py, amb_preempt_probe.py); 数据: experiments/analysis/data/priority_evidence_2026-10-27/; 探针路由: nets/dublin/weekday_18h_reroute_v2/probe_{amb,bus,car}_18h.rou.xml (仅评估用)。

## 0. 结论

1. **公交的优先级是真的, 但只在它熟悉的路线上。** 同一臂内公交处处好于小汽车 (零停 89–90% 对 81%, 遇红后停车 1.1–1.3 s 对 2.4–2.6 s); 状态扰动测试里, 在已有小汽车排队的槽上再加一辆公交, 策略切过去放行的概率 (64–68%) 高于再加一辆小汽车 (55–60%)。但把同一辆车放到小汽车的路线上换成公交跑 (第二层), 它停得比小汽车孪生多 (新 541: 2.43 s 对 1.43 s)。学到的是 "某路口某相位在公交多时多放", 不是通用的 "见公交就放"。
2. **救护车没有得到优先, 反而比小汽车差。** 换车型孪生: 新 541 救护车 6.59 s/visit 对小汽车 1.43 s, 新 531 5.54 对 1.41, 新 521 4.39 对 1.56; 行程 timeLoss 多 8–17 s; 对车型盲的新 111 两者相等 (1.29 对 1.26), 说明不是车辆动力学的差别。个案逐步核对: 救护车在 cluster_135109528 的红灯槽里等了 268 s, 状态里 count/queue/等待全部正确 (优先级 5 槽 mean_awt 1 → 181 s), 奖励每步 −1.5 → −9.1 (权重 5 生效), 但 Q 值纹丝不动 (保持相位 −0.03, 其余 −0.06 ~ −0.10); 同一位置的小汽车孪生 5 s 就得到绿灯。状态扰动测试: 往红灯槽里放一辆救护车, 策略切过去放行的概率只有 18–39%, 低于放一辆小汽车 (50–60%)。
3. **原因不是状态、奖励或口径, 是学习信号太少。** 训练每集只有 1 辆救护车、3 次路口访问、几乎不等待, 优先级 5 的那 3 × 12 维特征在回放池里几乎恒为 0, 网络从未学到它们的含义; 奖励里权重 5 的惩罚是对的, 但 Q 函数没机会拟合它。旧四臂完全一样 (旧 541 救护车孪生 3.73 对 1.87, 扰动翻转 10%)。
4. **best × 10 里救护车 "表现好" 是假象**: 那辆固定路线的救护车恰好只经过主流方向被服务的路口, 它的 0 停车和优先级无关; 车型盲的 111 臂同样 0 停车。
5. **处理 (未实施, 待批)**: (a) 部署层救护车抢占掩码 (有救护车在红灯槽就只允许放行它的相位) —— 零重训探针结果见 §4; (b) 训练曝露 (把 36 辆探针救护车/公交放进训练路由, 或每集随机路线), 重训一臂; (c) 状态加优先级加权汇总特征 (Σ w·count, Σ w·queue, 加权等待), 让罕见类别通过共享维度起作用; (d) 论文里优先级证据一律用第二层的配对设计报, 第一层单独报会误导。

## 3. 第三层: 状态扰动测试 (策略决策时对车型的反应)

用 best 检查点在种子 123 上收集全部 12 960 个决策状态。对每个状态、每个当前红灯的真实槽, 注入 1 辆等待 10 s 的车 (count/queue 各 +1/容量, mean_awt 置为 10 s), 看贪心动作是否翻到放行该槽的相位 (只统计原动作不放行该槽且最短绿已满足的状态)。111 臂的观测对车型盲 (全部记为优先级 1), 三类注入等价。

| 臂 | 空槽里放 1 辆: car / bus / amb 翻转率 | 槽里已有小汽车排队再加 1 辆: car / bus / amb 翻转率 |
|---|---|---|
| 新541 | 82% / 57% / 20% | 55% / 64% / 18% |
| 新531 | 86% / 64% / 22% | 60% / 68% / 39% |
| 新521 | 85% / 69% / 26% | 50% / 53% / 28% |
| 新111 (盲) | 93% (任何车) | 58% (任何车) |
| 旧541 | 76% / 72% / 18% | 34% / 70% / 10% |
| 旧521 | 77% / 67% / 23% | 38% / 80% / 23% |
| 旧531 | 78% / 65% / 15% | 47% / 80% / 26% |

读法: (1) 右列是更贴近真实的情形 (槽里本来就有车): 加一辆公交比加一辆小汽车更能让策略切过来 (新 +4 ~ +9 个百分点, 旧 +30 ~ +40), 这是学到的公交优先; (2) 加一辆救护车的效果在所有臂都低于加一辆小汽车, 新旧一样 —— 优先级 5 的特征对策略来说是未学过的维度, 反应接近随机; (3) 旧臂的公交反应更强 (70–80%) 但代价是旧口径下小汽车反应弱 (34–47%), 与第二层 "旧 541 多放公交全网堵死" 一致。

## 4. 零重训兜底: 救护车抢占掩码 (amb_preempt_probe.py)

规则: 某红灯槽的优先级 5 count > 0 → 只允许放行该槽 (等待最长者) 的相位; 最短绿内仍保持; 其余时刻不干预。新 541 best, 探针救护车路由, 10 种子:

| | 探针救护车 停车/visit | 探针救护车 零停 | 其他小汽车 停车/visit | 每集强制改动决策 |
|---|---|---|---|---|
| 不加掩码 (= §2 的 amb 行) | 6.59 s (各种子 4.1–9.0) | 75% | 1.296 | 0 |
| 加抢占掩码 | **0.88 s** (0.63–1.04) | 83% | 1.243 | 64 (51–79) |
| 对照: 小汽车孪生 (§2) | 1.43 s | 78% | 1.191 | — |

抢占掩码把救护车从比小汽车差 4.6 倍变成比小汽车好 40%, 其他小汽车不仅没受损反而略好 (1.296 → 1.243): 原本救护车单独占一个槽被晾几十到几百秒时, 它所在车道上后来的小汽车也一起被晾; 掩码早放早清。这说明 "救护车优先" 用一条规则就能拿到, 而且几乎免费; 剩下的 0.88 s 是最短绿与共享车道头车的物理限制。

## 5. 建议

1. 论文里 "优先级起作用" 的证据用第二层的配对设计 (同车换型), 报: 零停占比、停车/visit、首绿、行程 timeLoss 的配对差与 "更快的占比"; 第一层只能说明公交在训练分布内被区别对待。
2. 救护车优先要么靠规则 (抢占掩码, 部署层, 零重训), 要么靠训练曝露 (每集几十辆随机路线的救护车) 加状态共享特征 (优先级加权汇总) 重训; 现有的 "每集 1 辆固定路线" 既学不到也测不出。
3. 公交优先要在陌生路线上也成立, 同样需要训练时随机化公交路线或加权汇总特征。

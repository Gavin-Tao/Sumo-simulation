# 新场景最终设计 (只含 SUMO 场景文件): 真实都柏林路网 + 完全人造的背景车流 + 50 对公交/救护车 (2026-10-27)

范围 (用户令 2026-10-27 晚): 本文档只定义 SUMO 场景文件 —— 路网、车类、背景车流、实验车辆的路线与时刻表、文件清单、标定与核对。
训练安排 (种子、轮换、臂)、评估方案由用户后续另行指示; 最长等待掩码与救护车抢占规则用户决定不考虑, 本文档不涉及。
定位: 在真实都柏林 18 路口路网上, 用受控的人造车流检验 "只改优先级规格, 各类车的待遇是否按预期相对变化" (导师要求: 像对像 —— 同路线同时刻的车比, 或按路口比)。不回答 "12 米公交怎么通行", 不要求与 SCATS 相符。
用户决定 (2026-10-27 晚, 最终): 三类车同物理参数; 50 对; **所有车辆的路线与流量都可以任意设计, 由我决定, 只要符合验证目的; 训练时不能一直死锁或过饱和到没法训练**。
来源: DESIGN_UPSTREAM_AND_PRIORITY_AGG §7/§7.1, 两轮外部复核 (逐转向竞争表已按 meta 与路由核对), 锁死审计 (LOCK_AUDIT), 18h 改道的教训 (DUBLIN_18H_REROUTE)。

## 1. 路网与车类

- 路网与 meta 与 461 相同 (dublin_8std_splitslot)。已核对: 没有公交专用道、没有车类限制车道、没有 emergency 特权标记。
- 18 个 RL 路口里 659802 / 133307283 / 32236377 / 135109534 现实中无信号 (10-11 核实), 本场景按信号路口处理, 与所有既有实验一致; 论文注明 "人造车流 + 人造信号"。
- vType 三个, **物理参数完全一致** (用户令): 与 car 原来一样 = SUMO passenger 默认: 车长 5.0 m / 车宽 1.8 m, accel 2.6, decel 4.5, emergencyDecel 9.0, maxSpeed 55.6 m/s, speedDev 0.1, tau 1.0, vClass passenger, lcStrategic/lcCooperative/lcSpeedGain/lcKeepRight = 0。只差 id (car / bus / ambulance) 与颜色 (只影响 GUI)。三个 vType 集中定义在 vtypes_same.add.xml。
- 背景车全部 vType = car。GTFS 公交与原探针救护车不再使用 (背景是人造的, 不需要它们; 公交类统计因此只含 50 辆实验公交)。

## 2. 背景车流 (完全人造, 为验证与可训练性设计)

### 2.1 设计原则

1. **有竞争才有优先级**: 每个路口至少两个相位集都有需求, 实验车走的转向要有竞争相位在排队或在到达。常绿运动 (在该路口每个相位都放行, §2.2 标出) 不构成竞争, 只给少量背景需求。
2. **可训练 (用户要求)**: 训练初期 ε = 0.9, 策略近似随机, 每个运动平均只拿到约 1/相位数 的绿灯时间。按饱和流 1800 辆/h/车道、有效绿 0.8 估计, 随机策略下单车道运动的通过能力约 1150 / 相位数 辆/h (6 相位 ≈ 190, 3 相位 ≈ 380, 2 相位 ≈ 575)。设计需求取其 70–80%: **6 相位路口每运动 ≤ 150, 3 相位 ≤ 280, 2 相位 ≤ 400** (共享车道上的几个运动合计受同一上限)。这样随机策略下队列也有界, 训练不会一直死锁或过饱和; 训练好的策略下饱和度约 0.4–0.6, 仍有排队与竞争。
3. **不跨非 RL 让行口**: 18h 改道的教训 (Aungier → Peter's Row 让行合流把全网堵死)。背景路线只在 RL 路口之间走, 经过的非 RL 节点必须是本路线有路权的直行通过 (route_structure_2026-10-09.py 核对), 否则截断路线。
4. **既有均衡也有主支**: 多相位均衡路口 (1448442 型) 检验 "换哪个相位", 两相位主支路口 (1430847303 型) 检验 "肯不肯打断主流"; 共享车道路口 (659802、cluster_21620852、1448436) 保留但主流压到可训练上限以下。
5. 总量与 18h 同量级 (约 10 000 次运动访问/h, 约 6 000–7 000 辆/h), 只是分布按验证需要设计。

### 2.3 生成规则

- 路线 = 18h 真实小汽车路由的子路径 (保留真实路径结构), 经过 1–2 个 RL 路口: 优先取 "上一个 RL 路口出口边 → 本路口 → 出口边离网" 这类 2–3 边的子路径; 起点边长度 ≥ 60 m (13 个运动的进口边只有 10–27 m, 如 1448442 的南进口 10.7 m、389281 北进口 10.6 m、389332 东进口 11.3 m, 必须从上游一条边起步, 那段必须是有路权的直行通过非 RL 节点, 否则改为从相邻 RL 路口出口边起步)。
- 每条子路径贡献它经过的每个 (路口, 转向) 的需求; 生成器按 §2.2 表做需求记账 (贪心: 优先用覆盖多个缺口的子路径), 最后重算逐转向实际需求并写入 README, 任一转向超目标 15% 以上则回退。
- 出发时刻在 0–3600 s 均匀随机 (固定随机种子, 文件固定); 全部 vType = car; 车辆 id 带 (路口, 转向) 标签便于追溯。
- **车辆行为约定与 18h 完全相同 (用户确认 2026-10-27)**: (a) 三个 vType 的换道参数 lcStrategic / lcCooperative / lcSpeedGain / lcKeepRight 全为 0 —— 车辆不换道, 插入到哪条车道就一直在哪条车道, 所以状态里 "车道 → 运动槽" 的归属从插入起就固定, 共享车道头车阻塞等现象可复现; (b) 每辆车写明 departLane (与 18h 一样是具体车道号, 不用 best/random): 生成器按 meta 里该运动的 from_lane 指定, 同一运动在两条车道都允许时 (如 389332 的 E-T) 按车道平分; 换道关闭后车道一旦指错车辆就会卡在路口前, 生成后用 SUMO 跑一集核对无 "no valid lane" 类告警; (c) departSpeed = max, departPos 默认; (d) 唯一的随机性是 speedDev 0.1 (与 car 原来一样, 用户要求参数一致) 与出发时刻, 都由固定种子决定, 同一种子下整集逐秒可复现 (训练每集 SUMO 种子 = cfg.seed 的约定不变)。实验车 (§3) 同样遵守 (a)–(c)。
- 不经过非 RL 让行口 (§2.1 第 3 条), 工具核对每条子路径经过的节点。

### 2.4 标定判据 (按顺序, 全部要过)

1. **可训练性**: 随机策略 (每步在合法相位里均匀随机, 遵守最短绿) 跑 10 种子整集: 在网车辆数有界 (后 30 分钟不单调上升, 峰值 ≤ 固定周期峰值的 2 倍), 无锁死 (scan_locks 口径), 插入失败 < 2%, 任何进口道不被排队占满持续 > 120 s。不过 → 按比例下调该路口全部需求 (保持转向比例) 再测。
2. 固定周期 (路网默认配时, fixed_cycle_eval.py) 10 种子: 插入量 ≈ 需求 (失败 < 1%), 小时末在网车辆不增长, 无锁死、无 ≥ 60 s 饿死, 每个转向的出口边不回溢到路口。
3. 一个训练好的参考控制器 (469 best, 车型与本场景一致; **不作为前提**, 只看是否有锁死倾向) 10 种子: 无锁死。
4. §4 的有效决策机会达标。
先放 50 对实验车 (§3) 再做 1–4; 不达标的转向按 §2.2 增减; 迭代 2–3 轮, 每轮记录在 README。

## 3. 实验车辆: 50 辆公交 + 50 辆救护车

### 3.1 路线 (10 条共享, 两类车分配完全相同)

- 从 18h 真实小汽车路由里抽完整路线 (gen_probe_routes.py 的做法), 每条经过 ≥ 3 个 RL 路口。
- 抽取约束: 10 条合起来**按转向覆盖** §2.2 表里的竞争运动 (至少: 1430847303 W-T、659802 S-R 或 S-T、1448436 S-R、26165126 W-R、133307283 N-R、389281 W-R、389332 W-R、cluster_1448439 S-R、cluster_1998326407 N-T、cluster_2498303858 S-R、cluster_5166592137 W-R、5166592132 S-R、32236377 S-L, 以及 1448442 / cluster_21620852 / cluster_135109528 / 135109534 / 26165090 各至少一条支路转向), 同时每类车也有主流转向的访问 (避免一类总在容易过的方向); 每个路口 ≥ 2 条路线。
- 优先选不经过非 RL 让行口的路线 (route_structure_2026-10-09.py 核对), 实在避不开的在 README 里列出每条路线经过的非 RL 节点; 10 条凑不齐覆盖时允许到 12 条 (每条 4–5 对)。
- 两类车的路线分配逐条相同: 路线 r 有 5 对, 每对一辆公交一辆救护车。
- 另抽 10 条互不重叠的路线作 "未见路线" 文件 (备用, 是否使用由后续安排定)。

### 3.2 出发时间表

- 50 对在 0–2700 s 内出发 (每 54 s 一对), 留 15 分钟让最后一对走完 3600 s 的仿真; 未完成车辆单独计数。
- 对内同路线错开 90 s (超过一个周期与两个决策步); 奇数对公交先、偶数对救护车先。错开只是让两类车遇到多种条件, 不当作公平配对 (两辆车面对的背景车流与信号状态不同)。
- 生成工具按固定随机种子产出时刻表, 可生成多份 (同路线集, 重抽出发时刻与先后, 每份一个种子); 份数与用法按用户后续安排定, 第一版先出 1 份。
- 车辆 id 固定 (pair_01_bus / pair_01_amb …), 换标签或换优先级表时 id、路线、出发时刻、物理参数都不变, 这是后续做同车配对的前提。

## 4. 有效决策机会 (标定目标, 场景文件的验收项)

定义 (每辆实验车每次路口访问, 按 5 s 决策步统计): 该步算一次 "机会" 当且仅当
(a) 该车所在运动当前红灯 (常绿运动永远不满足, 自动排除); (b) 竞争相位有需求 (与该运动不同相位集的某运动 count > 0); (c) 控制器有不同的合法选择 (最短绿已满足, 静态相位掩码未把可选动作压成唯一)。
分三类: (i) 接近未停 (速度 > 0.1 m/s, 已在进口道感知范围内); (ii) 已在红灯方向排队; (iii) 优先级对优先级 (竞争运动上也有公交/救护车)。
"优先级只在有排队时体现" 的旧说法作废: 提前切绿、延长当前绿都算优先待遇, (i) 类必须覆盖。
标定目标 (起始值): 每条路线的每个竞争转向每集 ≥ 20 次机会 (三类合计), 全网每类车每集 ≥ 300 次; 三类都非零。机会数在固定周期下量 (与学习无关)。
工具: 新 opportunity_count.py (只读, 固定周期或任一检查点跑一集, 输出每路口每转向每类的机会数)。

## 8. 风险 (场景文件层面)

- 子路径起点边太短导致插入失败: 起点边 ≥ 60 m, 不行就从相邻 RL 路口出口边起步; 插入失败率进 README。
- 随机策略下某路口仍堆积 (共享车道、短进口道的容量低于估计): 按路口整体下调需求, 保持转向比例。
- 经过 2 个 RL 路口的子路径让上游路口的放行影响下游 (想要的网络耦合), 但也可能回溢: 固定周期下核对出口边不回溢。
- 10 条实验路线凑不齐转向覆盖: 允许 12 条。
- 3600 s 内未完成的实验车: 时间表压到 2700 s 内, 未完成数记录。
- 完全人造后与 18h 不可直接比: 有意为之; 同参数版 18h (weekday_18h_reroute_v2_samevtype) 另存, 回答 "真实车流下" 的问题。

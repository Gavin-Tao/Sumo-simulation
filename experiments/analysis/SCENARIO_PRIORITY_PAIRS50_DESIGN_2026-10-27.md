# 新场景最终设计: 真实都柏林路网 + 受控人造车流, 验证优先级规格 (2026-10-27)

定位: 在真实都柏林 18 路口路网上, 用受控的人造车流检验 "只改优先级规格, 各类车的待遇是否按预期相对变化" (导师要求: 像对像 —— 同路线同时刻的车比, 或按路口比)。
它不回答 "12 米公交怎么通行", 也不要求与 SCATS 相符。
来源: 设计文档 DESIGN_UPSTREAM_AND_PRIORITY_AGG §7/§7.1, 2026-10-27 晚两轮外部复核 (六点与逐转向车流表, 已逐条核对), 用户决定 (三类车同物理参数、50 对、111/531/351)。
取代 §7.1 里的 "按路口分组补流" 与 "有排队步 20–40%" 两条。

## 1. 路网、车类与物理参数

- 路网与 meta 与 461 相同 (dublin_8std_splitslot)。已核对: 没有公交专用道、没有车类限制车道、没有 emergency 特权标记, 改 vClass 不会让任何路线失效。
- vType 三个, **物理参数完全一致** (用户令 2026-10-27, 两次强调): 与 car 原来一样 = SUMO passenger 默认: 车长 5.0 m / 车宽 1.8 m, accel 2.6, decel 4.5, emergencyDecel 9.0, maxSpeed 55.6 m/s, speedDev 0.1, tau 1.0, vClass passenger, lcStrategic/lcCooperative/lcSpeedGain/lcKeepRight = 0。只差 id (car / bus / ambulance) 与颜色。做法与 weekday_18h_reroute_v2_samevtype 相同 (去掉 bus 的 vClass/length、ambulance 的 vClass/guiShape)。
- GTFS 的 262 辆公交保留作背景交通, vType 改为 **car** (外部复核建议 "作为普通优先级背景车"): 物理上本来就要和小汽车一样, 优先级按小汽车算, 不进公交类统计, 不需要新类名也不改收集器代码 (收集器按 vType id 分 car/truck/bus/ambulance 四类)。车辆 id 保留 bus_ 前缀便于追溯。
- 原探针救护车 (amb_1) 去掉。

## 2. 背景车流

### 2.1 底

18h 改道第二版的小汽车 5829 辆/h 为底 (它已经排掉了非 RL 让行口的死锁, 18 个路口的行为都已摸清), 加上改成 car 的 262 辆 GTFS 公交。不做全网等比放大 (放大会先把 659802 / 1448442 推进锁死)。
用户 (2026-10-27 晚) 允许改动这份车流; 只做**定向削减**, 且按触发条件执行, 不预先削:

| 流 | 现状 | 为什么可以削 | 做法 |
|---|---|---|---|
| 659802 的 E-R 577 + N-L 422 | 单车道近饱和, 有排队步 28%, 头车堵绿 24%, 新口径 1.7% 的锁死集都在这里 | 加 50 对实验车与补流后最先被压垮; 削减不减少决策机会 | 随机抽掉 20–25% (约 250 辆), 固定随机种子, 路线不变 |
| cluster_1998326407 的 S-L 968 | 全网最大单个运动, 但在该路口常绿 | 不构成竞争, 只给下游非 RL 合流口加压 (旧口径 gneE62 尾巴的来源) | 随机抽掉 30% (约 290 辆) |

### 2.3 补流的生成规则

- 补流车 vType = car, 路线尽量短: 从网络边界或某 RL 路口的出口边进入, 经过目标路口的目标转向后尽快离网; **不经过非 RL 让行口** (18h 改道的教训; 用 route_structure_2026-10-09.py 核对每条补流路线经过的节点), 若某转向无法避开让行口, 降低该转向数量或放弃。
- 出发时刻在整小时内均匀随机 (固定随机种子生成, 文件固定)。
- 一条路线经过多个路口, 补流后必须**重新汇总每个路口每个转向的实际需求** (工具按 §2.2 的口径重算), 防止给一个支路补车同时加重 659802 一类的负担; 659802 的 E-R / N-L 不得增加。

### 2.4 标定判据 (不用排队步占比)

1. 插入量 ≈ 计划需求 (插入失败 < 1%), 小时末在网车辆不持续增长 (后 20 分钟在网车数不单调上升);
2. 每个补流转向的下游有接收能力 (出口边不出现回溢到路口的排队);
3. 固定周期 (路网默认配时, fixed_cycle_eval.py) 与一个合理控制器 (461 best 作参考, **不作为前提**) 各跑 10 种子, scan_locks 无锁死、无 ≥ 60 s 饿死;
4. §4 的有效决策机会达标。
先放进 50 对实验车再量机会 (外部复核第 3 点), 缺机会的转向再按 §2.2 补, 迭代 2–3 轮。

## 3. 实验车辆: 50 辆公交 + 50 辆救护车

### 3.1 路线 (10 条共享, 两类车分配完全相同)

- 从 18h 小汽车路由里抽 (gen_probe_routes.py 的做法), 不用 GTFS 线路 (它们集中在少数主干路口, 且多走常绿运动; 4 个路口一辆不经过)。
- 抽取约束: 每条经过 ≥ 3 个 RL 路口; 10 条合起来**按转向覆盖** §2.2 表里的竞争运动 (至少: 1430847303 W-T、659802 S-R 或 S-T、1448436 S-R、26165126 W-R、133307283 N-R、389281 W-R、389332 W-R、cluster_1448439 S-R、cluster_1998326407 N-T、cluster_2498303858 S-R、cluster_5166592137 W-R、5166592132 S-R、32236377 S-L, 以及 1448442 / cluster_21620852 / cluster_135109528 / 135109534 / 26165090 各至少一条支路转向), 同时每类车也有主流转向的访问 (避免一类总在容易过的方向); 每个路口 ≥ 2 条路线。
- 两类车的路线分配逐条相同: 路线 r 有 5 对, 每对一辆公交一辆救护车。
- 另抽 10 条互不重叠的路线作 "未见路线" 文件 (只用于泛化评估)。

### 3.2 出发时间表

- 50 对在 0–2700 s 内出发 (每 54 s 一对), 留 15 分钟让最后一对走完 3600 s 的仿真; 未完成车辆单独计数并报告。
- 对内同路线错开 90 s (超过一个周期与两个决策步); 奇数对公交先、偶数对救护车先。**错开只用于训练曝露, 不当作公平配对** (两辆车面对的背景车流与信号状态不同); 公平配对见 §6。
- 文件: 训练 5 份 (同路线集, 重抽出发时刻与先后, 固定随机种子), 评估 1 份 (未见时刻表), 未见路线 1 份。

## 4. 有效决策机会 (标定目标与机制指标)

定义 (每辆实验车每次路口访问, 按 5 s 决策步统计): 该步算一次 "机会" 当且仅当
(a) 该车所在运动当前红灯; (b) 竞争相位有需求 (与该运动不同相位集的某运动 count > 0); (c) 控制器有不同的合法选择 (最短绿已满足, F1/最长等待掩码未把可选动作压成唯一)。
分三类: (i) 接近未停 (速度 > 0.1 m/s, 已在进口道感知范围内); (ii) 已在红灯方向排队; (iii) 优先级对优先级 (竞争运动上也有公交/救护车)。
"优先级只在有排队时体现" 的旧说法作废: 提前切绿、延长当前绿都算优先待遇, (i) 类必须覆盖。
标定目标 (起始值): 每条路线的每个竞争转向每集 ≥ 20 次机会 (三类合计), 全网每类车每集 ≥ 300 次; 三类都非零。机会数先在固定周期下量 (与学习无关), 再在训练后的策略下量 (作机制指标报告)。
工具: 新 opportunity_count.py (只读, 用 ckpt_env 或固定周期跑一集, 输出每路口每转向每类的机会数)。

## 5. 臂与训练

- 基底配置: 461 逐位 (精确版口径、对数等待、ψ、车道占用、槽内最短绿位、F1、hidden 128、γ 0.95、800 集、CPU), 换场景文件夹与优先级表, 加:
  - mask_max_wait: 60 s (训练 + 评估; 设计文档 §6.1; W 由零重训探针 30/60 s 的干预次数定, 训练前再在新场景固定周期下核一次干预次数);
  - route_file 按集轮换 5 份训练时刻表 (新键 route_file_rotation, SUMO 种子不变 = cfg.seed, 用户令);
  - eval_collector_1s 保持。
- 初筛: 111 / 531 / 351 × 训练种子 0 / 1 / 2 = 9 次训练 (约 9.5 h/次, 3 并行约 1.5 天)。
- 消融 (初筛后): 531 不开掩码 (种子 0, 必要时 3 个); 之后再决定优先级加权汇总 (obs_priority_agg) 与上游延伸 (obs_upstream_ext) 各一臂。
- 规则基线: 评估时开救护车抢占掩码 (eval_preempt_amb, 训练关), 报 "只学习 / 学习 + 规则 / 111 + 规则"; 称规则基线, 不称上界。

## 6. 评估

best 检查点 × 10 评估种子 (123–132), 逐秒收集器 (--collector-1s), 评估时刻表固定、三臂共用。

### 6.1 三层

1. **类平均 (原来的评估)**: 每类停车时间/visit、停车次数/visit、延误/visit、零停占比、遇红后首绿、行程 timeLoss; 公交类只含 50 辆实验公交 (背景公交已是 car)。
2. **跨臂同车配对 (主判据)**: 同一辆实验车 (同 id、同路线、同出发时刻、同物理参数) 在 531 与 351 (及 111) 的运行里逐路口相减: 救护车 Δ = 停车(531) − 停车(351) (权重 5 对 3), 公交反向; 50 辆 × 10 种子 × 经过的路口 = 上千个配对, 报均值、95% 置信区间、"权重高时更好" 的占比; 分路口类型 (均衡多相位 / 主支两相位 / 共享车道) 报。
3. **同臂换车型配对 (诊断)**: 评估时刻表再以 "全部实验车改为 car" 跑一遍, 同车相减, 回答 "这个策略对救护车比对小汽车好多少"; 三类物理一致, 差值只剩标签。

### 6.2 必报的代价与安全项

小汽车 (含背景公交) 停车/visit 与延误/visit 的变化 (配对种子); 最大等待与 > 60 s 等待的次数; 未完成车辆数; 到达车辆数 (通行量); 锁死扫描 (10 种子); 掩码干预次数/集; 抢占强制次数/集。

### 6.3 预注册的预期 (不是逐条通过的验收)

- 救护车: 权重 5 对 3 的配对差 < 0 且置信区间不含 0 (531 对 351); 公交反向同样成立。
- 111: 两类配对差报区间, 不作 "等效" 结论 (一个标准差内不是等效证明)。
- 小汽车代价: 每次访问 ≤ +0.05 s 为目标值, 超过则报出并讨论。
- 531 的公交 ≈ 351 的救护车 (镜像) 与逐路口同向: 只作一致性诊断, 不作通过条件。
- 未见路线、未见时刻表: 方向一致即可, 幅度允许缩小。
- 任何一条不成立, 用现有工具 (状态扰动、个案逐步、决策机会统计) 解释机制。

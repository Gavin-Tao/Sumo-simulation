# 设计定稿: 上游延伸观测 + 优先级加权汇总特征 (2026-10-27)

针对 PRIORITY_EVIDENCE_2026-10-27.md 查出的两个问题:
- 问题一 (看不见): 受控进口道短于十几秒车程时 (1448436 南进口 22 m, 四个路口最短 10–11 m), 非 RL 路口后面的来车在进入进口道前不在状态里, 优先级没有时间起作用。
- 问题二 (认不得): 每类车各自独立的状态维度, 救护车维度在训练里几乎恒为 0, 网络从未学到; 孪生救护车比孪生小汽车多停 3–6 s, 红灯槽注入救护车的翻转率 18–39% 低于小汽车 50–60%。

原则: 全部是**默认关的新开关**, 旧配置逐位不变; 奖励、统计器、动作集、F1 掩码一律不动; 只改观测类与它的独立重算核对工具。

## 1. 问题二: 优先级加权汇总特征 (obs_priority_agg)

**What.** 每个运动槽在现有 28 维之后加 3 维:

| 维 | 定义 | 归一 |
|---|---|---|
| wcount | Σ_w w · count_w / cap | 直接用 (车道满载小汽车 = 1, 满载救护车 = 5) |
| wqueue | Σ_w w · queue_w / cap | 同上 |
| wawt | Σ_w w · awt_w, awt_w 为该类平均本次访问等待的对数刻度 log1p(s)/log1p(3600) | 直接用 (小汽车等 100 s = 0.56, 救护车等 151 s = 3.07) |

w 取自 priority_source (与奖励同一张表); 111 臂全 1 时三维退化为总计数/总排队/各类对数等待之和, 对车型盲的臂无害。原分类维度保留。
可选开关 obs_priority_agg_scale: log (默认) | linear (awt 用 min(s, 500)/100, 与奖励同形式), 作为消融。

**Why.** 奖励是 −Σ_w w · 平均等待_w / 100, 加权汇总就是奖励在每个槽上的充分统计量; 它只要槽里有车就非零, 每步都在训练, 救护车的贡献沿着小汽车练熟的、单调的方向进入网络 (见 PRIORITY_EVIDENCE §0 第 3 条与对话记录), 而不是落在从未非零过的维度上。

**How.**
- observations.py `PriorityMovementObservationFunction`: 新参数 priority_agg: bool = False, priority_agg_scale: str = "log"; 在每槽循环末尾 (slot_min_green 之后) 追加 3 维; observation_space 维数同步 (28 → 31/槽, 336 → 372)。
- exp_params.obs_kwargs_from_cfg 透传 obs_priority_agg / obs_priority_agg_scale。
- state_reward_debug.Ref.expected_state 同步加这 3 维的独立重算 (验证链要求: 差 ≤ 1e-5 才算实现正确)。
- 其他 (train.py, ckpt_env, eval 工具) 通过 obs_kwargs_from_cfg 自动适配, 不改。

## 2. 问题一: 上游延伸观测 (obs_upstream_ext)

**What.** 对每个路口的每条受控进口道, 从停车线往上游量一个固定的观察距离 D (默认 120 m, 约 10–15 s 车程): 进口道自身够长的, 延伸段为空; 不够长的, 沿前驱车道跨过非 RL 节点继续, 直到累计 D 或碰到另一个 RL 路口为止 (RL 路口的进口道不纳入, 那是它自己的状态)。延伸段上的车按路线判断会进入本进口的哪个运动槽 (与现在给进口道上的车分槽同一规则: (进口边, 下一条边) → 槽), 每槽加 12 维 "在途" 特征:

| 维 | 定义 | 归一 |
|---|---|---|
| ext_count_w (5 维, 每优先级 1) | 延伸段上将进入本槽的该类车数 | / N_ref (默认 10) |
| ext_prox_w (5 维) | 该类最近一辆的接近度 1 − d/D, d 为到停车线的沿路距离; 没有车 = 0 | 0–1 |
| ext_wcount (1 维) | Σ_w w · ext_count_w | / N_ref |
| ext_wprox (1 维) | Σ_w w · ext_prox_w / w_max | 0–1 |

**故意不放**延伸段上的等待、排队、速度: 车在非 RL 让行口等了多久是上游的事, 本路口控制不了也不该为此被奖惩 (10-26 修正去掉的 "继承等待" 不能从这里回来); 本路口需要的只是 "有谁、多近、要来"。奖励与 visit 统计器完全不变, 车进入受控进口道后才按原口径计等待。

**Why.** 等价于在停车线上游 D 米装一组按运动分类的计数检测器 (SCOOT 的检测器摆法); RESCO 真实路网的工作对 < 15 m 的短车道同样把前驱车道并入状态 (arXiv 2309.09881); 救护车/公交的位置特征是 EMVLight 一类 EV 优先工作的标准做法。用接近度而不是距离, 是为了让 "没有车" 与 "车在很远" 都是 0、"车到门口" 是 1, 单调且无歧义。

**How.**
- 建表 (reset 时一次): 用 sumolib 读 net_file (obs_kwargs_from_cfg 传入路径), 对每条受控车道递归取前驱车道 (lane.getIncoming), 节点类型为 traffic_light 且 id 在 RL 路口集合里就停, 否则继续, 记每条延伸车道的 "车道末端到停车线的沿路距离" 偏移; 累计超过 D 的分支截断; 延伸车道与任何 RL 进口道互斥 (不重复计数)。
- 每步: 扫延伸车道上的车, 用路线找到本进口边在路线中的位置 (不在 → 不计), 槽 = by_edges[(进口边, 其后一条边)]; d = 偏移 + (车道长 − lanePos)。
- 参数: obs_upstream_ext: bool = False, obs_upstream_dist: 120, obs_upstream_nref: 10。维数 +12/槽 (336 → 480; 与问题二同开 → 516)。
- state_reward_debug.Ref 同步独立重算 (自己建延伸表, 不读观测类的表), 并新增一项静态审计: 每条延伸车道的偏移、是否跨过了 RL 路口、与进口道是否重叠。
- 延伸段的车不进奖励、不进统计器、不进 lane_occ。

## 3. 部署层兜底 (与训练无关, 可先行)

救护车抢占掩码 (已零重训验证: 孪生救护车 6.59 → 0.88 s/visit, 其他小汽车略好): 触发条件在实现时同时支持两种来源: (a) 受控进口道上的优先级 5 计数 (现在的探针); (b) 延伸段 (或沿路线 300 m 内) 的在途救护车。规则只在救护车出现时干预, 不碰用户否决的 "空槽绿灯掩码"。作为评估/部署选项 (eval_preempt_amb: false 默认关), 报告每集强制次数。

4. Tier 2 孪生 (A, B, C): 救护车孪生停车/visit ≤ 小汽车孪生 (目标 ≤ 0.5 倍), 公交孪生 ≤ 小汽车孪生, 其他小汽车停车不多于 +0.05 s; 短进口道路口 (1448436、389281、1448442、389332) 公交/救护车遇红后首绿明显下降 (B, C)。

## 5. 风险与取舍

- 维数 336 → 516, 学习可能变慢: 先看 A (372 维) 是否已足够解决问题二, B/C 再上。
- 延伸表依赖路网拓扑与车辆路线 (与现有分槽同一假设: 车辆意图可知); 真实部署对应 V2I/GPS 上报或上游检测器, 论文里写明。
- 加权汇总的 log/linear 两种刻度留开关; 若 A 的 Tier 3 翻转率升了但 Tier 2 没改善, 问题在检测范围 (去做 B), 而不是再调刻度。
- 不做: 并路口簇、改车流、改奖励、加头车运动特征 (另有记录, 低优先级)。

需要批准后实施; 实施顺序: 观测类两开关 → 重算工具 → 静态审计/快照对等 → 启动 A/B/C。

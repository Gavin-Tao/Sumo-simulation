# 50 + 50 配对场景 (lanefix 网) 实现计划 第三版 (2026-10-28, 供外部审阅)

第二、三版按两轮外部审阅意见修改, 处理记录见 §12、§12b。

**目标:** 在 18h 定稿所用的 lanefix 网上, 做一个受控测试场景: 背景是 18h 定稿的小汽车车流, 另加 50 辆公交与 50 辆救护车。用它比较不同优先级规格 (如 111 / 531 / 351) 下公交与救护车的待遇, **尽可能把路线、出发时机、沿途竞争程度这些外部因素隔离掉, 只看优先级规格的变化。**

**同时满足用户此前对 18h 提出的要求:** 训练友好 (不锁死、不过饱和、不一开局就压满); 没有与期望方向相反的结构性偏差; 有足够的放行取舍机会体现优先级; 场景本身允许按优先级顺序服务。场景能排除结构性偏向、提供充分的竞争机会, 但软权重奖励不能提前保证每辆车、每个种子都不反转; 最终效果要在冻结后、未参与调参的时刻表上检验。

**范围:** 只产出场景文件、生成与核对工具、标定结果。不启动训练; 训练与评估怎么安排由用户另定。18h 场景 (`nets/dublin/weekday_18h_nocg_claude/`) 与其工具已定稿, 本计划只读取, 不改动 (唯一例外是 `calib18.py` 的知道车型控制器, 见任务 5, 默认行为逐位不变)。不改训练代码。

**做法概述:** 沿用 18h 定稿的车流生成原则与工具 (`experiments/tools/dublin/scenario/claude18h/`): 逐车道连通的路线、写明出发车道、全程不换道、只从白名单入口出发、按入口车道统一排时刻、同一套标定判据与状态/奖励逐步重算。新增的部分是公交与救护车的共用路线、可互换的时刻表, 以及检验可互换性的判据。

**为什么 D5 是必需的:** 观测 (`PriorityMovementObservationFunction`) 把车型查表换成优先级档位后按档位分桶, 奖励 (`make_priority_avg_waiting_reward`) 用同一张表加权 —— 控制器只看到 "5 档、3 档、1 档", 看不到车型。若 262 辆 GTFS 公交仍是公交, 351 下 5 档是 312 辆公交, 531 下 5 档只有 50 辆救护车, 两个规格面对的就不是同一个问题。

**为什么 D9:** 奖励函数里 "车辆 id → 权重" 是闭包缓存 (`rewards.py`, `make_priority_avg_waiting_reward` 的 `vid_w`), 环境重置不清, 只在超过 5 万条时清空。若同一进程里先后跑第 k 份与镜像第 k′ 份 (同 id、换车型), 镜像份的奖励会沿用旧权重。观测的缓存随每集新建的信号对象重建, 评估指标统计器每辆新车现读车型, 两者不受影响。让 id 在所有文件之间唯一, 这个缓存就碰不上; 不需要改训练代码。缓存本身是训练代码里的潜在问题, 另行报告用户, 本计划不改。

## 1. 全局约束 (每个任务都隐含满足; 与 18h 相同的只列条目)

- 路网与 meta 只读, 工具启动时核验 sha256; 18h 场景文件只读, 工具启动时核验背景文件 sha256。
- 三个车型 (car / bus / ambulance) 物理参数逐项相同, 换道参数 lcStrategic / lcCooperative = −1, lcSpeedGain / lcKeepRight = 0: 行驶中不换道。直接复用 18h 的 `vtypes_same.add.xml`。
- 每辆车写明出发车道, 路线在车道图上逐段连通 (`routing.LaneRoutes`)。
- 不在 RL 进口或出口车道上发车; 不重复经过同一 RL 路口; 终点在边界出口边末离网。
- 同一入口车道上所有车辆相邻计划出发间隔 ≥ 3 s。
- sumocfg 与 18h 相同: `time-to-teleport -1`、`ignore-junction-blocker -1`、`collision.check-junctions true`。训练配置须开 `obs_all_connections`。
- 调参 (路线、对内间隔、生成规则) 只用标定时刻表 (第 1–6 份); 第 7–13 份在规则冻结后生成, 不按任何仿真结果筛选。
- 不启动训练; 不改训练代码。

## 2. 核心要求: 公交与救护车可互换

按三类外部因素逐一处理: 能做到逐车完全相同的就做到; 做不到的做到两类之间严格平衡; 剩下的量出来。

| 外部因素 | 措施 | 程度 |
|---|---|---|
| 路线不同 | 两类车共用同一套路线; 每条路线上两类车数量相同; 实测每辆车的实际车道轨迹, 同一路线上的车逐段同车道 (§4.1、P9) | 完全相同 |
| 途中被非 RL 路段卡住的程度不同 | 只从边界入口出发, 全程不经过非 RL 让行连接; 实测两类车在非 RL 车道上的停车 | 两类都接近 0 |
| 出发时机不同 | 对内间隔尽量小 (§5.3); 每条路线对数为偶数、路线内交替先后, 使单份时刻表里每条路线上两类车的先行次数相等、平均出发时刻之差 ≤ 1 s (找空档带来的预定误差); 原份与镜像合并后, 两类车的完整出发时间分布逐位相同 | 单份: 次数相等、均值差 ≤ 1 s; 合并: 逐位相同 |
| 沿途竞争程度不同 | 背景冻结且两类共用; 在中性控制器下检验优先车之间四种相遇的对称性与最低数量 (§5.5) | 中性条件下分布相等, 残差可量 |
| 车型本身影响物理行为 | 三车型参数逐项相同; 镜像一致性测试 (P2) 直接验证 | 完全相同 |

**去不掉的残差与量法:**

| 残差 | 原因 | 怎么量 |
|---|---|---|
| 单辆车遇到的竞争不可能逐一相同 | 两辆车不能同时在同一位置 | 中性控制器下两类车每次访问等待的差距, 用等效检验判定 (P1) |
| 531 与 351 下竞争与排队不同 | 策略不同, 放车时机不同, 下游相遇与排队随之改变 | 属于规格效果的一部分: 记录、作机制分析, 不调平、不从主效果里扣除 |
| 两次训练得到的策略不同 | 训练随机性 | 见 §8: 用同一检查点切换规格, 或多次独立训练 |

**小汽车不在互换范围内:** 它是背景, 所有规格下都是 1 档, 路线、时刻与访问分布都和配对车辆不同。小汽车一侧只作效率代价报告与结构性偏向报告 (P5), 不作为选线或验收的约束。

## 3. 背景车流 (冻结)

- 内容: 18h 的 `background_cars_{060,080,100}.rou.xml` + `bus_tt1_as_car.rou.xml` (262 辆, vType car)。文件逐位复制, 负荷与 18h 定稿完全相同。
- 所有时刻表、镜像、规格共用这一份背景。
- 配对车辆在入口车道上**联合**找合法空档: 先按 §5 抽出发时刻, 再按时间顺序逐辆移到最近的时刻, 使它与同车道所有背景车**以及已安排好的配对车辆**都相距 ≥ 3 s (不同路线可能共用入口车道, 不能让两辆实验车挤进同一个空档); 原份与镜像移动结果相同。报告每辆车的移动秒数 (目标 ≤ 5 s); 移动后重新核对对内间隔与路线内先后平衡。

## 4. 配对路线

### 4.1 候选 (规则同 18h 救护车选线, `ambulances18.score_route` 放宽 RL 数量门槛)

- 从 18h 的路线池 (`build/route_pool.json`) 与按车道图新生成的路线中取候选。
- 只从 15 条边界入口出发; 入口到第一个 RL 路口 ≥ 100 m; 入口车道平台期负荷 ≤ 450 辆/h (18h 救护车规则), 超过的入口只有在实测出发延迟 ≤ 2 s 时才可用。
- 全程不经过非 RL 让行连接 (`yield_links` 为空)。
- 经过 ≥ 3 个 RL 路口, 其中 ≥ 2 个是有竞争的转向 (排除恒绿车道与零需求转向); 尽量走计入指标的车道。
- **车道确定性:** 沿路线逐个节点检查 "本车道到下一条边是否有多条可选的去向车道" (SUMO 在这种分流处自己选车道, 路线文件管不了)。有分流的路线, 只有在实测中所有探针车的车道轨迹都相同时才可用 (§4.2)。

### 4.2 实测 (沿用 `amb_select18.py` 的做法; 只在第 1–6 份标定时刻表的背景上)

每条候选放探针车 (每集 20 辆, 平台期内均匀出发), 用固定轮转与排队驱动各跑 3 个种子, 记录:
- 有放行取舍机会的访问占比 (定义同 PAIRS50 设计 §4, 用固定轮转量);
- 每辆探针车的实际车道轨迹 (逐秒记录所在车道);
- 第 99 分位行程时间 (用于 §5.2 的出发窗);
- 探针车在非 RL 车道上的停车;
- 不分车型控制器下探针车与小汽车每次访问平均等待之差 (只报告, 不作选择依据)。

### 4.3 选择

- 选 K = 10–12 条, 依据只有: 覆盖、机会占比、车道确定性、非 RL 停车。**不依据任何等待结果或优先级排序选线。**
- 贪心覆盖: 优先补上还没被覆盖的 RL 路口竞争转向。目标是每个有竞争的 RL 路口至少被一条路线经过; 覆盖不到的列出原因, 由用户决定是否放宽某条规则。
- 每条入选路线: 机会占比 ≥ 70%; 车道轨迹确定; 探针车在非 RL 车道上的停车 ≈ 0。
- 另选 3 条未见路线 (不与入选路线共享任何 RL 进口边), 只用于评估。

## 5. 时刻表

### 5.1 对数分配
- 50 对分到 K 条路线, **每条路线对数为偶数** (4 或 6), 竞争转向多的路线多分。

### 5.2 出发窗
- 路线 r 的出发窗 = [900 s, 3000 s − 第 99 分位行程时间 − 对内间隔 − 120 s 余量]。
- 这不能保证所有车都在平台期内走完; 实测超出 3000 s 的车与 3600 s 时未完成的车单独报告, 照常计入所有统计, 不删除。

### 5.3 对内间隔
- 候选 60 / 90 / 120 s, 逐路线取使 "同对两辆车同时出现在同一 RL 进口" 的比例 ≤ 10% 的最小值 (中性控制器, 标定时刻表)。间隔越小, 两辆车遇到的背景越接近; 太小则后车搭前车的绿灯。

### 5.4 先后、交错与份数
- 同一路线内各对交替先后 (公交先、救护车先、公交先……), 对数为偶数, 所以单份时刻表里两类车在每条路线上的先行次数相等; 平均出发时刻在找空档前相等, 找空档后允许预定的小误差 (每条路线两类平均出发时刻之差 ≤ 1 s)。原份与镜像合并后, 两类车的完整出发时间分布严格逐位相同。
- 不同路线的对在全局时间轴上交错, 使优先车辆的到达在平台期内大致均匀。
- 份数与用途: 第 1–5 份训练 (目前只用第 1 份), 第 6 份标定, 第 7 份最终测试 (定稿前不跑), 第 8–13 份评估。
- 调参只用第 1–6 份。规则冻结后, 第 7–13 份用预先写定的随机种子 (7007–7013) 一次生成, 不仿真筛选、不重抽; 它们的平衡性事后报告。

### 5.5 优先车相遇的对称性 (只在中性控制器下检验)
- 相遇定义: 一辆优先车到达某 RL 路口时, 冲突方向 (不能与它同一相位放行) 的进口上有另一辆优先车。四种: 救护车遇公交、公交遇救护车、救护车遇救护车、公交遇公交。
- 在排队驱动与固定轮转下统计, **以原份 + 镜像合并后的计数为主** (合并后救护车遇公交与公交遇救护车按构造相等, 用来核对实现); 单份计数作报告。
- 设最低数量: 每类每集有效冲突机会 (对手为任一类优先车) ≥ 20 (起始值), 避免两边都是 0 也算对称。
- 第 1–5 份训练时刻表若单份不对称超过均值的 20%, 换种子重抽 (记录被拒种子数); 第 7–13 份不重抽。
- 531 / 351 等规格运行时的相遇与排队只记录、作机制分析, 不为调平而重新挑时刻表。

### 5.6 车辆 id、镜像与清单
- id 格式 `t{k:02d}{m}_p{NN}_{x|y}`: k = 份号, m 为空 (原份) 或 `m` (镜像), NN = 对号, x = 本对先出发的车。id 不含车型, 车型写在 `type` 属性里。
- 第 k 份的镜像 k′: 所有配对车辆的 `type` 在 bus 与 ambulance 之间对调, 路线、车道、出发时刻全不变, 文件里车辆的排列顺序与原份逐行对应。
- 清单 `pairs_manifest.json`: 每个 id → {份号, 是否镜像, 路线, 对号, 先后位置, 车型}。跨文件比较一律通过清单按 (份号, 路线, 对号, 先后位置) 对应。
- 同一份时刻表在不同规格下逐位相同 —— 这是逐车跨规格比较的前提。

## 7. 标定判据

**一、继承 18h 的硬判据** (定义与工具见 18h 计划 §5 与 `calib18.py`): 排队驱动与固定轮转各 5 种子, C1 在网增长 ≤ 10%、C3 堵死 0、C4 漏放 0、C6 回溢 0、C7 长进口越界 0、C9 换道/碰撞/瞬移/统计器缺条目 0 且配对车辆全部插入、C13、C14; 随机策略 5 种子作压力测试; 中段插车审查 (C17); 68 条 RL 进口车道三档都有车。只用标定时刻表。

**二、配对专项**

| 编号 | 项目 | 怎么量 | 要求 | 性质 |
|---|---|---|---|---|
| P1 | 可互换性 | 排队驱动与固定轮转分别算, 第 1 份 (单份, 不合并镜像)。同一集里的车互相排队、共同影响信号, 不是独立样本, **独立单位是整集运行**: 每个种子先算 "公交类均值 − 救护车类均值" (类均值 = 该类车辆的每次访问平均等待, 车道口径, 剔除恒绿车道, 同 wandb), 再对这些逐种子差值求 90% 置信区间 (t 分布)。种子数按预跑的方差定, 使区间半宽 ≤ 0.3 s (预计 30–50 种子, 单集约 12 s) | 预先定的等效界 ±0.5 s: 置信区间整个落在界内 (等效检验); 逐路线只报告 | 硬 |
| P2 | 镜像一致性 | 同一种子: (a) 固定轮转与排队驱动, 第 1 份对第 1′ 份; (b) 知道车型的控制器, 531 + 第 1 份对 351 + 第 1′ 份; (c) 111 + 第 1 份对 111 + 第 1′ 份。按清单逐车比较出发、到达、各路口等待、车道轨迹 | 逐位相同 (证明车型标签不影响物理行为, 且控制器只依据数值档位) | 硬 |
| P3 | 优先车相遇 | §5.5 | 合并计数相等; 每类每集有效冲突机会 ≥ 20 | 硬 |
| P4 | 有放行取舍机会 | 固定轮转, 第 1–6 份 × 5 种子 | 每条路线 ≥ 70%; 每类每集有机会的访问 ≥ 120 (起始值, 选线后再定) | 硬 |
| P5 | 优先车对小汽车 | 排队驱动 5 种子: 配对车辆与小汽车每次访问平均等待之差 (中性基准); 各规格下小汽车的效率代价留到评估 | 只报告方向与大小; 若优先车结构性地比小汽车多等 > 1 s, 报给用户决定 | 报告 |
| P6 | 优先服务能力 (启发式参照) | 知道车型的控制器 (所有判断都依据规格表的数值档位, 包括抢先切灯), 531 / 351 / 111 各 5 种子 | 531 下救护车 < 公交 < 小汽车、351 下公交 < 救护车 < 小汽车 (五种子平均); 报告每个种子。这只说明场景允许优先服务, 不代表 DQN 一定做到; 不满足时查路口结构原因, 不为通过而换路线 | 能力检查 |
| P7 | 同对共现 | 同对两辆车同时在同一 RL 进口的比例 (中性控制器) | ≤ 10% | 硬 |
| P8 | 非 RL 路段 | 两类车在非 RL 车道上的停车 (车·秒/集) | 两类都接近 0 且相差不大 | 硬 |
| P9 | 车道轨迹 | 每辆配对车逐秒所在车道; 同一路线的车逐段比较 | 同一路线上所有车的车道序列相同 | 硬 |
| P10 | 超窗与截尾 | 3000 s 后仍在网的配对车辆; 排空到 4500 s 仍未完成的配对车辆 (截尾) | 中性控制器下截尾 = 0; 其余报告数量与所属路线。截尾口径: 保留该运行; 没到达的路口不补零; 不只比较已完成车辆; 逐车路线总等待只对完成的车计算, 并同时报告截尾数; 截尾在两类或两规格间不相等时作敏感性分析 | 截尾 = 0 为硬, 其余报告 |

**三、状态与奖励逐步独立重算:** 复用 `validate18.py` 的做法, 固定轮转与随机策略各 1 种子, 状态、奖励、统计器全部一致。另加: 第 1 份与第 1′ 份各起新进程, 在配对车辆出现的决策步, 核对状态里该车所在档位与奖励里它的权重都等于规格表里它的车型对应值 (`test_priority_levels_follow_type`)。

**不达标时:** P1/P3/P7 先调对内间隔、重抽训练时刻表种子; P4/P9 换路线或调各路线对数; 硬判据不过时才动背景 (按 18h 的迭代规则下调车道容量系数, 逐条记录为偏离; 背景一旦改动, 即不再与 18h 逐位相同, 须在 README 写明)。

## 8. 评估设计建议 (训练后用; 本计划只准备文件)

三种比较, 各自说明不同的问题:

| 比较 | 能说明什么 |
|---|---|
| 中性控制器: 原份对镜像, 按清单逐车轨迹一致 | 车型标签没有改变物理行为 (标定阶段 P2 已做) |
| **同一份时刻表、车型不变, 只换 531 / 351** | **优先级改变是否改善了对应车辆的待遇 —— 主证据** |
| 531 + 原份, 对比 351 + 镜像 | 车型与优先级同时互换后的对称性 (每辆车的数值档位其实没变; 一个完全忽略优先级的策略也能通过, 只作对称性核对) |

- **主证据:** 同一批救护车在 531 下是否比在 351 下等待更少; 同一批公交在 351 下是否比在 531 下等待更少。原份与镜像都做, 再合并。111 作空白对照。
- **两种做法:**
  - 用同一个检查点切换规格 (展示不重训的优先级适应能力): 每次切换都必须新建环境、观测与奖励函数, 规格表随之更换;
  - 每个规格分别训练: 还要考虑训练随机性, 需要多次独立训练才能把规格效果与训练差异分开, 评估集数再多也替代不了。
- 所有规格用同一批评估时刻表 (第 8–13 份及其镜像) 与同一批评估种子 (未见种子)。
- 辅助: 换车型孪生 (优先车对小汽车); 未见路线 (泛化); 按到达时冲突方向排队数分层 (机制分析)。
- 每臂评估集数 ≥ 30。跨时刻表评估时保留整集的配对关系 (同一份时刻表、同一评估种子在各规格下各跑一集, 以整集为单位比较), 不把不同集的车辆混成独立样本。
- 评估也按 D6 排空到共同上限, 截尾口径同 P10。

## 9. 审阅重点 (最可能出问题、各任务自带测试未必覆盖的情形)

1. 规则互相冲突导致路线太少: "边界入口 + 入口负荷 ≤ 450 + 无让行连接 + ≥ 3 个 RL + 车道确定" 可能只剩少数候选, 覆盖不到部分路口。处理: 报告覆盖缺口, 由用户决定放宽哪一条, 不自行放宽。
2. 对内间隔取小时, 后车搭前车绿灯, "先行" 与 "后行" 的待遇系统性不同; 路线内交替能抵消均值, 但会放大方差。P7 与按先后分层的报告兜底。
3. 配对车辆找空档时移动过多, 破坏对内间隔或路线内平衡; 移动量要报告, 移动后重新核对。
4. 镜像一致性可能因 SUMO 内部按车辆插入顺序分配随机数而失败: 镜像文件逐行对应、插入顺序不变, 理论上逐位相同; 若不同, 说明车型影响了物理行为或控制器用了车型, 要先查清再继续。
5. 配对车辆在非 RL 的优先路口 (非让行) 也可能被横向车流间接拖慢; P8 兜底。
6. 知道车型的控制器若仍有任何按车型名字的判断 (例如只给救护车抢先), 351 与 111 的检查就失效; P2 (b)(c) 兜底。它是启发式参照, 结果不代表 DQN。
7. 奖励缓存: 靠 id 唯一规避; 评估工具若在同一进程里切换规格, 必须新建奖励函数。

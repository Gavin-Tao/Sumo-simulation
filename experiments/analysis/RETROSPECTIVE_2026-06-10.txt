  1.1 新发现 A: 容量是倒挂的放大器 (exp148-150)
─────────────────────────────────────────────────────────────────────────────
  hd 128→256:
    521: amb 1.58→2.67 (+69%), bus 5.43→4.87
    531: amb 2.24→2.68,        bus 4.05→2.61 (-36%)  ← amb≈bus, 濒临倒挂
    541: amb 3.25→3.83 (+18%), bus 2.34→2.29, all 24.7→21.9 (最优!)
  解读: 更大网络更彻底地優化 weighted 目标 → bus/all 更好, amb 被更精确地
  "正确牺牲"。与 (a) vanilla 不倒挂/协同方法倒挂、(b) CoLight bus 2.35 倒挂
  最深, 构成三重证据: **倒挂随优化能力增强而加深, 是 reward 公式的忠实执行,
  不是欠拟合**。THESIS 关键句: priority inversion is not a failure to optimize
  — it is what optimizing this reward looks like.

─────────────────────────────────────────────────────────────────────────────
  1.2 新发现 B: 6-4-1 无效 (exp157) — 修正"加权重就行"的直觉
─────────────────────────────────────────────────────────────────────────────
  margin 算术: 641 的 6−(4+1)=+1 与 531 的 5−(3+1)=+1 相同。
  但 641 amb=3.25 (与 541 持平), 531 amb=2.24。
  → margin 相同, 结局不同 → margin 不是充分统计量;
    w_bus=4 本身带来的 bus 拟合压力 (梯度平衡点偏移) 是独立的恶化因子。
  → 进一步支持双因子模型 (margin × fit-noise), 且说明只动分子没用,
    必须同时打分母 (分层采样 / obs 加 waiting / 门控协同)。

  1.3 新发现 C: PER 的三面性 (exp153 raw vs MAD)
─────────────────────────────────────────────────────────────────────────────
                     raw last20        MAD-filtered     median   max
  exp147 (无PER)     3.13±1.66         3.25±1.55        3.33     5.83
  exp153 (+PER)      7.96±26.92        2.55±1.97        1.25     125.0
  PER 把 amb 的典型表现做得更好 (median 1.25!), 与 buffer 实测一致
  (PER 放大 amb 采样 1.79×); 但偶发 125s 灾难 + car/all 全面变差。
  → PER 不是"没用", 是"不稳定的偏科生"。safety-critical 场景不可接受
    尾部, 但它证明了"提高 amb 采样占比方向正确" → 分层采样 (uniform
    within class) 是保留其好处、去掉其尾部的对症替代。

  1.4 新发现 D: +Double 两次崩盘 (exp156, exp160)
─────────────────────────────────────────────────────────────────────────────
  exp156 (Coeff+PER+D): all 38.1;  exp160 (CoLight+PER+D): all 55.1, bus 13.4。

─────────────────────────────────────────────────────────────────────────────
  1.5 与无协同 baseline 的逐 weight 对比 — 倒挂的真实成因再精确化
─────────────────────────────────────────────────────────────────────────────
  协同相对 vanilla 的改善幅度 (MAD last-20, 越负越好):

              amb 改善                bus 改善                all 改善
  weight   CoLight   Coeff        CoLight   Coeff         CoLight  Coeff
  521      -16%      -46%         -43%      -31%          -6%      -11%
  531       +1%      -24%         -40%      -33%          -15%     -16%
  541       +7%      -24%         -54%      -54%          -14%     -13%

  三个关键读数:
  (a) CoeffDQN 的 amb 在每个 weight 都比 vanilla 好 (-46%/-24%/-24%)
      → 协同(concat state)本身对 amb 是【有帮助的】, 不是伤害。
  (b) 但协同对 bus 的帮助不成比例地大 (541 时 -54% vs amb 的 -24%)
      → 倒挂的精确成因 = 协同对高频类的改善远大于稀有类, 排序被翻转,
        而不是"协同让 amb 变差"。vanilla 自己 541 时 amb 也退化到 4.25
        (weight 效应打击所有方法), 只是它 bus 同样烂 (5.13) 才没倒挂。
  (c) CoLight 的 amb 改善随 weight 消失 (-16%→+1%→+7%):
      纯 state-layer 协同在高 bus 权重下对 amb 零贡献甚至负贡献;
      CoeffDQN 的 concat (含邻居 obs 直接进 Q) 始终保有 -24%。
      → state 协同的"信息红利"被 bus 优化压力吃掉的速度, GAT 聚合比
        concat 更快 (GAT 把邻居信息加权平均后, 稀有 amb 信号更容易被抹)。
  (d) all 指标: 两种协同在所有 weight 都比 vanilla 好 ~6-16% →
      协同的整体收益真实存在, thesis 不需要否定协同, 需要修复它的分配。
  ⚠ 注意: 这些 % 基于单 seed + seed-123 记忆协议 (2.1), 数值仅供方向参考;
     541 的 amb 差异在 Mann-Whitney 下不显著 (raw: p=0.74), bus 显著 (p<0.001)。

─────────────────────────────────────────────────────────────────────────────
  1.6 新发现 E: 1x1 无倒挂 (exp168-170)
─────────────────────────────────────────────────────────────────────────────
  单路口下三个 weight amb 全部 << bus。结合 1x3 的倒挂震中在 t 路口
  (amb 相位 vs bus 相位零和) → 倒挂需要 (a) 高 bus 权重 + (b) 相位结构上
  amb/bus 零和 + (c) 足够的优化能力, 三者缺一不可。
  ⚠ 场景不同 (NSamb vs NS20bus_U), 跨比仅作方向参考。


─────────────────────────────────────────────────────────────────────────────
  1.7 假设检验: "541 倒挂是不是 amb 生成时机/多 amb 稀释造成的?" → 否决
─────────────────────────────────────────────────────────────────────────────
  实测 (exp147 greedy policy, 每 seed 1 ep, 记录 amb 生成与同时在场):

  seed   n_amb  depart时刻    max同时在网  某TS同时>=2amb的步数  同时在网秒数
    0      1    [620]             1              0                  0
  123      2    [375, 725]        1              0                  0   ← 训练+eval
  124      0    []                0              0                  0
  125      2    [705, 720]        2              5                 70   ← 唯一稀释案例
  126-130  0-2  各异              ≤1             0                  0

  否决理由 (三条):
  (a) exp145/146/147 共用同一 route 文件 + 同一 seed → amb 生成模式在三个
      weight 下完全相同, 无论时机如何都无法解释 weight 轴上的差异。
  (b) seed 123 (所有主结果的实际场景): 2 辆 amb, 相隔 350s, 从未同时在网,
      从未在同一路口同时出现 → reward 的 avg_amb 永远只平均 1 辆,
      稀释事件数 = 0。(这也再次解释了 exp167 ambmax ≡ exp147。)
  (c) eval 指标本身是 per-vehicle per-visit 口径, 即使两辆同时在场也不会
      像 reward 那样瞬时平均稀释。

  但顺带发现更值得警惕的事实:
  ★ 整个 541 倒挂结论建立在 seed 123 的【两辆固定时刻 (t=375, t=725) 的
    救护车】被重放 2000 遍之上 —— n=2 个固定事件。这比"稀释"更根本地
    说明为什么 P-1 (multi-seed 协议) 必须先做: amb 事件样本量按 seed 算
    只有 2, 按事件类型算 t=375 (中段) 和 t=725 (尾段) 各 1 个。
  ★ seed 125 证明双 amb 同时在场在其它 seed 下确实会发生 (70s 重叠,
    5 个 TS 步双 amb) → v2 协议的 eval seed 集要么记录 n_amb 分别统计,
    要么在 metric 层 per-vehicle 口径已天然免疫 (现状 OK), reward 层
    的稀释在 multi-seed 训练时会成为真实噪声源 (单 amb 场景设计的
    avg≡max 性质失效), 届时 wait² 类非线性惩罚的价值上升。

─────────────────────────────────────────────────────────────────────────────
  2.1 ★★★ eval seed 污染训练 — 训练集 == 测试集
─────────────────────────────────────────────────────────────────────────────

  机制 (4 个脚本同构: train.py / traincolight.py / trainorico.py / traincoeff.py):

    构造:        sumo_seed = cfg["seed"] = 0
    训练 ep N:   env.reset(env.sumo_seed)          ← 读当前 sumo_seed
    eval (ep5):  env.reset(int(eval_seed))         ← reset(123)
                 env.py L282: if seed is not None: self.sumo_seed = seed
                 → env.sumo_seed 被永久改写为 123
    训练 ep6+:   env.reset(env.sumo_seed) = reset(123)   ← 从此训练在 eval seed 上!

  时间线: ep1-5 训练 seed 0 → ep5 末 eval seed 123 → ep6-2000 训练 seed 123
          且每个 episode 的交通需求 (含 amb 出现时刻) 完全相同。

  影响:
   (a) 所有 eval 指标 = 在"训练了 1995 遍的同一个场景"上的表现 → 记忆不是泛化。
   (b) "每 ep 随机交通"的假设不成立: 训练数据多样性 = 1 个需求实现 + ε 探索。
   (c) 同协议下方法间相对比较仍内部公平 (所有 exp 同样被污染), 倒挂结论的
       内部效度保留; 外部效度 (对新需求模式) 全部未经检验。
   (d) 旁证: 行为探针在 seed 124-130 (训练从未见过) 上复测, exp145 在 t 仍
       93% 选 amb 相位、exp147 仍 71% → 核心结论在未见 seed 上方向成立,
       但量化数字 (1.58/3.25 等) 都只属于 seed 123。
   (e) 此问题同样适用于 5 月的 exp135/137 (同款脚本结构)。

  建议修法 (不改代码, 仅记录):
    - 训练 reset 改为 env.reset(int(base_seed + episode)) 之类的逐 ep 变 seed;
    - eval 用独立 held-out seed 集 (如 9000-9009 取均值), 与训练 seed 域不重叠;
    - 或最小改动: eval 后手动恢复 env.sumo_seed = train_seed。
    任何修法都会让新旧实验不可比 → 作为新 protocol 版本号管理 (v2),
    P0 实验 (exp172+) 应在 v2 协议下跑, 否则继续生产"记忆指标"。

  2.2 ★★★ 绘图管线 amb=0.0 丢弃偏差 (plot_wandb_3way_sweep_w20.py)
─────────────────────────────────────────────────────────────────────────────

  collect_stats(): if vtype == "ambulance": series = [v for v in series if v != 0.0]
  本意: 丢掉"无 amb"的 eval。
  实际: eval seed 固定 → amb 必然在场 → 0.0 只能是"amb 全程一次没停" = 完美 run。

  实测丢弃率 (最后 40 个 eval):
    exp145 (5-2-1): 15/40 被丢 (全程 26%)   ← 最好的方法被丢最多
    exp147 (5-4-1):  2/40 被丢 (全程 11%)

  后果: 图上 amb 数字系统性偏差 (向坏), 且偏差与方法好坏正相关 →
    5-2-1 的真实 amb 远好于图示 1.58 (38% 的近期 eval 是完美 0);
    weight 轴的退化斜率被低估; 方法间 amb 差距被压缩 (可能掩盖了显著性)。

  建议修法: eval 时记录 n_amb_present (metrics.py 已有 n_vehicles 口径),
    只丢 n_amb==0 的 eval; 或 seed 固定时直接不丢 0。
    旧图需要用修正口径重生成后再进 thesis。

─────────────────────────────────────────────────────────────────────────────
  2.3 ★ eval 方差来源的正确解读
─────────────────────────────────────────────────────────────────────────────
  greedy policy (ε=0) + 固定 seed → 单次 eval 完全确定。
  因此 last-20-eval 的 ±std 不是"交通随机性", 而是 **checkpoint 间 policy
  漂移** (训练仍在进行, 每 5 ep policy 变一次)。
  → "±1.55" 应解读为训练不稳定性指标; 真正的交通方差需要 multi-seed eval。
  → exp147 与 exp167 逐点相同的 eval 序列由此完全解释 (同 policy 同 seed)。

  ✓ PER 实现: sum-tree 正确, IS weight (N·P)^-β/max 归一, priority 更新

  ✓ waiting_time_memory=1000 = 全 episode, 无饱和。

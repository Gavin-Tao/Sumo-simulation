║   Part 0: TL;DR — 三层方案 + 一句话判决                                      ║
╚══════════════════════════════════════════════════════════════════════════════╝

  按"保证强度"分三层。保证强度 = 在什么意义下 amb<bus 成立。

  层   方案                       保证强度              改什么       泛化性
  ──   ────────────────────────   ──────────────────    ─────────    ──────
  G1   Lexicographic 动作屏蔽     HARD (每步, 可证)     动作选择     ★★★★★
  G2   CMDP / Lagrangian 约束     SOFT (期望, 渐近)     reward+对偶  ★★★★☆
  G3   Reward 模式切换            STRONG-ish (非保证)   reward       ★★★☆☆
  ──   ────────────────────────   ──────────────────    ─────────    ──────
  H1   Stratified Replay          HELP (无保证)         采样         ★★★★★
  H2   Per-class reward 归一化     HELP (无保证)         reward       ★★★★☆
  ──   ────────────────────────   ──────────────────    ─────────    ──────
  Y1   DWL 多头 + Lexicographic   HARD + 高效率         架构+动作    ★★★★☆
       仲裁 (混合, ⭐thesis 卖点)

  一句话判决:
    • 只要"保证 amb<bus" → G1 (最干净, 不碰 reward, 任意 weight/场景都成立)
    • 想要"原理优雅 + 单旋钮可调" → G2 (T 直接是 amb 目标上界)
    • 想要"既保证又不牺牲 bus 效率 + 有架构创新" → Y1 (DWL 三头给稀疏 amb
      一个专属 Q, lexicographic 在其上加排序保证)
    • 不想动结构, 只想缩小差距 → H1 (已是 exp172 计划, 实测梯度占比 0.5%→25%)

  G 与 H 的根本区别 (这是 thesis 的核心论点):
    G 改"优化问题本身"(把排序编进约束/动作空间) → 与 reward 权重解耦, 保证成立
    H 改"优化能力"(让网络把 amb 学准) → 缩小 fit-noise, 但 Pareto 前沿仍含倒挂点
    → G 回答"要不要倒挂", H 回答"能不能学准"。两者正交, 可叠加。

  ── 1.3 形式化: 为什么 w_amb=5>w_bus=4 不蕴含 amb<bus ─────────────────────────

  加权求和最优解满足"边际交换率"= 权重比, 不是"结局排序"= 权重序:
      在最优点, ∂(总delay)/∂g 处处相等 →  w_amb·|∂d_amb/∂g| = w_bus·|∂d_bus/∂g|
  这只约束"再挪一点绿灯时间, 两边加权边际损益相等", 完全不约束 d_amb 与 d_bus
  的绝对大小。当 bus 的边际曲线陡 (高频, 改善空间大), 最优点可以落在 d_amb>d_bus
  且仍满足边际相等的位置 —— 这就是 Pareto 前沿上的合法倒挂点。
  → 任何"加权求和 + 调权重/归一化"都在这条前沿上移动, 进不了"排序保证"区。
    要保证排序, 必须改优化问题的可行域 (G1 改动作空间, G2 加约束)。

║   Part 2: GUARANTEE 层 — 结构上保证 amb < bus                               ║
╚══════════════════════════════════════════════════════════════════════════════╝

─────────────────────────────────────────────────────────────────────────────
  G1  Lexicographic 动作屏蔽 (action masking)   ★ 最干净的硬保证
─────────────────────────────────────────────────────────────────────────────

  机制:
    在动作选择时, 若本路口 incoming lane 有 amb 在场且在等待 → 把 argmax 的
    可行动作集限制为"给该 amb 所在 lane 放绿"的相位。amb 不在场 → 不限制,
    退化回原 Q 策略。
        a* = argmax_{a ∈ A_amb(s)} Q(s,a)    若 amb 在场且 halt
             argmax_{a ∈ A}       Q(s,a)    否则
    A_amb(s) = {能让 amb 所在进口道获得通行权的相位}

  为什么是 HARD 保证:
    amb 一旦在某进口道等待, 下一个决策步它所在相位必被选 (或被强制最快轮到)。
    在"amb 出现就放行"的策略下, amb 的等待上界 = 决策粒度 + 当前相位剩余 +
    min_green 一档, 与 bus 完全脱钩。只要 bus 流量使其平均等待 > 这个上界,
    amb<bus 恒成立, 且与 (w_amb,w_bus,w_car) 取值无关。

  代码注入点 (单点, ~15 行, 不碰 reward / 不碰训练):
    • 动作选择: sumo_rl/agents/coefficient/dqn_coeff.py:118  take_action()
        现状: return self.q_net(state_t).argmax().item()
        改为: 先算 mask, q[~mask] = -inf, 再 argmax
    • amb 在场判定 (两条现成途径, 任选):
        (i) 从 obs 读: PriorityBCAObservationFunction (observations.py:230) 的
            观测向量已含每 lane 的 inc_amb 计数 → 直接切片判 >0
        (ii) 从 SUMO 读: getTypeID(vid)=="ambulance" (traffic_signal.py:349
             已有 car/bus 同款写法, 照抄即可)
    • A_amb(s) 映射 (唯一非平凡处): "amb 所在 lane → 放它绿的相位 index"。
      需要 lane→phase 的静态映射, 从 net 的相位定义一次性建表。1x3 三个路口
      各建一张即可。

  优点:
    • 真·保证, 可在 thesis 里写成命题 + 证明 (上界推导)
    • 与 reward / weight 完全解耦 → priority 值 1~5 任意、车流比例任意都成立
    • 不增加任何训练难度 (Q 网络照常学, 只在推理时套约束)
    • 给出天然的"oracle 上界": 它是"无条件优先 amb"的性能天花板
  缺点:
    • 可能过度服务 amb (1 辆 amb 也打断 50 辆 bus); 但单 amb 场景代价小
    • 需要 lane→phase 映射 (工程量小但要对每个 net 配)
    • 是"硬切换"不是"学出来的", 会被审稿人问"那还要 RL 干嘛"
      → 反驳: RL 仍负责 amb 不在场时 (99% 时间) 的 bus/car 效率; G1 只在
        稀有的 amb 事件上加一道安全约束 (= shielding / safe-RL 范式, 有文献背书)

  泛化性: ★★★★★  完全 generic。换流量/比例/priority 值/拓扑都不重写逻辑,
          只重建 lane→phase 表 (每个 net 一次)。

  [推测] 量化预测 (打因果链最后一环, 直接钉死"amb 在场选 amb 相位 @ t"):
    • amb 相位被选率 @ t: 71% → ~100% (定义上)
    • amb per-visit: 3.13 → 趋近 521 水平 (~1.0~1.5), 因为等待上界 ≈ min_green
      + 半个相位 ≈ 1 个决策粒度, 与 weight 无关
    • bus 代价: 会从 2.34 回升 (失去"挤占 amb 相位"换来的 bus 优化)。
      估计 bus → ~2.6~3.2 (介于 CoLight 倒挂态 2.34 与 vanilla 5.13 之间,
      因为只在 amb 在场的少数 step 让出绿灯)。 ⚠ 这是基于 t 路口 amb 相位
      +4.16 震中量级的粗估, 待实测。
    • all (car): 轻微上升, 因 amb 中断打散绿波; 估计 +1~3s。

  如何帮助 thesis 分析:
    G1 是"代价基线 / oracle"。它回答:"如果无条件保证 amb 最优, bus/car 要付
    多少代价?" 这条线一画, 所有 HELP 类方法 (H1/H2) 的"性价比"就有了参照系:
    一个方法离 G1 的 amb 越近、离 G1 的 bus 代价越远, 越好。它还把"倒挂是结构
    问题还是优化问题"做成可证伪实验 (见 Part 6)。

─────────────────────────────────────────────────────────────────────────────
  G2  CMDP / Lagrangian 约束 (constrained MDP)   ★ 单旋钮 + 原理优雅
─────────────────────────────────────────────────────────────────────────────

  机制:
    把 amb 从"目标项"改成"约束":
        min  E[ w_bus·bus_wait + w_car·car_wait ]
        s.t. E[ amb_wait ] ≤ T
    Lagrangian 松弛 → 训练时 reward:
        R = −(w_bus·bus + w_car·car) − λ·max(0, amb_wait − T)
    λ 用对偶上升自动更新: 约束被违反 (amb_wait>T) → λ↑; 满足 → λ↓。
    λ 自己长到"恰好让约束绑定"的值, 不需要手调 amb 权重。

  保证强度: SOFT (期望意义、渐近)。收敛后 E[amb_wait]≤T; 只要 T < E[bus_wait]
    就 amb<bus。但不是每集/每步保证 (λ 动态有滞后)。

  代码注入点:
    • reward: rewards.py 加一支 _make_cmdp_reward(w_bus,w_car,T,λ_ref); amb 项
      改成 hinge −λ·max(0, amb_wait−T) (现有 _make_avg_waiting_bc (rewards.py:407)
      是同款 factory 结构, 照搬)
    • λ 更新: traincoeff.py 训练循环里, 每集后 λ ← clip(λ + η·(amb_wait−T), 0, λ_max)
      (λ 是标量, 存在 trainer 里, 喂给 reward factory)

  优点:
    • T 是直接、可解释的 amb 目标 (e.g. T=2s "救护车平均等待不超 2 秒")
    • λ 自调 → 免去 5-2-1/5-3-1/5-4-1 这种权重网格搜索
    • 原理对口 (safe-RL / CMDP 主线文献), 好写好引
  缺点:
    • 仍受稀疏信号拖累: 约束项 99% step 为 0 (amb 不在场), λ 的梯度也稀疏
      → 建议与 H1 (stratified replay) 叠加才稳
    • λ 动态可能震荡 (滞后), 要调 η、λ_max
    • 软保证: 极端流量尖峰时单集可能短暂违反

  泛化性: ★★★★☆  generic, 但 T 要随场景设 (不同流量下"合理的 amb 等待"不同)。
          可把 T 设成相对量 (e.g. T = 0.5×当前 bus_wait) 恢复全自适应。

  [推测] 量化预测:
    • 终态类似 G1 但更"温和": amb 收敛到 ≈T, bus 代价比 G1 小 (G1 是硬中断,
      G2 允许在约束内权衡)。若 T=2.0, 估计 amb→~2.0, bus→~2.5~2.8。
    • λ 轨迹本身是好图: 看它在 521/531/541 下分别稳定到多大, 量化"维持排序
      需要多大的约束压力" —— 比"扫权重"更干净的一条 sensitivity 曲线。

  如何帮助 thesis 分析:
    G2 把"优先级"从模糊的权重比变成一个有物理意义的旋钮 T 和一条可观测的
    对偶变量 λ(t)。论文里可以画"T vs (amb_wait, bus_cost)"的 trade-off 前沿,
    这正是审稿人想看的"你的方法怎么 generic 地控制优先级强度"。

─────────────────────────────────────────────────────────────────────────────
  G3  Reward 模式切换 (event-gated objective swap)   △ 你之前说"不太好", 列作参照
─────────────────────────────────────────────────────────────────────────────

  机制: amb 在网络内时 R=−w_amb·amb_wait (只剩 amb 项); 否则 R=−(bus+car)。
        amb 在场期间 amb 成为唯一目标 → 强力下压 amb_wait。

  保证强度: STRONG-ish 但非保证。amb 模式太稀 (1.9% step) 时, Q 仍主要由
    bus/car 模式塑形, 切换瞬间的 Q 可能没学好。比 G1/G2 弱。

  代码注入点: rewards.py 包一层 gate(读 amb 计数, 同 G1 的判定); 无新参数。

  注意 (与既有 doc 的关系 + 你的反馈):
    • 你在前序讨论里把 event-gating / MAX / 抢占判为"不太好" → 故此项不推荐,
      仅作完整性列出。
    • REWARD_STATE_AUDIT Part 2.4 选定的"event-gated additive COORDINATION"
      与本项不同: 那个 gate 的是"邻居 reward 协同项", 这个 gate 的是"自己的
      目标函数"。前者是 HELP (给协同注入 amb 信号), 后者想当 GUARANTEE 但其实
      做不到硬保证 → 性价比不如 G1。

  泛化性: ★★★☆☆  generic 但切换边界行为依赖 amb 频率, 稀疏时退化。

  [推测]: amb 改善幅度介于 H1 与 G1 之间; 风险是切换处 Q 不连续导致 bus 抖动。
  如何帮助分析: 作为"软门控 vs 硬屏蔽"的中间档对照, 衬托 G1 硬保证的必要性。

║   Part 3: HELP 层 — 不保证排序, 但缩小差距 (打拟合噪声)                      ║
╚══════════════════════════════════════════════════════════════════════════════╝

  这层不改优化问题, 改"优化能力"。理论上不保证 amb<bus, 但实测因果链显示
  541 倒挂的 binding constraint 是 amb |TD|=0.635 (拟合噪声), 不是 weight。
  把噪声打下去, 有机会让 amb 自然回到 bus 之下 —— 但 Pareto 前沿仍含倒挂点,
  所以是 HELP 不是 GUARANTEE。

─────────────────────────────────────────────────────────────────────────────
  H1  Stratified Replay (amb transition 强制占比)   ★ 已是 exp172, 优先做
─────────────────────────────────────────────────────────────────────────────

  机制: 单独维护 amb-related transition 的 buffer, 每个 batch 强制 amb 占 25%,
        组内 uniform 采样 (不按 TD 优先, 避开 exp153 PER 过拟合 outlier 的坑)。
        直接把 amb 梯度占比从实测 0.5% → ~25% (50× 放大)。

  保证强度: HELP, 无保证。
  代码注入点: sumo_rl/agents/coefficient/replay_buffer.py (加分层采样);
              traincoeff.py 采样调用处。单变量对照 exp147。

  优点: 单变量干净 (只改采样); 不碰 reward/结构; 通用 (任何稀疏-高优先类都适用)。
  缺点: 不保证排序; amb buffer 需要"哪些 transition 算 amb-related"的判定。

  泛化性: ★★★★★  完全 generic, 稀疏关键类的通用补救。

  [推测] 量化预测 (打因果链的 |TD| 环, 然后顺链传导):
    amb 梯度占比 0.5%→25% ⇒ amb |TD| 0.635 → 估 ~0.40 (回到 531 档)
      ⇒ Q-margin/std 0.62 → ~0.9
      ⇒ amb 相位被选率 @ t 71% → ~85%
      ⇒ amb per-visit 3.13 → ~1.7~2.2 (531 档)
    若 bus 维持在 ~2.3, 则 amb~1.7~2.2 有可能 un-invert (落到 bus 之下), 但
    margin 很薄 —— 这正是"HELP 不保证"的体现: 成败取决于具体数字, 不是结构。
    ⚠ 跨指标比较 (per-visit vs avg_stopped) 不可直接相减, 上面只表方向与档位。

  如何帮助分析:
    H1 是"倒挂到底是采样问题吗?"的判决性实验。若 H1 单独就 un-invert →
    倒挂主因是优化/采样, reward 结构没错 (支持你"方法能 work"的目标, 不必上
    CMDP/lexicographic 这种重武器)。若 H1 后仍倒挂 → 必须上 G 层。

─────────────────────────────────────────────────────────────────────────────
  H2  Per-class reward 归一化 (你前序问过的"每项归一化")
─────────────────────────────────────────────────────────────────────────────

  机制: R = −(w_amb·amb/σ_amb + w_bus·bus/σ_bus + w_car·car/σ_car), σ 为各类
        典型尺度。让 amb 项的有效梯度不被 bus/car 的大数值淹没。

  保证强度: HELP, 无保证 (Part 1.3: 归一化只在 Pareto 前沿上移动, 不出排序区)。
  代码注入点: rewards.py 的 _get_weighted_avg_waiting_time (rewards.py:375) 加除 σ。

  优点: 改动极小; 缓解尺度失衡。
  缺点: σ 要估 (可用 running std); 不解决稀疏 (amb 项仍 1.9% 非零); 不保证排序。
  泛化性: ★★★★☆  generic, 但 σ 需在线估计。

  [推测]: 单独用收效有限 (它治"尺度"不治"稀疏", 而实测瓶颈是稀疏导致的 |TD|)。
          预测改善 < H1。价值是与 H1 叠加时让 amb 梯度方向更稳。
  如何帮助分析: 作为"尺度 vs 稀疏"的拆分对照 —— 若 H2 几乎无效而 H1 有效, 就
          实证了"瓶颈是稀疏不是尺度", 进一步坐实因果链。


╔══════════════════════════════════════════════════════════════════════════════╗
║   Part 4: HYBRID — DWL 多头 + Lexicographic 仲裁 (⭐ thesis 卖点)            ║
╚══════════════════════════════════════════════════════════════════════════════╝

  ── 4.1 动机: 为什么单纯 DWL (Dusparic) 仍会倒挂 ──────────────────────────────

  原版 DWL 的 W-value 仲裁目标是 Pareto 最优, 不是优先级排序 (前序讨论结论):
    • W-value 机制让各目标"循环补偿", 收敛到 Pareto 前沿某点
    • Pareto 前沿含倒挂点 (Part 1.3) → DWL 可能停在倒挂点
    • 且 amb 不在场时 r_amb=0=公平份额 → W_amb 不增长, 稀疏使其长期被压制
  → 直接套 DWL 解决不了你的问题。但 DWL 的"每类一个 Q 头"对稀疏信号有价值。

  ── 4.2 设计: 取 DWL 的多头, 换掉它的仲裁 ────────────────────────────────────

  每路口 agent:
      共享编码器 → 三个独立 Q 头  Q_amb / Q_bus / Q_car
      各头用各自的 per-class reward 训练:
          r_amb = −amb_wait/100,  r_bus = −bus_wait/100,  r_car = −car_wait/100
      关键: Q_amb 只吃 amb 的 reward → amb 信号不再被 bus/car 淹没在 0.4% 里,
            而是 Q_amb 头的 100% 训练信号 (这是对"稀疏"的结构性解法)

  仲裁换成 lexicographic (不是 DWL 的 W-value):
      若 amb 在场:  a* = argmax_{a ∈ Top-ε(Q_amb)} [Q_bus(s,a)+Q_car(s,a)]
                    (先锁定对 amb 近似最优的动作集, 再在其中最大化 bus+car)
      否则:        a* = argmax_a [Q_bus(s,a)+Q_car(s,a)]
      Top-ε(Q_amb) = {a : Q_amb(s,a) ≥ max_a Q_amb − ε}

  保证强度: HARD (ε=0 时严格 lexicographic; ε>0 给 bus/car 留优化缝隙)。

  代码注入点:
    • 网络: sumo_rl/agents/coefficient/dqn_coeff.py 把单头 q_net 改三头 (共享
      trunk + 3 个 head)。改动中等 (~1 个 forward + 3 路 TD loss)。
    • 仲裁: take_action() (dqn_coeff.py:118) 实现上面的 Top-ε 两段式 argmax。
    • reward: 需要 per-class 分量 (rewards.py 已能按 type 数, 拆成三路即可)。

  优点 (为什么这是最优组合):
    • 同时解决两个根因: 多头治"稀疏"(Q_amb 专属信号), lexicographic 治"排序"
      (硬保证)。G1 只治排序、H1 只治稀疏, 此项一并拿下。
    • ε 是"优先级软硬度"旋钮: ε=0 绝对优先, ε 大近似加权 → 一个模型覆盖
      从 lexicographic 到 soft-priority 的整条谱 (审稿人爱看的 generic 控制)。
    • Q_bus/Q_car 独立优化, bus 效率不被牺牲 (优于 G1 的硬中断)。
    • 有清晰的架构创新点 (DWL 多头 × lexicographic 仲裁, 填"多目标 RL 做
      优先级排序而非 Pareto"的空白)。
  缺点:
    • 参数 ~3× (三头), 训练更重。
    • 仍建议配 H1 (即便 Q_amb 专属, amb 经验绝对量少, stratified 让它更快收敛)。
    • ε 要调 (但比扫 weight 网格语义清楚)。

  泛化性: ★★★★☆  类数可扩 (priority 1~5 → 5 个头 + 字典序逐级 argmax);
          换流量/比例不改逻辑。代价是头数随类数线性增。

  [推测] 量化预测:
    • amb: 接近 G1 (硬保证), 但因 Q_amb 学得准, 中断更"聪明"(只在真有 amb 时),
      估计 amb per-visit ≈ 1.0~1.5。
    • bus: 优于 G1 (Q_bus 独立优化 + ε 缝隙), 估计 bus ≈ 2.4~2.8 (接近倒挂态
      的 2.34, 但这次 amb 在它之下 → 健康)。
    • 即"amb~1.3 < bus~2.6", 既不倒挂又保住效率 —— 若实测兑现, 这是全 doc
      最强结果。

  如何帮助分析:
    这是把前面所有碎片 (稀疏诊断、Pareto 论证、lexicographic 保证) 收口成
    一个方法的地方。ablation 轴天然清晰:
      单头+lexico (=G1) | 三头+W-value (=DWL) | 三头+lexico (=Y1)
    三格一比, 直接证明"多头(治稀疏)"与"lexico(治排序)"各自的独立贡献 ——
    这正是一篇方法论文的核心 ablation。

╔══════════════════════════════════════════════════════════════════════════════╗
║   Part 7: 选型决策 (按你的目标"方法能 work")                                ║
╚══════════════════════════════════════════════════════════════════════════════╝

  你的目标不是写 thesis 凑公式, 是"方法真能 work、且 generic"。据此:

  推荐主线 (按投入/产出):
    1. 先跑 exp-A (H1 stratified)。 成本最低, 若它就 un-invert, 收工 —— 你
       证明了"协同方法 + 修采样"即可维持优先级, 不必引入重机制。
    2. 若 exp-A 不够 → 主推 Y1 (exp-C)。 它一次性给你: 硬保证 (审稿无懈可击) +
       bus 效率不塌 (G1 做不到) + 架构创新点 (DWL×lexico) + 一个 ε 旋钮覆盖
       soft→hard 全谱 (generic 卖点)。
    3. G1 (exp-B) 始终要做, 但定位是"上界对照 / 安全网", 不是主推。
    4. G2 (CMDP) 作为"原理优雅"的备选叙事, 若想要"单旋钮 T 控优先级强度"
       的卖点再上; 否则 Y1 的 ε 已覆盖类似功能。

  generic 检验 (你反复强调的点) —— 各方案在四个维度的稳健性:
    维度              G1     G2     H1     Y1
    换车流量          稳     需调T  稳     稳
    换车流比例        稳     稳     稳     稳
    换 priority 值1-5 稳     稳     稳     稳(加头)
    换拓扑(grid)      重建表 稳     稳     稳
    → G1/Y1 最 generic; G2 的 T 是唯一需要随场景设的量 (可改相对量自适应)。

  一句话收尾:
    "保证"只能来自改优化问题本身 (G1 动作空间 / G2 约束 / Y1 lexico 仲裁);
    "调权重、归一化、换协同结构"都只在 Pareto 前沿上挪动, 进不了排序保证区。
    最优解 = Y1 (多头治稀疏 + lexico 治排序), 退路 = G1 (硬保证) 或 H1 (够用就行)。

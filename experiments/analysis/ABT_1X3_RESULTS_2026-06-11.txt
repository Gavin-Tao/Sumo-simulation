╔══════════════════════════════════════════════════════════════════════════════╗
║   Part 0: TL;DR                                                              ║
╚══════════════════════════════════════════════════════════════════════════════╝

  1. **工作了吗? —— 4/5 臂工作, 效率排序干净且统计可靠**:
     10 个未见 seed 上 car 等待 (std 仅 1-2s):
       coeff(187) 37.9 < T-nocoord(185) 44.2 ≈ B-nocoord(184) 44.6
       < Tnb(188) 49.6 << colightorig(186) 99.2 (训练退化, 见 3)
     → 协同有真实价值: coeff 比 nocoord 省 15% car 等待;
     → B ≈ T 在 1x3 完全打平 (与 1x1 一致), generic 文档"零改动上
       1x3"的主张被完整兑现 ✓。

  2. **最大发现是协议问题, 不是算法问题: 救护车统计欠功效**。
     1amb_U 是 Poisson 流 (≈1.1 辆/episode, 有的 episode 为 0)。
     同一臂的 amb 均值在不同 ckpt/种子批间大幅摆动 (187: best ckpt
     11.3±9.8 vs final ckpt 2.4±4.8; 184: 7.8±9.6 vs 3.2±3.9), std≈均值。
     → 训练中单次 eval 看到的 "Tnb amb=0.0s" / "coeff amb 反转 (13.5 >
       bus 2.5)" **都是噪声实现, 不可入论文**。
     → 在补足统计前, 关于 5-4-1 排序在协同下是否保持的问题 **悬而未决**
       —— 这是本批实验设计的缺口 (修法见 Part 4 B1, 不用重训)。

  3. **colightorig+B 训练退化 (可修, 非"协同有害")**: best 停在 ep145
     后单调恶化 (末期 speed 0.94 vs best 2.25), 三路口均匀变差 (非局部
     协同 bug)。证据链: 与 5 月跑通的 exp135 **超参逐项相同, 唯一差异
     是 obs 从 PriorityBCA(33 维) 换成 B(125 维)** → GAT 在高维输入下
     同 lr 失稳; 与 1x1 的 R2 证据同构 (有 clip 的 T 臂活, 无 clip 的
     179 Q 发散)。trainorico.py 无梯度裁剪。修法: clip 1.0 + lr 3e-4
     (+ 可选 obs LayerNorm), 重跑一臂即可判。

  4. **与 5 月老基线对比 (方向性更强的胜利)**: 老 1x3 基线 (exp137
     vanilla −33.0 / exp135 colight −25.0) 是 watershed 前的数字 ——
     当时 eval seed=训练 seed, 系统性高估。新臂在干净评估下仍然:
     B-nocoord(−29.3) 优于老 vanilla, coeff(−22.5) 优于老 colight。

  5. **对 Dublin 的选型回答** (1x1 文档遗留问题):
     主力 = **B-cqm**(与 T 打平但更便宜、1x1 保序记录最好);
     协同层 = coeff (效率增益已证, 排序影响待 B1 协议补测后定);
     第二臂 = T/Tnb (Tnb 的"边界 token 协同"在 car 上反而比纯 T 差
     12%, 单 seed 下不结论, 但暂不优先)。
     M3 (mask 接入) 后即可上 Dublin 三场景。

║   Part 3: 各臂叙述                                                           ║
╚══════════════════════════════════════════════════════════════════════════════╝

  3.1 L0 双臂 (184 B / 185 T): 稳定收敛, 1x3 完全打平 (44.6 vs 44.2,
      重叠区间)。与 1x1 一致 (B −38.8 / T −37 同档)。generic 文档的
      "syc 1x3 零代码改动"主张兑现。B 仍是性价比之王 (参数更少,
      MLP vs transformer, 训练 wall-clock 更短)。

  3.2 187 coeff (L2): **效率冠军**, car −15% vs nocoord (37.9 vs 44.6,
      不重叠), bus 也最好 (2.8)。best@ep1000 后平台稳定 (2.2)。
      β 系数协同在贯通走廊场景的价值首次在干净评估下确认。
      amb 影响未决 (B1)。

  3.3 186 colightorig (L1): 训练退化, 诊断见 TL;DR 3。补充证据:
      best 时刻 (ep145) 也仅 −83 (从未达到 nocoord 水平); 末期
      eval J0 amb speed→0。**不构成"GAT 协同对 B 状态无效"的结论**,
      构成"trainorico 缺少高维输入的稳定化手段"的结论。
      修复优先级: ① grad clip 1.0 (一行, 1x1 已验证此手段);
      ② lr 3e-4; ③ obs LayerNorm。重跑一臂 (~1 GPU·h) 再判。

  3.4 188 Tnb (边界 token) vs 185 T: car 49.6 vs 44.2 —— 边界 token
      在本场景**净伤害** (~12%)。[推测] 1x3 贯通走廊的边界 token 携带
      的"网络外"信息有限, 反而占用注意力; 其在 Dublin (真边界、
      有意义的进出流) 的价值需另测, 暂不否定设计本身。
      (单 seed, 差异 5.4s > 3×std≈4.2s, 勉强可信但建议复跑。)

  3.5 排序 (5-4-1) 的现状: 以 per-visit 口径, 四个工作臂的点估计都
      满足 amb/visit ≤ bus (2.3-3.8 vs 2.8-5.2), 无可证实的反转;
      但 amb 方差吞没臂间差异 → "协同是否侵蚀 amb 优先级"——也就是
      PRIORITY_ORDERING 文档 HELP 层够不够的问题——**本批数据回答
      不了**, 留给 B1 协议。


╔══════════════════════════════════════════════════════════════════════════════╗
║   Part 4: 问题/bug/改进清单 (重要度排序)                                     ║
╚══════════════════════════════════════════════════════════════════════════════╝

  B1 ★★★ amb 评估协议欠功效 (本批最重要的产出):
     现状: eval episode 1000s × Poisson 3.5/h → 1.1±1.0 辆/ep;
     10 ep 才 ~11 个观测, amb std≈均值。
     修法 (不重训, 只改评估):
       a. 对既有 best/final ckpt 跑 50-episode 评估 (≈1h CPU,
          eval_unified --episodes 50, seed 基址 1000) → amb n≈55,
          std/√n 收到 ~1.3s, 足够分辨 2-4s 级差异;
       b. 或建 eval 专用 rou 变体: amb 流密度 ×5 (exp(0.000194)),
          其余不动 —— 训练场景保持不变, 只改评估场景 (注意论文表述:
          evaluation-time intervention)。
     推荐 a 先行 (零新资产), b 作为 robust 性复核。

  B2 ★★ best-ckpt 选择 = 单次 eval@123 的 argmax → 选择噪声:
     187 final(37.5) 甚至略好于 best(37.9); 186 的 best@145 也是这个
     机制选的。
     ✅ 已修复 (2026-06-11 当晚): 四个 trainer (train / traincoeff /
     trainorico / traincoeff_gat) 的 best 判据统一改为"最近 K 次 eval
     滑动均值" (K = cfg best_eval_window, 默认 3; 窗口满后才参与比较,
     防止开局单次幸运 eval 锁死门槛)。best_metrics.json 新增
     eval_last_reward / best_criterion 字段; eval_mean_reward 语义变为
     滑动均值 (跨 watershed 对比时注意: exp184-188 及更早 = 单次 argmax,
     之后的 run = sliding3)。烟雾测试 ✓ (16ep/3 评估/恰好 1 次更新)。
     注: 既有 exp184-188 的 best.pth 不受影响, 其数字按旧判据解读。

  B3 ★★ 全臂单训练 seed (0): 跨臂 car 差异 >5s 的结论 (coeff 增益、
     Tnb 伤害) 建议 3-seed 复跑确认; <3s 的差异本文已不下结论。

  B4 ★★ 186 不稳定 (修法见 3.3, 一行 clip 起步)。

  B5 ★ run 残骸: 每 exp 2-4 个中止目录 (11:16/11:44/11:51/12:05/12:12
     批), 含误导性 best_metrics → 建议 rm 或归档, 防止后续脚本误聚合。

  B6 ★ 观察: eval_unified 的 episode seed = config_seed+i, 若直接用
     原 config (seed 0) 跑会踩训练 seed → 本日用临时 config (seed
     1000) 规避; 建议给 eval_unified 加 --seed-base CLI 参数固化纪律。

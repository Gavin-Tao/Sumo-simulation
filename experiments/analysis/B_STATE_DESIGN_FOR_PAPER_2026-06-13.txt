╔══════════════════════════════════════════════════════════════════════════════╗
║  Part 1: 设计动机 (一段话, 可改写进 Introduction/Method)                       ║
╚══════════════════════════════════════════════════════════════════════════════╝

  目标: 在城市信号控制中显式保障高优先级车辆 (救护车 > 公交 > 小汽车),
  而不仅最小化总延误。为此把"优先级"同时编码进【状态】(按车辆优先级
  分桶的 movement 级特征) 与【奖励】(优先级加权等待), 二者共享同一张
  优先级表 → 改表即同时重定优先级语义 (state 与 reward 对偶, 便于
  zero-shot 调整优先级策略)。动作侧用统一的 8 标准相位 + 动作掩码,
  使异构路口 (不同进口数/相位数) 拥有同维动作空间。

╔══════════════════════════════════════════════════════════════════════════════╗
║  Part 2: 动作空间 A (8 标准相位 + 掩码)                                        ║
╚══════════════════════════════════════════════════════════════════════════════╝

  - 全网每个路口的物理相位经过重建, 映射到固定的 8 维标准动作空间
    a∈{0..7} (FRAP 式相位竞争模板: 8 个 NEMA 风格相位, 含直行/左转
    的各方向组合)。语义跨路口对齐 (a0 在每个路口都指同一类放行)。
  - 异构性处理: 路口 i 实际只拥有标准相位的一个子集 → 二值掩码
    m_i ∈ {0,1}^8 标出合法动作。非法动作在 ε-greedy 的探索分支被排除,
    在贪心分支 Q 值置 −∞ 再取 argmax → 永不被选、永不入经验池。
  - 映射表: meta sidecar (dublin_8std_meta.json) 提供 std↔green_index
    与 link→(approach,turn) 表; 训练器每次 reset 后把 green→std 映射
    stash 到 TrafficSignal 上, 使观测的相位 one-hot 也在 8 维标准空间。

╔══════════════════════════════════════════════════════════════════════════════╗
║  Part 3: 状态 B 方案 (PriorityMovement) —— 完整构造                            ║
╚══════════════════════════════════════════════════════════════════════════════╝

  3.1 符号定义
  ────────────
    路口 i 的状态 s_i 由三部分拼接: [ 相位头 H | 12 个 movement 槽 ]。
    movement 槽 = (approach 进口方位, turn 转向):
       approach ∈ {N, E, S, W}    (4)
       turn     ∈ {L, T, R}       (左/直/右, U 折入 L)   (3)
       ⇒ N_SLOTS = 4 × 3 = 12 个槽 (固定, 跨路口同构)
    优先级桶: PRIORITY_LEVELS = {1,2,3,4,5} (固定 5 档, 代码常量)。
       车辆类型经优先级表映射到桶: 默认 {ambulance:5, bus:3, car:1};
       无优先级对照设 {全:1} (所有车塌缩到桶1, 维度不变)。
    每槽每桶的基础字段 (φ, "cqm"):
       count  c  : 该 (槽,桶) 的车辆数
       queue  q  : 其中停驶 (速度<0.1) 的车辆数
       mean_awt   : 该桶车辆在【本进口车道】的平均累计等待 (秒)

  3.2 车辆如何归桶 (关键: 意图归槽, 非车道归槽)
  ─────────────────────────────────────────────
    优先级: prio(v) = 优先级表[type(v)]          (memoized)
    槽位:   slot(v) = movement_by_edges[(当前边, route下一条边)]
            即按车辆的【路线意图】(从哪条边来、要去哪条边) 唯一归槽;
            一辆车恰好进一个槽 (共享车道上不同转向的车分到不同槽,
            分子无重复)。
    等待口径 (awt_basis="local", 论文主配方): 只计车辆在【当前进口
       车道】挣得的等待 (首次见到时记基线, 过路口等效清零), 与奖励
       的逐路口口径对齐, 使多路口网络上特征分布平稳。

  3.3 归一化 (invariant I5)
  ─────────────────────────
    密度类字段除以槽容量: count/cap_s, queue/cap_s,
       cap_s = Σ_{lane feeds slot s} (车道长 / (最小车距+车长))  [jam 容量]
    mean_awt 除以 awt_scale=100 (并可选 awt_cap 在原始秒数封顶, 防
       极端拥堵下的无界特征)。

  3.4 相位头 H (legacy 模式, Dublin 用)
  ─────────────────────────────────────
    H = [ 8 维当前相位 one-hot (标准动作空间) , min_green_ok (1 维) ]
        共 9 维。 min_green_ok = 是否已满足最小绿+黄 (可切换标志)。

  3.5 可选扩展字段 (论文主配方 208 全开)
  ──────────────────────────────────────
    ψ (downstream / outgoing, "outcq"): 每槽对其下游 to-lane 也做
       优先级分桶的 {count, queue} = 5桶×2 = 10 维/槽。捕捉出口侧
       溢出 (spillback) —— MaxPressure 的下游压力项的优先级版。
    lane_occ (I2): 每槽 1 维 = max_{feed lanes}(车道全车数/车道容量),
       与意图无关的物理占用真值, 修共享车道密度低估。

  3.6 维度推导 (论文主配方 exp208: cqm + ψ-cq + lane_occ)
  ───────────────────────────────────────────────────────
    每槽 = φ(5桶×3字段=15) + ψ(5桶×2字段=10) + lane_occ(1) = 26
    状态维 = H(9) + N_SLOTS(12) × 26 = 9 + 312 = 321  ✓ (实测 obs_dim=321)
    核心版 (仅 cqm, 无 ψ/lane_occ): 9 + 12×15 = 189。

╔══════════════════════════════════════════════════════════════════════════════╗
║  Part 4: 奖励 R (优先级加权等待, 与 state 对偶)                                ║
╚══════════════════════════════════════════════════════════════════════════════╝

    r_i = − ( Σ_{p∈levels} p · avg_wait_p ) / 100
    其中 avg_wait_p = 路口 i 进口车道上、优先级为 p 的车辆的平均累计
    等待 (本车道口径, 跨车道修正只算本路口挣得的等待)。
    权重 = 优先级等级本身 (p): 救护车(5) 的等待被放大 5×, 小汽车(1)
    权重 1 → agent 有动机优先清空高优先级车辆。
    与 state 共享同一优先级表 → "改表" 同时重定 state 分桶与 reward
    权重 (设计的对偶性/zero-shot 可调性)。
    性质: r ≤ 0 (等待非负); 这是 R1 钳位 (target≤0) 的数学依据。

║  Part 5: 伪代码 (可直接改写为论文 Algorithm 1 / 2)                             ║
╚══════════════════════════════════════════════════════════════════════════════╝

  Algorithm 1: PriorityMovement 状态构造 φ(i)  (每路口每决策步)
  ─────────────────────────────────────────────────────────────
   输入: 路口 i, 优先级表 P, 字段集 F=(count,queue,mean_awt)
   1: slot_stat[s][p] ← 0, ∀ s∈[1..12], p∈{1..5}
   2: for 每条进口车道 lane of i:
   3:     for 每辆车 v on lane:
   4:         s ← slot_by_intent(v)          # (from_edge, next_edge)→槽
   5:         if s 无效: continue
   6:         p ← P[type(v)]                  # 优先级桶
   7:         w ← local_wait(v, lane)         # 本车道累计等待
   8:         slot_stat[s][p].count += 1
   9:         slot_stat[s][p].queue += (speed(v)<0.1)
  10:         slot_stat[s][p].sum_wait += w
  11: H ← [ onehot8(std_phase(i)) , min_green_ok(i) ]      # 相位头
  12: obs ← H
  13: for s in 1..12:                          # 固定槽序
  14:     for p in 1..5:                        # 固定桶序
  15:         c,q,sw ← slot_stat[s][p]
  16:         mean ← sw/c if c>0 else 0;  mean ← min(mean, awt_cap)
  17:         obs += [ c/cap_s , q/cap_s , mean/100 ]        # φ (cqm)
  18:     (可选) obs += ψ_downstream(s)          # 5桶×{count,queue}
  19:     (可选) obs += lane_occ(s)              # 物理占用 1 维
  20: return obs                                # 维度 = 9 + 12×(15[+10+1])

  Algorithm 2: 训练循环 (masked DQN, 主配方)
  ──────────────────────────────────────────
   每决策步:
     for 每路口 i:  a_i ← argmax_{a: m_i[a]=1} Q(φ(i), a)   (ε-greedy, 探索仅在合法集)
     执行 {a_i}, 观测 r_i, φ'(i)
     存 (φ(i), a_i^std, r_i, φ'(i), m_i') 入共享经验池      # 存标准动作
     采样 batch, 计算 TD 目标:
        y = r + γ · Q_target(φ', argmax_{a: m'[a]=1} Q_online(φ',a))   # Double + mask
        y = min(y, 0)                                       # R1 钳位 (因 r≤0 ⇒ Q≤0)
     Huber(Q(φ,a), y) 上做梯度步; grad-clip; 每 720 步同步 target 网

╔══════════════════════════════════════════════════════════════════════════════╗
║  Part 7: 字段/变体说明 (回答 "cqm vs qm 何时用")                               ║
╚══════════════════════════════════════════════════════════════════════════════╝

  字段集变体 (obs_fields):
    cqm  = (count, queue, mean_awt)  ← 论文主线 (Dublin 全部用此)
    qm   = (queue, mean_awt)         ← 1x3 早期【字段消融】臂 (去掉 count
           看是否更优); 结论 count 有用、cqm 占优 → Dublin 不再用 qm。
           【用途: 仅当你要在论文放"状态字段消融表"时才需要它。】
    cqmm = (count,queue,mean_awt,max_awt)  ← 加 max_awt 的消融, 同上。
  相位编码变体 (obs_phase_state):
    legacy   = 前置相位 one-hot + min_green (Dublin 用, 8维标准空间);
    perphase = 每相位行 is_current + [min_green, elapsed] (另一种编码消融)。
  等待口径 (obs_awt_basis): local (主线, 逐路口) | global (早期, 全程累计)。
  这些都是 config 可切换的消融维度 — 主线固定 cqm + legacy + local,
  其余仅供"消融实验"章节使用。
